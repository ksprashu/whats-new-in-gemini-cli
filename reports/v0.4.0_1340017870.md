# 🚀 What's New: Gemini CLI Update

## Feature: Interactive Pro Quota Management
**PR:** [#7094](https://github.com/google-gemini/gemini-cli/pull/7094) | **Author:** @JayadityaGit

### 1. Feature Summary
We are introducing the **Pro Quota Dialog**, a significant improvement to the Developer Experience (DX) when using Gemini Pro models. Previously, hitting a daily usage limit resulted in an abrupt stop. Now, the CLI handles these limits gracefully by triggering an interactive dialog.

This new workflow empowers developers to immediately resolve the bottleneck by either switching authentication profiles or seamlessly falling back to the Flash model, all without exiting the terminal session.

### 2. Background & Context
**The Problem:**
Prior to this update, when a user exceeded their daily quota for a Pro model, the CLI’s behavior was described as an "abrupt notification-only flow." This meant the CLI would likely output an error or a static notification, forcing the user to:
1.  Read the error.
2.  Manually exit the current command.
3.  Remember the command flags to switch accounts or change models.
4.  Re-type and re-run the prompt.

**The Solution:**
This change transforms a "hard stop" error into an actionable decision point. By intercepting the quota limit event, the CLI now keeps the user in the flow. The goal is to minimize context switching and frustration when working with heavy workloads on the Pro tier.

### 3. How-To Guide
You will encounter this feature automatically when you reach your usage limit. Here is the workflow:

1.  **Trigger:** Run a standard prompt using a Pro model (e.g., `gemini prompt "Analyze this codebase..."`).
2.  **Event:** If you have exceeded your daily Pro quota, the CLI pauses and displays the **Pro Quota Dialog**.
3.  **Action:** You will be presented with two distinct options:
    *   **Option A: Switch Auth.** Select this to cycle to a different authentication profile (e.g., a personal account vs. a work account) that has remaining quota.
    *   **Option B: Continue with Flash.** Select this to immediately re-run your prompt using the Gemini Flash model (which is generally faster and lower cost/higher quota).
4.  **Tip:** If you choose to exit or need to re-run the exact prompt later, the dialog reminds you to use `Ctrl+P` to recall your previous prompt instantly.

### 4. Walkthrough / Technical Deep Dive
Under the hood, this update refactors how the CLI creates the "view" layer for error handling.

*   **Error Interception:** The CLI listens for specific API error responses indicating a quota limit (typically associated with HTTP 429 or specific gRPC status codes regarding resource exhaustion).
*   **The `ProQuotaDialog` Component:** Instead of passing the error text directly to `stdout`, the application instantiates the `ProQuotaDialog` class. This is a TUI (Text User Interface) element that captures user input.
*   **Refactoring `InfoMessage`:** As part of this UI cleanup, the `i` prefix was removed from the `InfoMessage` component. This ensures that the dialog looks cleaner and more aligned with a "system alert" aesthetic rather than a generic informational log.
*   **State Preservation:** Crucially, if the user selects "Continue with Flash," the CLI preserves the original prompt text in memory. It swaps the model parameter in the configuration context temporarily and re-sends the request, making the fallback invisible to the user aside from the model change.
