# 🚀 What's New: Model Context Protocol (MCP) Resource Support

**Contributor:** @MrLesk
**Feature:** MCP Resource Discovery & Context Injection

## 1. Feature Summary
The Gemini CLI has expanded its integration with the **Model Context Protocol (MCP)**. Users can now directly access **MCP Resources** within the CLI interface.

By simply typing the `@` symbol in your prompt, you can now discover, search, and attach external data (such as files, database rows, or system logs) served by any connected MCP server. This bridges the gap between the Gemini model and your local or remote data sources without manual copy-pasting.

## 2. Background & Context
**The Problem:**
Previously, providing context to the Gemini CLI required manually copying file contents or data into the terminal. While the CLI is powerful, it was isolated from the user's broader development environment (databases, internal documentation, or complex file structures).

**The Solution:**
The Model Context Protocol (MCP) is an open standard that allows AI assistants to connect to data sources. While the Gemini CLI may have already supported basic tools, **Resources** are a distinct primitive in MCP designed for reading data rather than performing actions.

**Why this change matters:**
Based on the implementation by @MrLesk, this update allows the CLI to act as a fully compliant MCP Client for resources. It shifts the workflow from "User finds data -> User pastes data -> User prompts Gemini" to "User references data via `@` -> Gemini reads data."

This change aligns the Gemini CLI with modern AI coding agent standards, making it a viable central hub for interacting with diverse technical stacks.

## 3. How-To Guide

### Prerequisites
Ensure you have an MCP server configured in your Gemini CLI configuration file (usually `~/.gemini/config.json` or similar).

**Example Config (connecting to a local file server):**
```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": ["-y", "@modelcontextprotocol/server-filesystem", "/path/to/project"]
    }
  }
}
```

### Using the Feature

1.  **Start the CLI:**
    Run your standard entry command (e.g., `gemini chat`).

2.  **Trigger the Menu:**
    In the prompt input, type the **`@`** symbol.

3.  **Browse & Select:**
    A dropdown or autocomplete menu will appear listing available resources from your connected servers. You might see entries like:
    *   `@filesystem/src/main.py`
    *   `@postgres/users_schema`

4.  **Chat:**
    Select the resource. It will appear as a chip or token in your prompt.
    > **User:** Analyze the error handling in @filesystem/src/main.py

5.  **Result:**
    The CLI fetches the content of `main.py` behind the scenes and sends it to Gemini as system context, allowing the model to answer accurately.

## 4. Walkthrough / Technical Deep Dive

Here is how the integration works "under the hood" based on the standard MCP specification and this PR:

### 1. Initialization (Handshake)
When the Gemini CLI starts, it spawns the defined MCP servers (via Stdio). It sends an `initialize` request to negotiate capabilities. The CLI now specifically advertises that it supports `resources` as a client capability.

### 2. Discovery (`resources/list`)
When the user types `@`, the CLI triggers an asynchronous call to all connected servers using the `resources/list` method.
*   **Input:** Optional pagination cursor.
*   **Output:** A list of resource objects containing a `uri`, `name`, and optional `mimeType`.
*   **UI Layer:** The CLI filters this list based on whatever text the user types after the `@`.

### 3. Context Resolution (`resources/read`)
Once a user submits a prompt containing a resource reference (e.g., `mcp://filesystem/...`):
1.  The CLI parses the prompt for resource URIs.
2.  It executes a `resources/read` request to the specific MCP server that owns that URI.
3.  The server returns the binary or text content (blob).
4.  The CLI injects this content into the `user` message or a specialized `context` block in the API payload sent to Google Gemini.

### 4. Updates (`notifications/resources/list_changed`)
If the MCP server supports it, the CLI listens for notifications indicating that the list of available resources has changed (e.g., a new log file was created), keeping the `@` menu up to date in real-time.

**Demo 1: The "Chat with your Database" (Postgres)**

*   **Action:** Type `@`, select a specific table schema (e.g., `@users_table`).

*   **Wow Factor:** Demonstrates handling large text blocks automatically.

*   **Wow Factor:** Shows the power of combining distinct data sources via a unified CLI interface.
