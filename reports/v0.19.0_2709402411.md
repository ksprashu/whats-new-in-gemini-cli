# What’s New: Interactive Shell UX Overhaul

**Date:** October 26, 2023
**Components:** Interactive Shell, UI/UX
**Contributors:** @galz10, @jackwotherspoon

## 1. Feature Summary
This update brings significant quality-of-life improvements to the **Interactive Shell** within the Gemini CLI. We have bridged the gap between the embedded terminal and the main CLI interface.

*   **Click-to-Focus:** Users can now click directly on the embedded shell output to focus it for input and click back on the main prompt to return control to Gemini.
*   **Context-Aware Status:** The CLI no longer displays generic "witty" loading phrases when the shell is actually waiting for you. A specific status message now alerts you when the shell is idle and awaiting input.
*   **History Hygiene:** Logic for cancelled shell commands has been refined to prevent duplicate or messy history entries.

## 2. Background & Context
**The Problem:**
Previously, the Interactive Shell experience suffered from two distinct friction points:
1.  **Focus Friction:** Switching between chatting with Gemini and typing into the running shell command was cumbersome. Users instinctively wanted to click the terminal window to type, but the interface didn't support it.
2.  **Status Ambiguity:** When a running shell command (like a server or a script prompt) paused to wait for user input, the Gemini CLI loading indicator continued to cycle through generic loading jokes. This confused users, making it look like Gemini was still "thinking" or processing, rather than waiting on the user to provide input (PR #12535).

**The Solution:**
*   **PR #13341** introduces a global focus state manager. It detects mouse clicks within the specific terminal buffer regions, allowing for seamless toggling between the shell and the prompt.
*   **PR #12535** implements an "idle watcher." If the shell hasn't produced output for 5 seconds, the CLI infers it is waiting for user input and switches the loading text to a clear instruction.

## 3. How-To Guide

To utilize these features, ensure you have the latest version of the Gemini CLI installed.

### Prerequisites
*   Ensure the **"Use Alternate Buffer"** setting is enabled in your configuration. This feature relies on the buffer rendering capabilities to detect click zones.

### Using Click-to-Focus
1.  Ask Gemini to run a command that requires interaction (e.g., `python script.py` that asks for a name, or an `ssh` session).
2.  **Focus the Shell:** Hover over the embedded terminal output and **Left Click**.
    *   *Visual Cue:* The cursor will move into the embedded shell. You can now type directly into the running process.
3.  **Unfocus:** When done, **Left Click** anywhere on the main Gemini CLI prompt (the bottom input bar).
    *   *Result:* Control returns to the main CLI, allowing you to send new instructions to Gemini.

### Seeing the Waiting Status
1.  Run a command that pauses (e.g., a script with `input("Press Enter to continue")`).
2.  Do not type anything.
3.  **Wait 5 seconds.**
4.  Observe the loading spinner text change from generic phrases to:
    > *"Interactive shell awaiting input... press Ctrl+f to focus shell"*

## 4. Walkthrough / Technical Deep Dive

### State Management (Click-to-Focus)
Under the hood, this feature introduces a new action, `setEmbeddedShellFocused`, within the `UIActionsContext`. This allows the application to centrally manage where the keystrokes are directed.
*   **Event Listeners:** The rendered terminal buffer now listens for mouse events.
*   **Unfocus Logic:** A specific handler was added to the main Input Prompt component. Clicking it triggers a "force unfocus" event on the embedded shell, ensuring no "focus traps" occur where the user gets stuck in the terminal.

### Idle Detection (Loading Phrase)
The new loading phrase logic is more than just a text change; it is time-sensitive state tracking.
*   **Output Time Tracking:** The system now tracks `lastOutputTime` for both shell commands and tool outputs.
*   **The 5-Second Rule:** To prevent the "Awaiting Input" message from flashing rapidly while a script is just processing data, a 5-second delay was implemented. The `useLoadingIndicator` hook checks the delta between `Date.now()` and `lastOutputTime`.
*   **Reset Logic:** If the shell spits out a new log line, the timer resets, and the standard loading phrase cycle resumes.

### History Clean-up
Refinements were made to `useGeminiStream` and `shellCommandProcessor`. Previously, cancelling a command (Ctrl+C) might leave partial or duplicate entries in the CLI history. The new logic intercepts the cancellation signal and ensures the UI state finalizes cleanly before writing to history.
