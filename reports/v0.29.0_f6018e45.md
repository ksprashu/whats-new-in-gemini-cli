## The Headline
The Gemini CLI has introduced a sophisticated new workflow dubbed "Plan Mode," effectively teaching the AI agent to think before it acts. Rather than rushing immediately into code generation—which can sometimes lead to premature or incorrect implementation—this feature introduces a dedicated state for research and architectural design. By separating the planning phase from the execution phase, the CLI offers developers a transparent view of the AI's intended strategy. It turns the AI from a hasty coder into a thoughtful architect, allowing users to review a markdown-based roadmap via a new slash command before a single line of code is written.

## Quick Start / How to Try It Out
To access Plan Mode, users must enable the experimental feature flag in their configuration.

*   **Prerequisites:** Ensure the `experimental.plan` feature flag is enabled in your `.gemini/config.ts` or application configuration.
*   **Triggering Plan Mode:**
    *   **Via Command:** Type `/plan` in the CLI interface. This switches the approval mode and displays the most recently generated plan (if available).
    *   **Via Agent Decision:** The agent can autonomously decide to switch modes using the `enter_plan_mode` tool when faced with complex requests.

## Use Cases (Why you need this)
*   **Complex Refactoring:** When reorganizing a large codebase, Plan Mode ensures the agent maps out dependency changes and structural moves in a read-only environment before altering files.
*   **Architecture Research:** Ideal for tasks requiring documentation lookup or library comparison. The agent can "read" and summarize its findings without the risk of generating broken code during the discovery phase.
*   **Safety & Oversight:** For critical systems, this provides a "review gate." Developers can inspect the AI's generated Markdown plan to ensure logical soundness before authorizing the implementation.

## What to Expect (Things to Look Out For)
*   **Read-Only State:** When the agent enters Plan Mode, it is restricted to read-only tools. Do not expect code edits while in this state.
*   **Confirmation Prompts:** Transitioning into this mode triggers a user confirmation flow (Approve/Deny/Cancel) to ensure the user is aware of the context switch.
*   **Experimental Status:** As this is an experimental feature, appropriate error messages will appear if the command is run without the correct configuration flags enabled.

## Technical Deep Dive (Admin)
The implementation of Plan Mode spans two major Pull Requests involving both user-interface commands and agent-tooling logic.

*   **The Slash Command (`/plan`):**
    *   Implemented in PR #17698, this introduces a command that interfaces with the `ApprovalMode` state.
    *   It includes logic to scan a temporary plans directory. If a plan exists (stored as a Markdown file), the content is read and rendered directly to the user interface.
    *   It enforces a check for the `experimental.plan` setting, returning a specific error if the feature is disabled.

*   **The Tool (`enter_plan_mode`):**
    *   Implemented in PR #18324, this adds `EnterPlanModeTool` to the agent's registry `packages/core/src/tools`.
    *   The tool explicitly switches the internal state to `ApprovalMode.PLAN`.
    *   **Security & Safety:** The `shouldConfirmExecute` method dictates that the agent cannot silently slip into this mode; it requires user interaction (ASK_USER logic).
    *   Once in this mode, the agent's capabilities are effectively throttled to read-only operations to prevent accidental side effects during the planning phase.

## Background & Context (Admin)
Prior to this update, the Gemini CLI agent operated in a relatively linear fashion, often attempting to solve complex architectural problems and implement code simultaneously. This led to friction where the agent might hallucinate a library method or misunderstand a dependency graph, resulting in code that had to be rolled back. 

Plan Mode addresses the community and internal feedback regarding the need for "Chain of Thought" visibility. By decoupling the "thinking" (planning) from the "doing" (coding), the system mimics human engineering workflows—designing a spec before writing the implementation.
