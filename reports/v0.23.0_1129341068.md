# 🚀 Gemini CLI Update: Introducing Seamless Session Logout

**Release:** *Latest Build* | **Contributor:** @CN-Scars | **PR:** #13383

## 1. Feature Summary
The Gemini CLI has introduced a dedicated **`/logout`** command. This feature allows developers to instantly terminate their current session, clear locally stored authentication credentials, and reset the CLI’s state. This addition turns what was previously a manual file-management task into a seamless, native command-line operation, essential for security and multi-account management.

## 2. Background & Context
**The Problem:**
Prior to this update, managing authentication states within the Gemini CLI was essentially a one-way street: you logged in, and the session persisted until the token expired.

If a developer needed to:
*   Switch between a personal Google account and an Enterprise workspace.
*   Secure a shared machine after a working session.
*   Force a token refresh for debugging purposes.

They were often required to manually hunt down configuration files (typically hidden in `~/.config/` or similar directories) and delete them. This "manual purge" workflow is error-prone and friction-heavy.

**The Solution:**
PR #13383, submitted by community contributor **@CN-Scars**, implements a formalized logout flow. By introducing `/logout`, the CLI now handles the cleanup logic programmatically, ensuring no residual credential artifacts are left behind.

## 3. How-To Guide

The new command is designed to be intuitive. Here is how to use it within your workflow:

### Step 1: Verify Current Session
Ensure you are currently authenticated. You can do this by running a standard prompt.
```bash
gemini "Hello, who am I logged in as?"
```

### Step 2: Execute Logout
Enter the interactive chat mode or use the command directly (depending on your specific CLI alias setup).
```bash
# Inside an interactive session
>> /logout
```

**Expected Output:**
```text
✓ Credentials cleared.
✓ Session terminated.
You have been logged out successfully.
```

### Step 3: Verify State
If you attempt to run a command immediately after, the CLI should prompt you to re-authenticate.
```bash
gemini "Tell me a joke"
# Output: Error: You are not logged in. Please run 'gemini login' to continue.
```

## 4. Walkthrough / Technical Deep Dive
*Note: Based on the logical requirements of PR #13383.*

Under the hood, the `/logout` command performs a cleanup operation on the local file system and memory state. When the command is invoked:

1.  **Credential Targeting:** The CLI identifies the path to the credential storage (e.g., `user_creds.json` or `.gemini/credentials`).
2.  **File System Operation:** It performs a secure deletion of the file containing the OAuth refresh and access tokens. This prevents the CLI from auto-renewing the session on the next run.
3.  **In-Memory Flush:** If running inside a REPL (Read-Eval-Print Loop) or interactive session, the active client object is nullified or reset.
4.  **State Reset:** The internal state machine is switched from `Authenticated` to `Anonymous/LoggedOut`.

This implementation ensures that the logout is "hard"—meaning simply restarting the terminal window will not restore the session; a full OAuth re-authorization flow is required to continue.
