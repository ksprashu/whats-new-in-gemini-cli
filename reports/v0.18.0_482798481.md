# 🚀 Gemini CLI Update Report: UI Stability & Configuration

## 1. Feature Summary
**Temporary Rollback of Rich TUI Elements**

In the latest update, the Gemini CLI has reverted its default interface behavior. The "Rich" UI elements—specifically embedded scrolling and mouse support—have been disabled by default. The CLI now defaults to a standard line-printer (streaming) interface. However, for users who prefer the interactive terminal experience, this feature is not gone; it has been moved behind a configuration flag.

## 2. Background & Context
**Why was this change made?**

The decision to rollback the updated UI stems from a commitment to stability and universal compatibility. While the "Alternate Screen Buffer" (which powers the rich UI) offers a modernized experience similar to IDEs, it requires "more time to bake."

In the context of Terminal User Interfaces (TUIs), relying on the Alternate Screen Buffer can introduce edge cases across different environments (e.g., specific Linux distros, older versions of Windows Terminal, or conflicts with screen multiplexers like `tmux`).

The goal of this change is to:
1.  **Ensure Reliability:** Return to the battle-tested standard output mode as the default to prevent rendering glitches for new users.
2.  **Preserve Choice:** Rather than removing the code entirely, it has been exposed as a user preference, acknowledging that many power users enjoyed the mouse support and scrolling capabilities.

## 3. How-To Guide
**Re-enabling the Rich UI**

If you miss the embedded scrolling and mouse support, you can manually opt-in to the "Updated UI" using the internal settings menu.

**Steps:**
1.  Open your terminal and run the Gemini CLI.
2.  Enter the settings command:
    ```bash
    /settings
    ```
3.  Use your arrow keys to navigate the menu list.
4.  Locate the option: **Use Alternate Screen Buffer**.
5.  Toggle the value to `true`.
6.  Exit the settings menu.

Your CLI will now switch into the full-screen interactive mode, restoring mouse support and internal scrolling.

## 4. Walkthrough / Technical Deep Dive
**The Tale of Two Buffers**

To understand this change, it is helpful to understand how terminal emulators render text.

*   **Standard Output (The Rollback):** By default, CLI tools write to `stdout`. This appends text to the bottom of the terminal history. This is robust, scriptable, and allows you to scroll back using your terminal's native scrollbar. This is the mode Gemini CLI has reverted to.
*   **Alternate Screen Buffer (The "Updated UI"):** When you set `Use Alternate Screen Buffer -> true`, the CLI sends specific ANSI escape codes (usually `\e[?1049h`). This switches the terminal to a separate "canvas."
    *   In this mode, the CLI takes full control of the screen (like `vim`, `htop`, or `nano`).
    *   It captures mouse events (clicks/scrolls) and handles the rendering of text areas manually.
    *   When the program exits, it swaps back to the main buffer, leaving your previous terminal history untouched.

**The Technical Challenge:**
The rollback suggests that managing state within the Alternate Screen Buffer was causing friction—likely regarding copy-pasting text behavior or rendering artifacts on resizing windows. By making this opt-in, the team can continue refining the TUI rendering engine without disrupting the workflow of users who just want a simple text-in/text-out experience.
