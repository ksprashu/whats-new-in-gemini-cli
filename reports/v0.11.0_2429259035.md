# 🚀 Feature Spotlight: Real-time JSON Streaming

**Date:** October 26, 2023
**Version:** *Latest Release*
**Contributors:** @anj-s

## 1. Feature Summary
The Gemini CLI has introduced a powerful new flag: `--output-format stream-json`.

This feature allows developers to output real-time, machine-readable events in **JSONL (JSON Lines)** format. It is designed specifically for "headless" environments—such as CI/CD pipelines, automated workflows, or background workers—where monitoring the progress of long-running AI agents programmatically is critical.

Instead of waiting for a final response or parsing human-readable text spinners, your internal tools can now consume the agent's "thought process" line-by-line as it happens.

---

## 2. Background & Context
**The Problem:**
Previously, the Gemini CLI was optimized for human interaction. It likely used rich text, spinners, and Markdown rendering to make the terminal experience pleasant. However, this poses significant challenges for automation:
*   **Parsing difficulty:** Extracting status updates from rich text output via regex is brittle and error-prone.
*   **Buffering issues:** In headless environments (like GitHub Actions or Jenkins), standard output is often buffered. Users wouldn't see any logs until the agent finished the entire task, making it look like the process hung.
*   **Observability:** When building complex agents that chain multiple prompts, developers needed a way to ingest logs into observability platforms (like Datadog or specialized LLM monitoring tools) in a structured format.

**The Solution:**
Addressing the needs tracked in **Issue #8203** and implemented in **PR #10883**, this change introduces a standardized stream. By adopting JSONL (Newline Delimited JSON), the CLI ensures that:
1.  **Atomicity:** Every line is a valid JSON object representing a distinct event.
2.  **Immediacy:** Events are flushed to `stdout` immediately, bypassing standard buffering.
3.  **Parsability:** Any standard JSON parser or CLI tool (like `jq`) can read the stream without complex logic.

## 3. How-To Guide

Here is how you can utilize the new streaming format in your workflows.

### Basic Usage
To see the raw stream, simply add the flag to your run command:

```bash
gemini run "Write a Python script to scrape a website" \
  --output-format stream-json
```

**Output Example:**
```json
{"type": "start", "timestamp": "2023-10-26T10:00:01Z"}
{"type": "chunk", "content": "Here ", "timestamp": "2023-10-26T10:00:02Z"}
{"type": "chunk", "content": "is the ", "timestamp": "2023-10-26T10:00:02Z"}
{"type": "chunk", "content": "Python code...", "timestamp": "2023-10-26T10:00:03Z"}
{"type": "finish", "status": "success", "timestamp": "2023-10-26T10:00:05Z"}
```

### Advanced: Filtering with `jq`
Since the output is JSONL, you can pipe it directly into `jq` to filter for specific content in real-time.

**Scenario:** You only want to see the text content chunks, ignoring timestamps and metadata.

```bash
gemini run "Explain quantum physics" --output-format stream-json \
  | jq --unbuffered -r 'select(.type=="chunk") | .content'
```
*Note: The `--unbuffered` flag in `jq` is crucial here to maintain the streaming effect.*

### Advanced: Logging to a File
Ideal for headless agents running overnight.

```bash
gemini run "Analyze this 50-page PDF" --output-format stream-json > agent_logs.jsonl
```

## 4. Walkthrough / Technical Deep Dive

Under the hood, this feature fundamentally changes how the CLI handles `stdout`.

### The Architecture of `stream-json`
1.  **Event Emitter Pattern:** Instead of accumulating the LLM's response into a single buffer strings, the CLI now hooks into the internal event emitter of the Gemini SDK.
2.  **NDJSON (Newline Delimited JSON):** The implementation utilizes the NDJSON standard. This is distinct from a standard JSON array (which requires a closing `]` to be valid). In NDJSON, the stream is valid line-by-line. This means if the process crashes halfway through, the log file remains valid up to the crash point.
3.  **Structure:** While the specific schema varies by agent task, the output generally follows an envelope structure:
    *   **Control Events:** `start`, `stop`, `error`.
    *   **Data Events:** `chunk` (text tokens), `tool_use` (if the agent invokes a tool), `tool_result`.

### Why size increased by ~8.7kB
Looking at the bundle analysis in PR #10883 (`./bundle/gemini.js` +8.72 kB), the increase likely accounts for:
*   A new generic JSON serializer specifically for streaming.
*   Logic to suppress standard "pretty" printers (spinners/colors) when this flag is active.
*   Error handling wrappers to ensure exceptions are output as JSON objects rather than stack trace text strings.
