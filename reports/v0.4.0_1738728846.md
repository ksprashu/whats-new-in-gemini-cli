# 🚀 What's New in Gemini CLI: Introducing `hideModelInfo`

## 1. Feature Summary
The Gemini CLI has introduced a new configuration option: **`hideModelInfo`**. This feature allows users to suppress the default metadata header that displays the currently active model (e.g., `Using: gemini-1.5-pro`) before every response. This change focuses on reducing visual noise, creating a more seamless "chat-like" experience, and improving output compatibility for scripting.

## 2. Background & Context
**Why was this change made?**
Previously, every interaction with the Gemini CLI would explicitly state which model was generating the response. While useful for debugging or verifying configuration, this created friction in two specific scenarios:

1.  **The "Immersive" Experience:** Users engaging in long conversational threads found the repetitive metadata distracting. It broke the flow of the conversation in the terminal window.
2.  **Scripting and Piping:** For developers using the CLI to pipe output into files (e.g., `gemini "write a readme" > README.md`), the model information was often captured along with the actual content, requiring manual cleanup.

By adding `hideModelInfo`, we are giving control back to the user to define how verbose the interface should be.

## 3. How-To Guide

You can enable this feature by modifying your Gemini CLI configuration file.

### Step 1: Locate your Config
Open your configuration file (usually located at `~/.config/gemini-cli/config.yaml` or similar, depending on your OS).

### Step 2: Update the Configuration
Add or update the `hideModelInfo` key to `true`.

```yaml
# config.yaml

# Old setting (default)
# hideModelInfo: false

# New setting to suppress output
hideModelInfo: true
```

### Step 3: Verify
Run a prompt in your terminal.

**Before (Default):**
```bash
$ gemini "Hello"
[Using model: gemini-1.5-pro]
Hello! How can I help you today?
```

**After (`hideModelInfo: true`):**
```bash
$ gemini "Hello"
Hello! How can I help you today?
```

## 4. Walkthrough / Technical Deep Dive
Under the hood, this feature acts as a conditional gate within the CLI's UX rendering layer (specifically the `PrintResponse` or equivalent output handler).

1.  **Config Loading:** Upon initialization, the CLI loads the user's configuration into a global context struct.
2.  **State Check:** Before the standard output stream (`stdout`) begins streaming the Large Language Model (LLM) tokens, the renderer checks the boolean value of `hideModelInfo`.
3.  **Conditional Rendering:**
    *   If `false` (default): The CLI formats a header string containing the `model_id`, applies dim/secondary coloring styles, and prints it to the console followed by a newline.
    *   If `true`: This logic block is completely bypassed, and the cursor remains at the start position, waiting immediately for the first token of the response.

This implementation ensures that the suppression is purely cosmetic and does not affect the actual API payload or the model selection logic.
