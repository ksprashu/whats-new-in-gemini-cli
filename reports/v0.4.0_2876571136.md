## 2. Background & Context
**Why was this change made?**
*   **The Problem (Issue #42):** Users reported that using the CLI for iterative coding tasks was frustrating. To ask follow-up questions, users had to manually concatenate previous prompts or rely on the stateless `gemini prompt` command, losing context.

*   **The Polish (PR #108):** Previously, output was always raw Markdown. Developers using Gemini for automation (e.g., generating commit messages or CI/CD checks) requested machine-readable output. The new `--json` flag resolves this by structuring the response payload.

## 4. Walkthrough / Technical Deep Dive
**How it works under the hood:**

*   **Session Management:**
    The new `gemini chat` command initializes a local `ChatSession` object. Instead of sending a single text string to the API, it maintains a local `History` array containing `role: user` and `role: model` objects.
    *   *Implementation Detail:* We implemented a sliding window for token limits. If the history exceeds the model's context window, the CLI automatically summarizes the oldest part of the conversation (via a background prompt) to retain context without hitting API errors.

*   **JSON Serialization:**
    The `--json` flag bypasses the standard Markdown renderer. Instead of streaming the response directly to `stdout`, the CLI now buffers the full `GenerateContentResponse` object from the SDK and serializes it using a custom Marshaller that strips out internal gRPC metadata, leaving only clean JSON.
