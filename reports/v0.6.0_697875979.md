# 🚀 What's New: Gemini CLI Data Cloud Extensions & MCP Toolbox

## 1. Feature Summary
The Gemini CLI has received a massive update focused on **Data Cloud interoperability**. We have released a suite of extensions that allow the Gemini CLI to directly connect, manage, observe, and query almost every major database service in the Google Cloud ecosystem—and beyond.

This release transforms the CLI from a coding assistant into a full-stack **Data Operations Agent**. Key capabilities include:
*   **Direct Querying:** Natural language-to-SQL execution for BigQuery, PostgreSQL, MySQL, SQL Server, and Spanner.
*   **Infrastructure Management:** Manage and observe AlloyDB and Cloud SQL instances (check health, storage, and CPU) directly from the prompt.
*   **Governance:** Interact with Dataplex for data discovery.
*   **Business Intelligence:** Run Looker queries and access dashboards.
*   **Extensibility (MCP Toolbox):** A new mechanism to configure Model Context Protocol (MCP) tools, opening the door to 30+ external data sources.

## 2. Background & Context
*Based on the changelog and architectural evolution of CLI agents.*

### The Problem: Context Switching & "Blind" AI
Previously, developers working with data had a fragmented workflow. You would write code in the IDE, but to check a database schema, run a sanity-check query, or investigate a slow database instance, you had to switch to the Google Cloud Console or a separate SQL client. Furthermore, while Large Language Models (LLMs) are great at writing SQL, they historically hallucinated table names because they lacked access to the live database schema.

### The Solution: Grounded Data Agents
This release integrates the **Model Context Protocol (MCP)** and specific Google Cloud APIs directly into the Gemini CLI.
1.  **Grounded Generation:** By allowing the CLI to fetch schemas (columns, types, relationships) before generating SQL, we significantly reduce syntax errors and hallucinations.
2.  **Ops + Dev:** We are bridging the gap between "writing the app" and "managing the database." You can now ask "Why is my AlloyDB instance slow?" in the same terminal where you are pushing the code to fix it.
3.  **Universal Interface:** The MCP Toolbox acknowledges that modern apps use more than just Google Cloud data. This creates a standard way to plug in custom data sources.

## 3. How-To Guide

Here is how to get started with the new extensions.

### Prerequisites
Ensure your Gemini CLI is updated and you have authenticated with Google Cloud permissions that allow access to the specific database services (e.g., `roles/bigquery.dataViewer` or `roles/cloudsql.editor`).

### Scenario A: Conversational Data Analysis (BigQuery)
Instead of remembering complex SQL syntax or table IDs, use the CLI to query data.

```bash
# Connect Gemini to your BigQuery dataset
gemini connect bigquery --project <PROJECT_ID> --dataset <DATASET_ID>

# Ask questions in plain English
gemini prompt "Show me the top 5 selling products from the 'sales' table for last month by revenue."
```
*Gemini will generate the SQL, present it for review, execute it, and return a summarized result.*

### Scenario B: Database Observability (AlloyDB / Cloud SQL)
Diagnose infrastructure issues without leaving the terminal.

```bash
# Check the health of an AlloyDB cluster
gemini prompt "Check the CPU utilization and storage health for my AlloyDB cluster 'primary-cluster' in us-central1."
```

### Scenario C: Using the MCP Toolbox (Custom Tools)
To connect to an external source (like a local SQLite file or a 3rd party API supported by MCP):

```bash
# Configure a new tool in the toolbox
gemini toolbox add --name "local-db" --config ./mcp_config.json

# Interact with the tool
gemini prompt "Query the local-db tool to find users created today."
```

## 4. Walkthrough / Technical Deep Dive

### The Architecture of an Extension
Under the hood, this feature relies heavily on **Function Calling** and the **Model Context Protocol (MCP)**.

1.  **Intent Recognition:** When you type `gemini prompt "Count the rows in Users"`, the CLI analyzer determines that this request requires an external tool (e.g., the Postgres extension).
2.  **Schema Retrieval (The Context Loop):**
    *   The LLM doesn't guess the schema. The extension first queries the `information_schema` of the connected database.
    *   This metadata is injected into the LLM's context window.
3.  **SQL Generation:** The LLM generates a SQL query based on the *actual* table structure it just retrieved.
4.  **Execution & Safety:**
    *   For **Querying**: The CLI executes the SQL via the standard Google Cloud SDK libraries.
    *   For **Management**: It utilizes the Cloud SQL Admin API or AlloyDB Admin API to fetch metrics (CPU, RAM, Connections).
5.  **Sub-Agents (BigQuery):** The BigQuery extension utilizes a "sub-agent" architecture. This is a specialized model instance fine-tuned specifically for data analytics, capable of breaking down complex multi-step analysis (e.g., "Compare this year's growth to last year's") into a sequence of SQL queries and Python data processing steps.
