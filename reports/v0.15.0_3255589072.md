# 🚀 What's New: Auto-Planning & Todo Lists in Gemini CLI

**Release Date:** October 26, 2023
**Pull Request:** [#12905](https://github.com/google-gemini/gemini-cli/pull/12905)
**Author:** @anj-s

## 1. Feature Summary
The Gemini CLI has introduced a new **"Todo Planning"** capability. When users input complex, multi-faceted prompts, the CLI no longer attempts to execute everything in a single, opaque pass. Instead, it intelligently breaks the request down into a discrete checklist of tasks.

The model now manages this list visibly, executing items sequentially and checking them off as they are completed. This transforms the CLI from a "black box" text generator into a transparent, agentic task runner.

## 2. Background & Context
**The Problem:**
As documented in Issue #12675, users often encountered friction when asking the CLI to perform "compound" tasks (e.g., *"Refactor this file, write a test for the new function, and update the README"*).
*   **Context Loss:** The model might complete step 1 and 2 but forget step 3.
*   **Lack of Visibility:** Users had to wait for the entire generation to finish to see if a specific requirement was missed.
*   **Error Propagation:** If the model hallucinated on the first step, subsequent steps were often based on bad data.

**The Solution:**
By implementing an agentic loop detailed in PR #12905, the CLI now enforces a "Plan -> Execute" workflow. This change ensures that complex logic is decoupled. It reduces cognitive load on the model by allowing it to focus on one sub-task at a time, resulting in higher accuracy and more reliable code generation.

## 3. How-To Guide

This feature requires no new flags or configuration; it is triggered automatically when the model detects a prompt with high complexity.

### Step 1: Input a Complex Command
Run the Gemini CLI with a prompt that implies multiple distinct actions.

```bash
gemini "Analyze the src/utils folder, create a unit test file for every .ts file found, and generate a summary report in markdown."
```

### Step 2: Watch the Plan Generation
Instead of streaming code immediately, the CLI will output a plan:

> **Gemini is planning your task...**
> 
> ⬜ List all .ts files in src/utils
> ⬜ Create test file for date-utils.ts
> ⬜ Create test file for string-formatter.ts
> ⬜ Generate SUMMARY.md

### Step 3: Execution & Completion
As the CLI works, you will see the UI update in real-time (referenced as the "gif" in the changelog):

> ✅ List all .ts files in src/utils
> ✅ Create test file for date-utils.ts
> 🔄 **Create test file for string-formatter.ts** (In Progress...)
> ⬜ Generate SUMMARY.md

Once finished, the CLI returns control to the user.

## 4. Walkthrough / Technical Deep Dive
*Based on the PR size change of +967 B in `gemini.js`.*

The implementation of this feature is surprisingly lightweight, suggesting a change in the **system prompt architecture** and the **orchestration loop** rather than a massive engine overhaul.

1.  **Intent Recognition:** When a prompt is received, the CLI evaluates if the request requires a "Chain of Thought" or single-shot answer.
2.  **Task Decomposition:** If complex, the model is prompted to generate a structured JSON object or specific token sequence representing the "Todo List."
3.  **The Loop:**
    *   The `gemini.js` bundle likely contains a small state machine that iterates through this list.
    *   It feeds the context of "Task 1 Output" into the prompt for "Task 2."
4.  **Sandbox Interaction:** The file size changes in `gemini.js` (and the presence of `sandbox-macos-*.sb` files in the context) confirm that the CLI maintains secure boundaries while executing these sequential file operations.

This approach mimics "Agentic" behaviors seen in frameworks like LangChain, but natively optimized for the Gemini CLI experience.
