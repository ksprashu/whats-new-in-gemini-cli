# 🚀 Gemini CLI Update: Multi-Extension Uninstall Support

**PR Reference:** [#13016](https://github.com/google-gemini/gemini-cli/pull/13016)
**Contributor:** [@JayadityaGit](https://github.com/JayadityaGit)

## 1. Feature Summary
The Gemini CLI now supports **Multi-Uninstall** for extensions. This feature allows users to remove multiple extensions in a single operation, streamlining environment cleanup and extension management.

Previously, users were restricted to uninstalling extensions one by one. With this update, the `uninstall` command accepts variadic arguments (a list of names), processes them sequentially, and provides a consolidated status report upon completion.

## 2. Background & Context
**The Problem:**
As the Gemini ecosystem grows, developers frequently install multiple extensions for testing, development, or specific project workflows. Cleaning up this environment was previously tedious. If a user wanted to remove three extensions, they had to run the uninstall command three separate times, waiting for the CLI to initialize and complete for each individual instance.

**The Solution:**
Pull Request #13016 refactors the extension management logic. By updating the command signature to accept multiple arguments, we reduce friction for power users and CI/CD pipelines that need to ensure a clean state.

Crucially, this update addresses **robustness**. In a batch operation, if one item fails to uninstall, it shouldn't stop the rest. This PR ensures that the process is resilient, handling partial failures gracefully rather than aborting the entire operation.

## 3. How-To Guide

The command syntax has evolved from `uninstall <name>` to `uninstall <names...>`.

### Basic Usage
To uninstall multiple extensions, simply list them separated by spaces.

```bash
# Old workflow (still supported, but slower)
gemini ext uninstall extension-one
gemini ext uninstall extension-two

# New workflow (Multi-uninstall)
gemini ext uninstall extension-one extension-two extension-three
```

### Handling Errors
If you attempt to uninstall a mix of existing and non-existing extensions, the CLI will handle the valid ones and report errors for the invalid ones at the end.

**Example:**
*Assuming `valid-ext` exists, but `fake-ext` does not.*

```bash
gemini ext uninstall valid-ext fake-ext
```

**Result:**
1. `valid-ext` is uninstalled successfully.
2. The CLI attempts to uninstall `fake-ext` and logs an error internally.
3. The process finishes and reports the specific error for `fake-ext`.
4. The CLI exits with a non-zero status code to indicate that not every request was successful.

## 4. Walkthrough / Technical Deep Dive
Based on the architectural changes in PR #13016, here is how the feature works under the hood:

### Variadic Argument Parsing
The command definition was updated to support `args...`. This transforms the input from a single string argument into an array of strings.
*   **Before:** `uninstall(name: string)`
*   **After:** `uninstall(names: string[])`

### Aggregated Error Handling Strategy
The most significant technical improvement is the "continue-on-error" loop. The logic follows this flow:

1.  **Initialization:** An empty list of `errors` is created.
2.  **Iteration:** The CLI iterates through every extension name provided in the arguments.
3.  **Execution:** It attempts the uninstallation logic for the current extension.
4.  **Catch & Continue:** If an exception occurs (e.g., extension not found, permission denied), the error is caught and pushed to the `errors` list. **Crucially, the loop does not break.** It proceeds to the next extension.
5.  **Final Reporting:** Once the loop finishes:
    *   If the `errors` list is empty, the command exits with Success (0).
    *   If the `errors` list contains items, the CLI prints all accumulated errors to `stderr` and exits with Failure (non-zero).

### Backward Compatibility
Because the logic simply treats a single argument as an array of length 1, existing scripts and workflows that uninstall extensions one by one remain fully functional without modification.
