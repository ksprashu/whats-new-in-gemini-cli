# 🚀 What's New: Seamless Paste & Terminal Reliability

## 1. Feature Summary
The latest update to the Gemini CLI brings significant quality-of-life improvements to terminal interactions, specifically focusing on **Clipboard operations**. We have introduced a robust **OSC 52 fallback mechanism**, ensuring paste functionality works even when system clipboard access fails. Additionally, we have completely refactored how the CLI handles pasting on Windows, resolving issues where newlines were dropped or misinterpreted during multi-line pastes.

In short: **Pasting code and prompts into the Gemini CLI is now smoother, faster, and more reliable across all operating systems.**

## 2. Background & Context
Terminal-based tools often struggle with the simple act of pasting text. Different operating systems and terminal emulators handle clipboard data differently. Based on recent pull requests and issue reports, we identified two major friction points for our users:

*   **Silent Failures (PR #15336):** The CLI relies on the `clipboardy` library to read the system clipboard. However, in certain environments (like headless servers or restricted containers), this library would fail silently or throw generic errors, leaving the user unable to paste their code context.
*   **Windows Formatting Issues (PR #15932):** Windows users experienced erratic behavior when pasting multi-line text. The previous implementation of "bracketed paste" wasn't correctly detecting terminal capabilities, leading to garbled input where newlines were ignored or processed incorrectly.

These changes were made to centralize terminal logic and provide "graceful degradation"—if the best way to paste fails, the CLI now has smart backup plans.

## 3. How-To Guide
Because these features are foundational reliability improvements, there are no new flags or configuration files required. You simply benefit from them by updating the CLI.

### How to Verify the Experience
1.  **Update Gemini CLI** to the latest version.
2.  **Copy a block of code** (e.g., a Python function with indentation and multiple lines) from your IDE.
3.  **Run a Gemini command** that accepts input, such as `gemini chat`.
4.  **Paste the code** into the terminal.

**What you will see:**
*   **On Windows:** The code will appear instantly with all line breaks and indentation preserved, exactly as it was in your IDE.
*   **Over SSH/Remote:** If you are using a modern terminal (like iTerm2, Windows Terminal, or VS Code), the paste will succeed even if the remote server cannot access your local OS clipboard, thanks to the OSC 52 fallback.

## 4. Walkthrough / Technical Deep Dive
For the curious, here is how we re-engineered the paste logic under the hood.

### A. The OSC 52 Fallback Mechanism
*Ref: PR #15336*

Previously, if `clipboardy` failed to read the clipboard, the operation aborted. We have introduced a fallback chain:
1.  **Primary Attempt:** The CLI attempts to read the clipboard via standard system calls (`clipboardy`).
2.  **The Fallback:** If that fails, the CLI sends an **OSC 52** (Operating System Command) escape sequence to the terminal emulator. This effectively asks the terminal: *"Please send me the contents of the user's clipboard."*
3.  **Response Parsing:** The CLI listens to `stdin` for the specific OSC 52 response sequence.
4.  **Decoding:** The terminal responds with Base64-encoded text. The CLI's `KeypressContext` now includes logic to capture this stream, decode the Base64 content, and emit a clean "paste" event.

### B. Intelligent Bracketed Paste & Windows Fixes
*Ref: PR #15932*

We moved away from a scattered approach (logic split between React hooks and utility files) to a centralized **`TerminalCapabilityManager`**.

1.  **Dynamic Detection:** Instead of assuming support, the Manager now actively queries the terminal to see if it supports "Bracketed Paste Mode."
2.  **Centralized Control:** Enabling/disabling this mode is now handled in one location, preventing race conditions.
3.  **The `bufferFastReturn` Solution:** For Windows environments or terminals that *do not* support bracketed paste, we implemented a buffering mechanism. It detects the rapid sequence of characters typical of a paste operation. Specifically, it watches for "fast returns" (newline characters arriving in milliseconds) and ensures they are interpreted as formatting rather than "Submit Command" keystrokes.
