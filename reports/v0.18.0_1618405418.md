# 🚀 Gemini CLI Update: Natural Language Control for Redis

## 1. Feature Summary
The Gemini CLI now supports direct integration with **Redis** via the Model Context Protocol (MCP). By installing the new Redis extension (`@redis/mcp-redis`), developers can manage, query, and manipulate data within their Redis instances using natural language.

Instead of remembering complex `redis-cli` syntax or switching context to a GUI tool, you can now simply ask Gemini to "find all keys starting with `session:`" or "check the memory fragmentation ratio," directly from your terminal.

## 2. Background & Context
### The Problem
Developers frequently interact with Redis for caching, session management, and message brokering. However, this workflow often introduces friction:
*   **Context Switching:** Developers must leave their coding environment to use `redis-cli` or third-party GUI tools (like RedisInsight).
*   **Syntax Recall:** interacting with complex data types (Hashes, Sorted Sets) or specific modules (RedisJSON) requires memorizing specific command arguments.
*   **Safety:** Manually typing `FLUSHALL` or delete commands carries a risk of human error.

### The Solution
This change leverages the **Model Context Protocol (MCP)**. By treating Redis as an external tool context, Gemini acts as an intelligent translation layer. The `mcp-redis` repository provides a standardized server that exposes Redis capabilities as executable "tools" to the LLM.

This integration transforms the CLI from a text generator into an **agentic database administrator**, allowing for semantic queries (e.g., "What is the structure of the user profile hash?") rather than just syntax queries.

## 3. How-To Guide

### Prerequisites
*   Gemini CLI installed and authenticated.
*   A running Redis instance (Local Docker container or Redis Cloud).
*   Node.js (required to run the MCP server).

### Step 1: Install the Extension
Run the following command in your terminal to register the Redis MCP server with Gemini:

```bash
gemini extensions install https://github.com/redis/mcp-redis
```

### Step 2: Configuration
When prompted (or via your configuration file), provide the connection string for your Redis instance.
*   **Environment Variable:** `REDIS_URL`
*   **Example:** `redis://localhost:6379` or `redis://:password@host:port`

### Step 3: Usage Examples
Once installed, you can interact with Redis naturally.

**Example A: Basic CRUD**
> **User:** "Set a key named 'deployment_status' to 'active' with a TTL of 60 seconds."
> **Gemini:** "I have set `deployment_status` to `active` (expires in 60s)."

**Example B: Investigation**
> **User:** "List all keys that look like user session tokens and show me the value of the first one."
> **Gemini:** "I found 5 keys matching `session:*`. Here is the value for `session:1024`: ..."

**Example C: Server Health**
> **User:** "What is the current memory usage of my Redis instance?"
> **Gemini:** "According to `INFO MEMORY`, the `used_memory_human` is 12.5M."

## 4. Walkthrough / Technical Deep Dive
Here is how the interaction works under the hood:

1.  **The MCP Server:** The `redis/mcp-redis` package runs as a local server implementing the Model Context Protocol. It connects to your database using the standard `ioredis` client.
2.  **Tool Exposure:** The server exposes specific **Tools** to Gemini. Based on the source code, these include:
    *   `list_keys`: Wrapper for the `KEYS` or `SCAN` command.
    *   `get_value`: Retrieves values based on type (String, Hash, List, etc.).
    *   `set_value`: Handles `SET` operations.
    *   `execute_command`: A "fallback" tool that allows the LLM to construct raw Redis commands (e.g., `FT.SEARCH` or `JSON.GET`) if a specific tool doesn't exist.
3.  **The Reasoning Loop:**
    *   You ask: *"Find the user hash for ID 5."*
    *   Gemini CLI analyzes the request and selects the `execute_command` tool with arguments `['HGETALL', 'user:5']`.
    *   The MCP server executes this against Redis.
    *   The JSON result is fed back to Gemini, which summarizes it in plain English for you.

**Security Note:** The extension runs locally on your machine. Credentials are passed via environment variables and are not sent to Google's servers—only the schema of the tools (available functions) and the final text response are processed by the model.
