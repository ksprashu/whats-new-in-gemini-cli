# Gemini CLI Release Report: Built-in Skills, Gemini 3 Refinements, and Core Hardening

## 1. Feature Summary
This release focuses on streamlining the user experience and hardening the application core. The headline feature is the introduction of **Built-in Agent Skills**, which allows core functionalities to operate seamlessly without user friction. Additionally, we have refined the **Gemini 3 model's system instructions** to prioritize conciseness over conversation. On the technical side, users will notice significant performance improvements in large repositories due to **cached `.gitignore` parsing**, and improved reliability via a **robust, transparent retry mechanism** for network requests.

## 2. Background & Context
This release addresses specific friction points identified by the community and the engineering team:

*   **Friction in Core Capabilities (PR #16045):** Previously, all agent skills were treated equally. This meant users often had to explicitly confirm or view "housekeeping" skills that should be implicit. The introduction of "Built-in Skills" solves this by distinguishing core capabilities that should be trusted by default, reducing UI clutter and decision fatigue.
*   **Gemini 3 Verbosity (PR #16139):** Feedback indicated that the Gemini 3 model had become overly conversational ("chatter"), engaging in pleasantries rather than delivering direct technical answers. This update recalibrates the model to respect a "No Chitchat" rule unless explaining complex, non-obvious logic.
*   **Performance Bottlenecks (PR #16185):** In projects with complex or deeply nested `.gitignore` files, the CLI was experiencing lag. This was traced back to the repeated parsing of raw ignore patterns (Issue #11610). The new caching strategy resolves this.
*   **Network Resilience (PR #16489):** Transient network failures were causing operations to abort too quickly (after only 3 attempts), often silently or without clear user feedback. The retry count has been increased to 10, and the CLI now transparently communicates these attempts to the user.

## 3. How-To Guide

### Managing Built-in Skills
Built-in skills are designed to work in the background. By default, running `/skills list` will **not** show these system-level capabilities to keep your view clean.

To inspect the full range of capabilities, including the new built-in skills:

**In the CLI:**
```bash
gemini skills list --all
```

**In Chat/Slash Commands:**
```text
/skills list all
```

*Look for skills tagged with the `[Built-in]` label. You will notice that invoking these does not trigger a confirmation dialog.*

### Observing the Retry Mechanism
You don't need to configure this, but you will see it in action during network instability. Instead of the CLI hanging or failing immediately, you will now see real-time logs:

```text
Trying to reach gemini-1.5-pro (Attempt 1/10)
...
Trying to reach gemini-1.5-pro (Attempt 2/10)
```

## 4. Walkthrough / Technical Deep Dive

### Built-in Agent Skills Architecture
This feature required changes to the `SkillDefinition` interface and the `SkillManager`.
*   **Schema Update:** A new boolean property, `isBuiltin`, has been added to the skill definition.
*   **Priority Loading:** The `SkillManager` now loads these skills first.
*   **UI Filtering:** A new method, `getDisplayableSkills()`, filters these out for standard status bars and lists, ensuring the "Active Skills" count reflects only user-added tools.
*   **Trusted Execution:** The `ActivateSkillTool` logic has been modified to check the `isBuiltin` flag. If true, it bypasses the standard human-in-the-loop confirmation flow.

### `.gitignore` Caching Strategy
Performance was optimized by changing how the `GitIgnoreParser` handles data.
*   **Old Method:** Cached raw rule strings (`Map<string, string[]>`). This required re-compiling the ignore logic every time a file was checked against the rules.
*   **New Method:** Caches the compiled instance (`Map<string, Ignore>`) using the `node-ignore` library.
*   **Result:** The parser now retrieves a pre-compiled object, significantly reducing CPU cycles during file filtering in large repositories.

### Gemini 3 System Prompt Engineering
The improvements to Gemini 3 were achieved via "prompt engineering" rather than code changes.
*   **Restored Rules:** The "No Chitchat" directive was reinstated.
*   **Nuanced Instructions:** The prompt now explicitly differentiates between "obvious actions" (which require no explanation) and "non-obvious/complex actions" (which allow for a brief explanation). This prevents the model from explaining simple file reads while still allowing it to articulate complex reasoning.

### Event-Driven Retry Logic
The retry mechanism was overhauled to be event-driven.
*   **Core Events:** A new `RetryAttempt` event was added to `coreEvents`.
*   **Flow:** When a request fails, the core emits this event containing the `attemptCount`, `error`, and `model` ID.
*   **UI Listener:** The CLI UI listens for this specific event to render the `(Attempt X/Y)` feedback string, decoupling the networking logic from the display logic.

## 5. Next Steps for Demos

When showcasing this release to the community, I recommend the following three demos:

1.  **The "Silent" Skill Demo:**
    *   *Setup:* Run a complex prompt that utilizes both a user-defined skill and a new built-in skill.
    *   *Action:* Show the user-defined skill asking for permission (Y/N), while the built-in skill executes instantly.
    *   *Payoff:* Highlight the reduction in "clicks" and friction.

2.  **The "Ghost" Network Demo:**
    *   *Setup:* use a network throttling tool or mock a 500 error response.
    *   *Action:* Trigger a request.
    *   *Payoff:* Zoom in on the CLI output showing "Trying to reach... (Attempt 1/10)". Explain how this saves the user from restarting long-running tasks due to a 1-second Wi-Fi blip.

3.  **The "To The Point" Comparison:**
    *   *Setup:* Ask Gemini 3 a simple question like "Summarize this PR."
    *   *Comparison:* Show a screenshot of the old verbose response (with "Sure! I can help with that...") vs. the new response which immediately starts with the summary.
    *   *Payoff:* demonstrates respect for the developer's time.
