# 🚀 What’s New: The `/rewind` Command

**Date:** October 26, 2023
**Feature:** Session History Navigation & File Reversion
**PR:** [#15720](https://github.com/google-gemini/gemini-cli/pull/15720)
**Contributors:** @Adib234

---

## 1. Feature Summary
The Gemini CLI has introduced a powerful new mechanism for session management: the **/rewind** command. This feature acts as a "time machine" for your terminal, allowing developers to reset their conversation history to a specific previous message. Crucially, it integrates file system management with conversation history, offering the ability to automatically revert file changes made by Gemini during the segment of the conversation that is being rewound.

## 2. Background & Context
**The Problem:**
In conversational coding workflows, "rabbit holes" are common. A developer might ask Gemini to implement a feature, iterate on it for five or six turns, and realize the approach is fundamentally flawed. Previously, recovering from this required two manual steps:
1.  Manually undoing file changes (via git checkout or undoing saves).
2.  Restarting the CLI session or manually ignoring previous context to stop the LLM from hallucinating based on the "bad" path.

**The Solution:**
PR #15720 introduces a unified solution. By linking chat history checkpoints with file modification events, the `/rewind` command empowers users to exercise granular control over their workspace state. It acknowledges that in an AI-coding assistant context, **chat history and code state are inextricably linked.**

## 3. How-To Guide
The `/rewind` command is designed to be interactive. Here is how to use it in your daily workflow:

### Step 1: Invoke the Command
When you realize you need to step back in a conversation, simply type:
```bash
/rewind
```

### Step 2: Select the Checkpoint
The CLI will display your recent conversation history. Select the specific message you wish to return to.

### Step 3: Choose Your Rewind Mode
Once a target message is selected, you will be presented with three options regarding file changes associated with the messages you are "erasing":

*   **Rewind Only:** Resets the conversation context to the selected point but leaves your local files exactly as they are now. (Best for when you like the code, but want to restart the chat context).
*   **Rewind and Revert:** Resets the conversation context *and* undoes any file changes made by Gemini since that point. (Best for a complete "Undo" of a failed experiment).
*   **Revert Only:** Keeps the conversation history intact but undoes the file changes. (Best for when you want to keep the context/knowledge but reset the code implementation).

### Bonus: Improved Readability
As part of this update, when referencing files in your chat, you will now see distinct headers and footers:
```text
--- Content from referenced files ---
[File content here]
--- End of content ---
```
This makes it significantly easier to distinguish between your prompt, the LLM's response, and the raw file data being processed.

## 4. Walkthrough / Technical Deep Dive
The implementation of PR #15720 touches several core components of the Gemini CLI architecture:

**1. The `rewindCommand` Logic:**
The core logic resides in the new `rewindCommand` unit. It maintains a mapping between conversation turns and file system operations. When a user initiates a rewind, the system traverses the history stack backward. Depending on the selected mode (Rewind/Revert), it triggers file system rollbacks using the stored diffs or previous file states associated with those specific message IDs.

**2. Enhanced `loadHistory` Mechanism:**
A subtle but high-impact change was made to the `loadHistory` function in the UI context. It now accepts an optional `postLoadInput` parameter.
*   *Why this matters:* When you rewind a conversation, you usually want to immediately try a *different* prompt. This technical change allows the CLI to pre-populate the input buffer immediately after the history loads, streamlining the user experience so you can start typing immediately without waiting for a UI refresh loop.

**3. Reference Formatting (`@commandProcessor`):**
The `@commandProcessor` was updated to wrap retrieved file content in visual delimiters. This is purely a UX improvement, ensuring that large blocks of code from referenced files do not visually merge with the AI's natural language explanation.
