# Gemini CLI Update: Skills, Agent Hot-Reloading, and Enhanced Defaults

**Contributors:** @NTaylorMullen, @scidomino, @joshualitt

## 1. Feature Summary
This release focuses heavily on Developer Experience (DX), streamlining how agents are managed, developed, and utilized. Key updates include:

*   **Skills Enabled by Default & New `pr-creator` Skill:** The experimental "Skills" feature is now active out-of-the-box. We’ve also shipped a specific `pr-creator` skill to standardize how agents generate Pull Requests.
*   **Hot-Reloading for Agents:** You can now run `/agents refresh` to reload agent definitions and clear caches without restarting the entire CLI.
*   **Zero-Config Help Agent:** The `cli_help` agent is now enabled by default, providing immediate assistance without manual setup.
*   **UX Refinements:** A new user-configurable setting to suppress the "Home Directory" startup warning.

## 2. Background & Context

### Streamlining Workflows (PR #16232)
Previously, utilizing Gemini to create Pull Requests relied heavily on the LLM "guessing" the correct format or the user explicitly prompting with constraints every time. By introducing the **`pr-creator` skill**, we are effectively "grounding" the agent. This skill guides the agent to locate and strictly follow the repository's existing PR templates. Furthermore, enabling skills by default removes friction—users no longer need to hunt through JSON configs to turn on this powerful feature.

### Improving Iteration Speed (PR #16204)
Developers building custom agents faced a significant bottleneck: every time an agent definition was modified, the Gemini CLI had to be fully restarted to recognize the change. This broke flow and slowed down the development loop. The new **`/agents refresh`** command solves this by clearing internal caches and reloading the registry dynamically.

### Reducing Onboarding Friction (PR #16100)
The **CLI Help Agent** is a vital tool for new users, but it previously required manual activation. By making this default, we ensure that documentation and help are accessible via natural language immediately after installation, aligning the software behavior with the "batteries included" philosophy.

## 3. How-To Guide

### Using the `pr-creator` Skill
Since skills are now enabled by default, you can immediately leverage the PR creator if you have the CLI running in a repo.

1.  Ensure you have a PR template in your repository (e.g., `.github/pull_request_template.md`).
2.  Ask Gemini to open a PR:
    ```bash
    > /gemini create a PR for these changes
    ```
3.  The agent will now utilize the `pr-creator` skill to read your template and format the PR description accordingly.

### Hot-Reloading Agents
If you are developing a custom agent or editing an existing one in `.gemini/agents/`:

1.  Make changes to your agent's code or prompts.
2.  Instead of killing the terminal process, run:
    ```bash
    > /agents refresh
    ```
3.  The CLI will confirm the reload, and your changes are live immediately.

### Configuring the Home Directory Warning
If you frequently run the CLI from your user root and want to suppress the security warning:

1.  Open your `.gemini/settings.json`.
2.  Add the following key:
    ```json
    {
      "ui.showHomeDirectoryWarning": false
    }
    ```

## 4. Walkthrough / Technical Deep Dive

### The Skills Architecture
The activation of skills is handled via the `.gemini/settings.json` file. The update to `.gitignore` ensures that while the specific `.gemini/skills/` directory is tracked (allowing teams to share skills like `pr-creator` within the repo), local user settings can remain private if needed.

The `pr-creator` works by providing a structured definition (likely within `.gemini/skills/pr-creator/SKILL.md`) that acts as a system prompt extension, instructing the model to look for specific file paths (standard git provider template paths) before generating text.

### Agent Registry Reload Mechanism
The `/agents refresh` command triggers a complex chain of events in the backend:

1.  **Command Execution:** The command invokes a new function (refactored out of the main agents logic).
2.  **Registry Clearing:** The `AgentRegistry` calls a `reload()` method. This doesn't just re-read files; it aggressively clears the existing dictionary of loaded agents.
3.  **Cache Invalidation:** The `A2AClientManager` (Agent-to-Agent) executes `clearCache()`. This removes cached agent clients and "Agent Cards," ensuring that no stale metadata persists.
4.  **Event Emission:** A core event `AgentsRefreshed` is broadcast. This allows UI components or other listeners to update their state (e.g., refreshing a list of available agents in a GUI wrapper) without a hard reset.

### Default Configuration Logic
For the CLI Help agent, the change was applied in `packages/core/src/config/config.ts` and validated against `schemas/settings.schema.json`. The logic simply inverts the check: where it previously looked for `enabled: true`, the absence of a configuration now implies `enabled` for this specific agent ID.

## 5. Next Steps for Demos

When showcasing these changes in a video or demo, consider the following flow:

1.  **The "Developer Loop" Demo:**
    *   Start with a basic custom agent.
    *   Make a code change to the agent (e.g., change its personality or output format).
    *   Show the "Old Way" (mentioning needing to restart).
    *   **Show the "New Way":** Run `/agents refresh` and immediately call the agent to show the updated behavior.

2.  **The "Smart PR" Demo:**
    *   Open a repo with a specific, rigid PR template.
    *   Make some messy code changes.
    *   Ask Gemini to create a PR.
    *   Highlight how the output strictly adheres to the template headers thanks to the `pr-creator` skill.

3.  **The "Fresh Install" Experience:**
    *   Delete local configs.
    *   Start the CLI.
    *   Immediately ask: `@cli_help how do I change settings?`
    *   Show that it answers immediately without the user having to "turn on" the help bot.
