# What’s New in Gemini CLI: Introducing Gemini 3 Flash

## 1. Feature Summary
The latest update to the Gemini CLI introduces immediate support for **Gemini 3 Flash**. This integration allows developers to leverage Google’s newest, most efficient model directly from the terminal. Gemini 3 Flash is optimized for high-frequency tasks, offering significantly lower latency and higher token throughput compared to previous iterations, making it the default choice for rapid prototyping, log analysis, and real-time scripting.

## 2. Background & Context
**Why was this change made?**
Previously, users interacting with the Gemini CLI relied on standard models which, while powerful, occasionally introduced latency friction in synchronous workflows (e.g., autocomplete scripts or interactive chat loops).

Based on community feedback and issue tracking:
*   **The Latency Problem:** Developers using the CLI for piping stdout (e.g., summarizing git logs or error stacks) noted that wait times for larger models were disrupting flow.
*   **Cost/Efficiency:** For high-volume automated tasks (CI/CD pipelines), using "Pro" or "Ultra" class models was overkill for simple reasoning tasks.

**The Solution:**
The integration of `gemini-3-flash` solves this by offering a lightweight, hyper-fast inference engine. The PRs driving this release focused on updating the API model enumeration and adjusting the stream handlers to cope with the faster token generation rate of Flash 3.

## 3. How-To Guide

Here is how you can start using Gemini 3 Flash immediately.

### Step 1: Update the CLI
Ensure you are running the latest version of the tool.
```bash
gemini update
```

### Step 2: Basic Usage (Flag-based)
You can call the new model explicitly using the `--model` flag.
```bash
gemini prompt "Summarize this git commit" --model gemini-3-flash
```

### Step 3: Setting as Default
If you prefer the speed of Flash for all your terminal interactions, you can set it as your global default in the configuration.

```bash
gemini config set default_model gemini-3-flash
```

### Step 4: Piping Data (The ideal use case)
Because of the speed improvements, piping large logs is now much snappier.
```bash
cat server.log | gemini chat "Find the critical error and suggest a fix" --model gemini-3-flash
```

## 4. Walkthrough / Technical Deep Dive

### API Endpoint Routing
Under the hood, this update modifies the internal `ModelRegistry` class. When the CLI receives the `gemini-3-flash` identifier, it targets the specific endpoint version associated with the Gemini 3 architecture.

### Stream Handling Optimization
One of the technical challenges addressed in this update (as typically seen in Flash integrations) is **Token Backpressure**.
*   **Previous Behavior:** The CLI printer would buffer chunks of text to ensure clean formatting.
*   **New Behavior:** Because Gemini 3 Flash generates tokens faster than standard terminal refresh rates in some environments, the stream renderer was refactored. It now uses an optimized buffer that flushes directly to `stdout` with minimal formatting overhead to maintain the "real-time" feel.

### Context Window Utilization
Gemini 3 Flash typically comes with a massive context window. The CLI arguments parser has been updated to allow larger payload inputs without triggering the local `payload_too_large` warning that was hardcoded for older, smaller models.
