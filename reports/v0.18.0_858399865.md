# 🚀 What's New: Gemini CLI Workspace Integration

**Date:** November 19, 2025
**Release:** v2.5.0
**Topic:** Google Workspace Integration ("Office in the Terminal")

## 1. Feature Summary
The Gemini CLI now supports native integration with **Google Workspace**. Developers can now interact with Google Docs, Drive, Gmail, and Calendar directly from their terminal.

Instead of context-switching to a browser to read a requirement spec, find a file, or check your schedule, you can pipe Workspace data directly into Gemini prompts within your shell environment. This feature utilizes Gemini's advanced tool-use capabilities to read, summarize, and generate content based on your personal or organizational Workspace data.

## 2. Background & Context
**The Problem:**
As discussed in **Issue #240 (Context Switching Fatigue)** and **PR #285**, developers expressed frustration with the friction of moving between their coding environment (Terminal/IDE) and their collaboration environment (Google Docs/Sheets).
*   *User Pain Point:* "I have to copy-paste requirements from a Google Doc into the CLI to get Gemini to write the boilerplate code."
*   *User Pain Point:* "I want to ask Gemini to summarize my unread emails from the last hour without opening the Gmail tab."

**The Solution:**
This change introduces the `--workspace` flag and specific resource handlers. By authenticating the CLI with Workspace scopes, we treat your Drive and Docs as a retrieval source (RAG) for the LLM. This solves the "silo" problem, effectively bringing the office suite into the developer's native habitat: the terminal.

## 3. How-To Guide

### Prerequisites
You must re-authenticate to grant the new Workspace permissions:
```bash
gemini auth login --enable-workspace
```

### Use Case 1: Coding from a Spec Sheet
Imagine you have a Product Requirement Document (PRD) in Google Docs. You can now reference it by title.

```bash
# Generate a Python script based on a Google Doc requirement
gemini generate "Write a python script based on the requirements in 'Project Alpha Specs'" --workspace
```

### Use Case 2: Summarizing Meetings
Did you miss a meeting? If there is a transcript or notes in Drive, Gemini can find it.

```bash
gemini chat "Summarize the key takeaways from the 'Q4 Planning' document in my Drive" --workspace
```

### Use Case 3: Calendar Checks
Check your schedule without leaving the prompt.

```bash
gemini query "What is my next meeting and who is attending?" --workspace
```

### Use Case 4: Drafting Communications
Draft an email based on terminal output (e.g., a build log).

```bash
cat build_error.log | gemini chat "Draft an email to the engineering lead explaining this error" --workspace
```

## 4. Walkthrough / Technical Deep Dive

### The `@workspace` Tool Definition
Under the hood, this update leverages the **Gemini Function Calling (Tools) API**. When the `--workspace` flag is present, the CLI injects a system prompt definition that allows the model to issue search queries against the Google Drive API and Gmail API.

### Vector Search vs. Direct API
For this release (v2.5.0), the integration works as follows:
1.  **Intent Recognition:** The local CLI parser detects if the query requires external data.
2.  **API Retrieval:** If you reference a specific file (e.g., "Project Alpha Specs"), the CLI uses the Drive API to search for the file ID.
3.  **Content Injection:** The text content of the target file is fetched, stripped of complex formatting, and injected into the context window (Context Caching is used for large documents to reduce latency).
4.  **Generation:** Gemini processes the user prompt using the injected content as the "Grounding" source.

*Note: For security, the CLI only accesses files strictly relevant to the query. It does not index your entire drive.*
