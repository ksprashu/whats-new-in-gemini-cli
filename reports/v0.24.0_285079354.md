# Gemini CLI Update: Dynamic Agent & Skill Management

## 1. Feature Summary
The latest release of the Gemini CLI introduces a suite of "Hot Reload" and management features designed to keep developers in the flow. We have eliminated the need to restart the application when modifying configurations or developing extensions.

**Key additions include:**
*   **`/agents refresh`**: Dynamically reloads agent definitions and clears internal caches.
*   **`/skills reload`**: Refreshes discovered skills and applies configuration changes (enabling/disabling skills) instantly.
*   **`/skills install` & `/skills uninstall`**: Native CLI commands to manage Agent Skills from Git repositories or local paths without manual file operations.

## 2. Background & Context
**The "Restart Loop" Friction**
Prior to these changes, the developer experience involved a significant amount of friction when modifying the CLI environment.
*   **Agents:** As detailed in PR #16204, updating an agent's code or definition required a full application restart to clear the `AgentRegistry` and `A2AClientManager` caches.
*   **Skills:** Similarly, per PR #15865, simply enabling or disabling a skill in your settings required a restart for the changes to take effect. The CLI would previously display a static "Restart required" notice.

**Management Overhead**
Previously, installing a new skill was a manual process involving file system operations. PR #16377 addresses this by bringing package-manager-style convenience to Agent Skills, allowing users to pull skills directly from repositories or local archives.

**The Solution**
These updates collectively shift the CLI from a static configuration model to a **dynamic runtime model**, allowing the system to react to changes in the file system and configuration state without tearing down the session.

## 3. How-To Guide

### Managing Skills (Install/Uninstall)
You can now manage skills directly via the CLI, supporting both global (User) and project-specific (Workspace) scopes.

**Install a skill from a Git Repository:**
```bash
gemini skills install https://github.com/example/my-agent-skills.git --scope workspace
```
*Note: This supports monorepos! The installer handles subpaths automatically if the repository structure follows standard extension patterns.*

**Install from a local directory:**
```bash
gemini skills install ./path/to/local/skill --scope user
```

**Uninstall a skill:**
```bash
gemini skills uninstall my-agent-skill --scope workspace
```

### Hot-Reloading Configurations
If you change your `gemini` configuration (e.g., disabling a specific skill in your config file), you no longer need to restart.

1.  Modify your configuration file (e.g., add a skill to `disabledSkills`).
2.  Run the command:
    ```
    /skills reload
    ```
3.  The CLI will re-scan extensions and apply the new settings immediately.

### Developing Agents
If you are writing code for a custom agent and update its prompt or logic:

1.  Save your code changes.
2.  Run the command:
    ```
    /agents refresh
    ```
3.  The agent registry is rebuilt, caches are cleared, and your new logic is active immediately.

## 4. Walkthrough / Technical Deep Dive

### The Agent Refresh Logic (PR #16204)
The implementation of `/agents refresh` required deep changes to the `AgentRegistry` and cache management.
*   **Registry Reload:** A new `reload()` method was added to the `AgentRegistry`. This clears existing definitions and triggers a re-scan of the configured agent directories.
*   **Cache Invalidation:** Simply reloading definitions wasn't enough because the `A2AClientManager` (Agent-to-Agent) held stale references. A `clearCache()` method was implemented to explicitly remove cached agent clients and cards.
*   **Event Propagation:** A core event, `AgentsRefreshed`, is emitted upon completion. This allows other subsystems to react to the change, ensuring the UI and logic layers are synchronized.

### The Skills Reload Logic (PR #15865)
The `/skills reload` command relies on a new reactivity model within the core `Config` class.
*   **Re-Discovery:** The `Config.reloadSkills()` method re-executes the skill discovery process (scanning both extensions and local paths).
*   **Tool Re-registration:** It specifically re-registers the `ActivateSkillTool`, ensuring the LLM knows exactly which tools are currently available.
*   **UI Reactivity:** To ensure the user interface reflects these changes (e.g., in `/skills list`), a `SettingsChanged` event updates a `settingsNonce` in the `AppContainer`. This forces a React re-render of the relevant UI components, keeping the visual state in sync with the backend state.

### Skill Installation (PR #16377)
The installation logic leverages the existing `cloneFromGit` utility, ensuring reliability consistent with other parts of the ecosystem. It abstracts away the complexity of checking out specific branches or handling sparse checkouts for monorepos, placing the skill definition exactly where the runtime expects to find it based on the provided `--scope`.

## 5. Next Steps for Demos
To showcase these features effectively in a video or live demo, I recommend the following flows:

1.  **The "Live Coding" Demo:**
    *   Start a conversation with a custom agent.
    *   Modify the agent's system prompt in VS Code to change its personality (e.g., make it speak like a pirate).
    *   **Don't restart.** Run `/agents refresh`.
    *   Ask the same question again and show the immediate change in behavior.

2.  **The "One-Command" Setup:**
    *   Start with a clean workspace (no skills).
    *   Run `/skills list` to show it's empty.
    *   Run `gemini skills install <git-url>` to pull a complex skill (e.g., a Jira or GitHub integration).
    *   Immediately use the skill without restarting.

3.  **The "Config Toggle" flow:**
    *   Demonstrate a skill working.
    *   Edit the local config file to disable that skill.
    *   Run `/skills reload`.
    *   Show the CLI correctly refusing to use the disabled skill.
