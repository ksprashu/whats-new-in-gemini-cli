# 🚀 What's New in Gemini CLI v1.5.0: Personas & Interactive Chat

## 1. Feature Summary
The latest update to the Gemini CLI shifts the tool from a transactional "command-and-response" utility to a fully contextual coding partner. We are introducing two major capabilities:

1.  **System Instructions (The `--system` flag):** You can now define the behavior, tone, and role of the AI before the conversation starts. Whether you need a strict linter, a creative writer, or a Python expert, Gemini now stays in character.
2.  **Interactive REPL Mode:** Instead of piping single prompts, you can now launch a continuous chat session where context is preserved across multiple turns.

## 2. Background & Context
### Why this change?
Prior to this release, users engaged with the CLI in a "stateless" manner. As noted in **Issue #142 (Context Loss in complex debugging)**, developers found it frustrating to re-paste code snippets or re-explain the architecture in every single command.

Furthermore, **PR #156** highlighted that users were manually prepending "Act as a Senior React Developer..." to every prompt to get high-quality code reviews. This was repetitive and consumed token limits unnecessarily.

This update addresses these friction points by:
*   **Offloading Context Management:** The CLI now handles the conversation history buffer in memory during interactive sessions.
*   **Separating Instruction from Content:** By utilizing the new API field for system instructions, we ensure the "persona" doesn't get diluted by the chat history.

## 3. How-To Guide

### Using System Instructions
You can now pass a system prompt to define the AI's role.

**Example: The Code Reviewer**
```bash
gemini prompt "Why is this loop causing a memory leak?" \
  --system "You are a Senior C++ Engineer. Be concise. Focus only on memory management."
```

**Example: The Pirate Poet (For fun)**
```bash
gemini prompt "Explain recursion" --system "You are a pirate who loves haikus."
```

### Launching Interactive Mode
To start a continuous session, simply omit the prompt argument or use the `chat` command:

```bash
gemini chat
```

Once inside the session:
```text
> Please write a Python function to parse a CSV.
[Gemini generates code...]

> Now add error handling for missing columns.
[Gemini updates the previous code maintaining context]
```

### Configuration Shortcuts
You can save common personas in your `~/.geminicli/config.yaml` to avoid typing them out:

```yaml
personas:
  reviewer: "You are a strict code reviewer. Look for security vulnerabilities."
```

Usage:
```bash
gemini prompt "Check this file" --persona reviewer
```

## 4. Walkthrough / Technical Deep Dive
### Under the Hood: The Chat Session Loop
When you execute `gemini chat`, the CLI initializes a local `ChatSession` object. Here is the technical flow implemented in **PR #160**:

1.  **Input Loop:** The CLI utilizes the `readline` library to handle user input, allowing for command history (up arrow) and standard editing hotkeys.
2.  **History Management:** Unlike the stateless `prompt` command, the `chat` command maintains a localized `history` array structured as `[{ role: 'user', parts: [...] }, { role: 'model', parts: [...] }]`.
3.  **Token Budgeting:** To prevent hitting API limits during long sessions, the CLI implements a rolling window context. If the history exceeds the model's token limit, the oldest pairs of messages (excluding the System Instruction) are dropped from the payload sent to the API.
4.  **Streaming & Buffering:** We have switched to the `streamGenerateContent` API endpoint. The CLI now opens a persistent stdout buffer, printing chunks of text as they arrive from the Gemini API, reducing the "Time to First Byte" (TTFB) perception for the user.
