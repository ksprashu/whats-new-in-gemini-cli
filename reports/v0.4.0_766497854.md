# 🚀 Gemini CLI Update: Cleaner Outputs with `hideSandboxStatus`

**Date:** October 26, 2023
**Feature:** `hideSandboxStatus` configuration
**Category:** User Experience / Automation

## 1. Feature Summary
The Gemini CLI has introduced a new configuration option: `hideSandboxStatus`. This feature allows developers to suppress the verbose intermediate status messages (such as "Writing code...", "Running code...") that are generated when the model utilizes the Code Execution sandbox. This results in a cleaner, strictly text-or-data output stream, ideal for automation and streamlined reading.

## 2. Background & Context
### The Problem
Previously, when a user prompted the Gemini CLI with a task requiring calculation or logic (e.g., "Calculate the 50th Fibonacci number"), the model would trigger the Code Execution tool. The CLI would print the real-time status of this sandbox environment to the console:

```text
> gemini "Calculate 100!"
running...
(Sandbox) Writing code...
(Sandbox) Executing...
The result is 9.3326...
```

While useful for debugging, this "chatter" creates two main issues:
1.  **Automation Friction:** If a user pipes the output of the CLI into another tool (like `jq` or a file writer), the status text contaminates the output stream.
2.  **Visual Clutter:** For users who trust the tool execution, the status updates are unnecessary noise.

### The Solution
The `hideSandboxStatus` change addresses this by adding a conditional check in the output renderer. It allows the user to opt-out of seeing the "behind the scenes" work of the code interpreter, delivering only the final answer or the relevant generated text.

## 3. How-To Guide

You can utilize this feature either via command-line flags or by updating your configuration file.

### Option A: Usage via Config File
If you permanently want cleaner output, add the property to your project's configuration (e.g., `gemini.config.js` or `.geminirc` depending on your setup).

```javascript
// gemini.config.js
module.exports = {
  // ... existing config
  hideSandboxStatus: true,
};
```

## 4. Walkthrough / Technical Deep Dive

To understand how this works, we must look at how the Gemini API streams responses involving tools.

1.  **The Stream:** When Gemini decides to write code, it sends response chunks containing `executableCode` and `executionStatus`.
2.  **The Default Renderer:** By default, the CLI listens for these specific chunk types. When it detects a "tool use" event, it prints a formatted status line (often colored or prefixed) to `stdout`.
3.  **The Logic Change:**
    The update introduces a boolean filter before the render step.
    *   **Old Logic:** `if (event.type === 'status') { print(event.msg); }`
    *   **New Logic:** `if (event.type === 'status' && !config.hideSandboxStatus) { print(event.msg); }`

This ensures that while the model *is* still writing and executing Python code in the backend sandbox, the CLI client silently waits for the final text response before updating the user interface.
