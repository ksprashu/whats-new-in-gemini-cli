# What’s New in Gemini CLI: In-Session Extension Management

## 1. Feature Summary
The Gemini CLI now supports dynamic extension management directly within an interactive session. Users can now execute **`/extensions list`** to view installed tools and **`/extensions update`** to refresh them without interrupting their current workflow or restarting the CLI. This introduces a "hot-swappable" experience for developer tools and plugins.

## 2. Background & Context
**The Problem:**
Previously, managing extensions (such as code interpreters, search tools, or custom API connectors) was a static process. If a developer realized they were missing a tool or needed the latest version of an extension while in the middle of a debugging session, they had to:
1.  Exit the Gemini CLI (`Ctrl+C` or `/bye`).
2.  Run a separate installation/update command in the shell.
3.  Restart the Gemini CLI.
4.  Re-establish context (paste previous code/prompts).

**The Solution:**
This change addresses the friction of context switching. By implementing slash commands (`/`), the CLI treats extension management as a meta-layer within the chat loop. This brings the Gemini CLI closer to an Integrated Development Environment (IDE) experience, where tooling can be adjusted on the fly without breaking the user's "flow state."

## 3. How-To Guide

Here is how to utilize the new commands within your workflow.

### Prerequisites
Ensure you are running the latest version of the Gemini CLI and enter interactive mode (usually by running `gemini chat` or the equivalent command to start the REPL).

### Listing Active Extensions
To see what tools the model currently has access to:

1.  Inside the chat prompt, type:
    ```bash
    /extensions list
    ```
2.  **Output:** The CLI will print a table or list of loaded extensions, their versions, and their status (Active/Inactive).

### Updating Extensions on the Fly
If you suspect an extension is outdated or you've just pushed a fix to a local custom extension:

1.  Inside the chat prompt, type:
    ```bash
    /extensions update
    ```
2.  **Action:** The CLI will poll the extension registry (or local paths), download updates, and reload the modules.
3.  **Confirmation:** You will receive a message confirming: *"Extensions updated: [List of updated packages]. Context refreshed."*

## 4. Walkthrough / Technical Deep Dive

How does this work under the hood?

1.  **Command Parsing:**
    The CLI's input loop now contains a pre-processor that scans for lines starting with `/`. When `/extensions` is detected, the request is intercepted before being sent to the LLM API.

2.  **The Extension Registry:**
    The CLI maintains an internal registry (likely a Python dictionary or singleton class) that maps Extension IDs to their loaded module objects.

3.  **Hot Reloading (The `/update` logic):**
    When `/extensions update` is triggered:
    *   The CLI halts the chat loop temporarily.
    *   It executes the update logic (e.g., `pip install --upgrade` or a git pull for local extensions) in a subprocess.
    *   **Module Reloading:** Crucially, it likely utilizes `importlib.reload()` (in Python environments) to refresh the memory reference to the extension code. This ensures the CLI uses the *new* logic immediately, rather than the cached bytecode from when the session started.

4.  **Context Injection:**
    After an update, the system prompt or tool definition schema sent to the Gemini API is regenerated to reflect any changes in the tools' arguments or descriptions.
