## 4. Walkthrough / Technical Deep Dive
*Note: While the specific tech stack wasn't in the provided context, most modern CLI docs follow this architecture.*

**The "Docs-as-Code" Philosophy:**
The new site likely utilizes a Static Site Generator (SSG) such as **Docusaurus** or **VitePress**. This means the documentation is treated exactly like software:
*   **Source Control:** Documentation lives in Markdown files within the repository.
*   **CI/CD:** When a Pull Request is merged to the `main` branch, a workflow triggers (likely via GitHub Actions) to build the static HTML/CSS/JS assets.
*   **Deployment:** These assets are pushed to a CDN (like Vercel or Netlify), ensuring the documentation is always globally distributed and fast.

**Why this matters for the CLI:**
This decoupling allows the CLI development to move fast without breaking the docs. We can version the documentation (e.g., v1.0 vs v2.0) so users on older versions of the CLI can still find relevant instructions, a feature impossible with a standard README.
