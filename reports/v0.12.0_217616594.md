# 🚀 What's New: Intelligent Model Routing & Enhanced Configuration

**Release Date:** *[Current Date]*
**Contributors:** @abhipatel12

## 1. Feature Summary
The Gemini CLI has introduced **Intelligent Model Routing** as a default behavior. This feature automatically analyzes your prompt and selects the most efficient model for the job.
*   **Simple tasks** (fact retrieval, basic formatting) are routed to **Gemini Flash**.
*   **Complex tasks** (creative writing, deep analysis, coding) utilize the full power of **Gemini Pro**.

Additionally, managing this feature is now significantly easier. The CLI now includes a toggle within the interactive `/settings` dialog, removing the need to manually edit configuration files.

## 2. Background & Context
### The Problem
Previously, users faced two main friction points:
1.  **Quota Exhaustion:** Using the most powerful model (Pro) for every trivial interaction wasted API quota and increased latency unnecessarily.
2.  **Configuration Friction:** As noted in **PR #9262**, disabling or enabling specific routing features required users to manually locate and edit a `settings.json` file. This was error-prone and broke the flow of the terminal experience.

### The Solution
To address these issues, the team has enabled the Model Router by default. This ensures that new and existing users get the most optimized experience (speed and quota savings) out of the box without setup. Simultaneously, the introduction of a GUI-based toggle inside the CLI ensures that power users who want manual control can access it instantly.

## 3. How-To Guide

### Automatic Usage
You do not need to take any action to enable this. Simply run your queries as usual:

```bash
gemini "What is the capital of France?"
# > Routing logic detects a simple query -> Uses Gemini Flash (Fast/Low Quota)

gemini "Refactor this legacy Java class into Kotlin using functional programming patterns."
# > Routing logic detects complexity -> Uses Gemini Pro (High Reasoning)
```

### Managing the Feature via UI
If you prefer to force a specific model at all times, you can disable routing via the new settings menu:

1.  Open the settings dialog:
    ```bash
    /settings
    ```
2.  Navigate to the **Model Router** option.
3.  Press `Enter` or `Space` to toggle the value (On/Off).
4.  Save and Exit.

*Note: You can also access model options quickly via the `/model` command.*

## 4. Walkthrough / Technical Deep Dive
### Under the Hood
The core logic resides in the `ModelRouter` component. When a user submits a prompt, the CLI evaluates the complexity of the request before dispatching it to the API.

### Configuration Architecture Changes
According to **PR #9262**, several architectural changes were made to support this streamlined UX:

*   **Default State Flip:** The `useModelRouter` flag in `config.ts` was flipped to `true`. This means the routing logic is active immediately upon installation or update.
*   **Schema Update:** `settingsSchema.ts` was updated to ensure the new default state is validated correctly and persists properly when modified via the UI.
*   **Backward Compatibility:** The update includes logic to respect existing user configurations while defaulting to "On" for fresh environments.

### Code Path
The integration points for this feature were:
1.  **`settings.json`**: The storage backend.
2.  **`SettingsDialog.tsx`**: The frontend TUI (Text User Interface) element that now reads/writes the `useModelRouter` boolean directly.
3.  **`config.test.ts`**: Updated unit tests to ensure the default-on behavior doesn't cause regressions in the initialization flow.
