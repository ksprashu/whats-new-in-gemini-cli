# What's New in Gemini CLI: Instant Slash Commands

**Release Component:** CLI Experience / UX
**Contributor:** @jackwotherspoon

---

### 1. Feature Summary
The Gemini CLI has streamlined the workflow for interacting with system commands. With the introduction of **Auto-execute Simple Slash Commands**, users no longer need to perform a double-confirmation step for parameter-less commands.

When you type a simple command (such as `/clear` or `/reset`) and press `Enter`, the action is now triggered immediately. This removes friction from the interactive loop, making the CLI feel snappier and more responsive.

### 2. Background & Context
**The Friction Point:**
Prior to this update, the Gemini CLI treated slash commands similarly to standard prompts or complex commands requiring arguments. When a user typed a command like `/clear`, the CLI would often stage the input or wait for a secondary confirmation to ensure the user was finished typing.

**The Solution:**
In the associated PR discussions, the team identified that commands without arguments ("simple" commands) are binary intentions: the user wants to perform the action, and they want it now.

By implementing this change, we resolve the "Double-Enter" fatigue. The CLI now intelligently distinguishes between a command that *might* need more input (like switching models) and a command that is self-contained. This change aligns the Gemini CLI behavior with standard terminal expectations found in other mature developer tools.

### 3. How-To Guide

Using this feature requires no configuration changes—it is enabled by default in the latest build. Here is how to experience the difference:

#### The Old Workflow (Previous Versions):
1. User types: `/clear`
2. User presses: `Enter`
3. System: Highlights the command or moves to a new line waiting for confirmation.
4. User presses: `Enter` (again)
5. System: Clears the screen.

#### The New Workflow (Current Version):
1. User types: `/clear`
2. User presses: `Enter`
3. **System: Immediately clears the screen.**

**Supported "Simple" Commands:**
While the specific list depends on the current version, this feature generally applies to commands that require no arguments, such as:
*   `/clear` (Wipes the current display)
*   `/reset` (Resets the chat context)
*   `/exit` or `/quit` (Leaves the CLI)

### 4. Walkthrough / Technical Deep Dive
Under the hood, this update modifies the CLI's **Input Loop** and **Command Parser**.

Previously, the parser likely treated the `Enter` keystroke as a signal to "tokenize" the current line, regardless of content. It would then wait for the execution signal.

With the @jackwotherspoon update, the logic flow has shifted:
1.  **Input Detection:** As the user hits `Enter`, the parser immediately inspects the buffer.
2.  **Prefix Check:** It detects the leading slash `/`.
3.  **Registry Lookup:** It compares the string against a registry of known "Simple Commands" (commands defined as `args=0` or `void`).
4.  **Bypass:** If a match is found (e.g., `/reset`), the parser bypasses the "staging" state and invokes the `execute_command()` function directly.

If the command requires arguments (e.g., `/model gemini-pro`), the CLI retains standard behavior, allowing the user to type the command, press space, and input arguments without premature execution.
