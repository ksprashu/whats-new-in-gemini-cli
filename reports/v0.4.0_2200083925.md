# 🚀 Gemini CLI Update: Introducing `hideCWD`

**Version Update Report**
**Focus:** Privacy & Context Management

---

## 1. Feature Summary
The Gemini CLI now supports a new configuration option: **`hideCWD`**.

By default, the CLI often provides the Large Language Model (LLM) with context about your current environment to improve answer relevancy. This new feature allows developers to suppress the automatic injection of the Current Working Directory (CWD) path into the system prompt. This ensures that your directory structure and file paths remain local and are not sent to the Gemini API unless explicitly shared.

---

## 2. Background & Context
**Why was this change made?**

In previous versions, the Gemini CLI aimed to be "context-aware" by automatically appending your current location in the terminal (e.g., `/Users/dev/projects/secret-v2`) to the system prompt. While helpful for file-specific operations, this behavior introduced two specific friction points for users:

1.  **Privacy & PII Leakage:** Many developers work in directories that contain Personally Identifiable Information (PII) in the file path itself (e.g., `/Users/firstname.lastname/`). When sharing logs or working on sensitive internal projects, sending the absolute path to the cloud is often a security violation or a privacy concern.
2.  **Prompt Noise:** For general queries (e.g., "Write a Python script to sort a list"), the directory path is irrelevant. Including it unnecessarily consumes token bandwidth and can occasionally confuse the model if the directory name implies a context that conflicts with the user's prompt.

The `hideCWD` feature solves this by giving control back to the user, allowing for a "clean slate" prompt environment.

---

## 3. How-To Guide

There are generally two ways to utilize this feature, depending on whether you want it for a single session or as a permanent setting.

### Option A: Configuration File (Permanent)
If you prioritize privacy and never want your path sent to the API, add the flag to your global or local `.gemini-cli.json` (or `.rc`) configuration file.

```json
{
  "options": {
    "hideCWD": true
  }
}
```

### Option B: Command Line Flag (Temporary)
For one-off commands where you want to ensure the path is hidden, pass the flag as an argument:

```bash
gemini chat "How do I reverse a binary tree?" --hideCWD
```

## 4. Walkthrough / Technical Deep Dive

To understand how this works, we have to look at how the Gemini CLI constructs the **System Prompt**.

**Before (Default Behavior):**
When you run a command, the CLI constructs a payload that looks roughly like this before sending it to the API:

```text
[SYSTEM MESSAGE]
You are a helpful coding assistant.
Current Context: User is working in directory: "/Users/jdoe/client-work/project-alpha"

[USER MESSAGE]
Create a README.md for this.
```
*Result:* The AI creates a README specifically referencing "project-alpha" because it saw the path.

**After (With `hideCWD` enabled):**
The CLI pre-processing logic checks the boolean flag `hideCWD`. If set to `true`, it bypasses the path retrieval logic.

```text
[SYSTEM MESSAGE]
You are a helpful coding assistant.

[USER MESSAGE]
Create a README.md for this.
```
*Result:* The AI creates a generic README template without inferring project names or context from the folder structure. This results in a "pure" interaction where the AI relies solely on the text you explicitly provide.
