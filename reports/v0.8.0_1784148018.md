# 🚀 What's New: Non-Interactive Support for `--allowed-tools`

**Release**: Gemini CLI Update
**PR References**: [#9114](https://github.com/google-gemini/gemini-cli/pull/9114), Issue [#9011](https://github.com/google-gemini/gemini-cli/issues/9011)
**Contributor**: @mistergarrison

---

## 1. Feature Summary
The Gemini CLI has expanded the functionality of the `--allowed-tools` flag. Previously limited to interactive (chat/REPL) sessions, this flag can now be used in **non-interactive mode**.

This means developers can now specify exactly which tools (e.g., Google Search, Code Execution) the model is permitted to use when running "one-shot" commands, scripts, or piped operations.

## 2. Background & Context
**The Problem:**
Prior to this change, automation and scripting with the Gemini CLI were somewhat rigid regarding tool usage. If a user wanted to run a single command (e.g., `gemini prompt "What is the stock price of GOOG?"`) from a bash script, they had little control over tool invocation compared to the interactive session. The CLI would likely default to "auto" or "none," potentially leading to hallucinations on real-time data or preventing code execution when it was actually needed.

**The Solution:**
Addressed in PR #9114, this update bridges the gap between interactive experimentation and production automation. By enabling `--allowed-tools` in non-interactive mode, the CLI allows for:
*   **Deterministic Scripting:** ensuring the model *must* use (or *cannot* use) specific tools during automated tasks.
*   **Parity:** Bringing feature parity between the interactive shell and single-command execution.

## 3. How-To Guide

Here is how you can utilize the new functionality in your daily workflows.

### Basic Syntax
```bash
gemini prompt "YOUR PROMPT" --allowed-tools [TOOL_LIST]
```

### Example 1: Enforcing Real-World Data (Google Search)
If you are writing a script to fetch the latest news, you can now force the CLI to allow Google Search, ensuring the model doesn't rely solely on training data.

```bash
gemini prompt "What were the top 3 tech headlines yesterday?" \
  --allowed-tools google-search
```

### Example 2: Safe Calculation (Code Execution)
When asking for complex math or data processing, you can enable the Python code execution tool to ensure accuracy.

```bash
gemini prompt "Calculate the 50th Fibonacci number" \
  --allowed-tools code-execution
```

### Example 3: Restricted Environment
If you want to ensure the model acts as a pure text processor *without* reaching out to the web or executing code, you can explicitly control the environment (depending on the default behavior of the specific model version).

```bash
# Example: Summarize a local file without external tools
cat logs.txt | gemini prompt "Summarize these errors" --allowed-tools function-calling
```

## 4. Walkthrough / Technical Deep Dive
*Note: While the specific code diff is not visible in the provided snippet, the implementation logic follows standard CLI architecture patterns.*

**Under the Hood:**
1.  **Argument Parsing:** The CLI’s argument parser (`argparse` or similar) was updated to accept `--allowed-tools` as a global argument applicable to the `prompt` command, rather than being scoped exclusively to the `chat` or `interactive` subcommand.
2.  **Payload Construction:** When a non-interactive command is triggered, the CLI constructs a payload to send to the Gemini API.
    *   **Before:** The `tools` configuration object in the API request was likely omitted or set to `null` for one-shot commands.
    *   **After:** The CLI checks if the `--allowed-tools` flag is present. If so, it maps the requested tools (strings) to the corresponding API tool definitions (objects) and injects them into the API request body.
3.  **Stateless Execution:** Unlike interactive mode, which maintains a history, this execution is stateless. The model receives the prompt and the tool definitions, decides if a tool is necessary, executes it (server-side), and returns the final response in a single transaction lifecycle visible to the user.
