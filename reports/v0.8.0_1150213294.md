# 🚀 Feature Report: Real-Time Terminal Title Status

**Release:** Gemini CLI (Latest)
**Feature:** Dynamic Terminal Window Titles
**Contributor:** @Fridayxiao

---

## 1. Feature Summary
The Gemini CLI now supports **Terminal Title Status updates**. When enabled, the CLI utilizes the operating system’s window title bar to display real-time status indicators and "thoughts" from the LLM.

Instead of staring at a static cursor or relying solely on inline spinners, users can now glance at the tab or window title to see if Gemini is "Thinking," "Generating," or "Idle." This feature allows for better observability without cluttering the main output stream.

---

## 2. Background & Context
**The Problem:**
previously, users running complex queries or long-running tasks had to keep the terminal window in focus to track progress. If a developer switched to their IDE or browser while waiting for a response, they had no visibility into the CLI's state without tabbing back.

**The Solution:**
This feature utilizes the terminal emulator's native ability to display text in the window frame.

**Development Insights (PR #4386):**
The initial implementation proposed using a command-line argument (flag) to trigger this behavior. However, during the code review process, the maintainers identified this as a persistent user preference rather than a one-off toggle.
Consequently, the logic was refactored to check `settings.ts`. This ensures that users who enjoy this "heads-up display" style of status reporting can enable it once in their configuration and have it persist across all sessions.

## 3. How-To Guide

To enable this feature, you need to modify your Gemini CLI configuration settings. This is an **opt-in** feature.

### Step 1: Open your settings
Locate your Gemini CLI configuration file (typically `~/.gemini/config.json` or accessible via the settings command).

### Step 2: Update the configuration
Add or update the `showStatusInTitle` key to `true`.

```json
{
  "showStatusInTitle": true,
  "...": "other existing settings"
}
```

### Step 3: Run the CLI
Start a new session. When you submit a prompt, observe the top bar of your terminal window (or the tab name if using a tabbed terminal like iTerm2 or Windows Terminal).

**Example Workflow:**
1.  Run `gemini chat`.
2.  Input a complex prompt: *"Write a recursive algorithm to solve the Tower of Hanoi in Python."*
3.  Look at the window title. It will dynamically shift from your shell name (e.g., `zsh`) to Gemini's status (e.g., `Thinking...`, `Generating Code...`).

## 4. Walkthrough / Technical Deep Dive

### Under the Hood
This feature works by emitting **ANSI Operating System Command (OSC) escape sequences**—specifically **OSC 0** or **OSC 2**.

1.  **State Detection:** The CLI monitors the lifecycle of the LLM request.
    *   *State A:* Request sent (Thinking).
    *   *State B:* Tokens receiving (Streaming).
    *   *State C:* Request complete (Idle).
2.  **Configuration Check:** Before emitting updates, the application checks the `settings` object to verify `showStatusInTitle === true`.
3.  **The Escape Sequence:**
    *   To set the title, the CLI prints a standard sequence to `stdout` that looks like: `\x1b]0;Gemini: Thinking...\x07`.
    *   The terminal emulator intercepts this code. Instead of printing text to the screen, it replaces the string in the window’s title bar.
4.  **Cleanup:** Once the command exits or returns to the prompt, the CLI sends a final sequence to reset the title or allow the shell to reclaim control of the title bar.

### Why `settings.ts`?
As noted in the PR context, moving this to `settings.ts` allows for a cleaner user experience. CLI flags are best reserved for runtime variables (like specifying a file input), whereas UI behaviors (like colors, spinners, and window titles) belong in persistent configuration.
