# 🚀 What's New: Fuzzy Search in Gemini CLI Settings

**Contributor:** @sehoon38  
**Category:** User Experience / Configuration  

---

## 1. Feature Summary
The Gemini CLI has updated the configuration management experience. We have introduced **Fuzzy Setting Search** within the interactive settings dialog.

Previously, finding a specific configuration key required scrolling through a static list or knowing the exact setting name. Now, users can simply type partial queries (including typos or abbreviations) to instantly filter and locate the setting they need.

---

## 2. Background & Context
**The Problem:**
As the Gemini CLI capabilities have grown, so has the list of configurable options (e.g., API keys, model regions, temperature, token limits, safety filters).
*   **Navigation Fatigue:** Users reported that manually scrolling through long lists using arrow keys was inefficient.
*   **Cognitive Load:** Users often remember *what* they want to change (e.g., "tokens") but not the exact configuration key string (e.g., `max_output_tokens`). Exact string matching failed in these scenarios.

**The Solution:**
This update addresses the friction of configuration management. By implementing fuzzy search, we shift the burden of discovery from the user to the CLI. This change was championed by @sehoon38 to make the tool feel more responsive and developer-friendly.

---

## 3. How-To Guide

Here is how to utilize the new search functionality:

1.  **Launch Settings:**
    Open your terminal and run the interactive configuration command:
    ```bash
    gemini settings
    # or depending on your specific alias
    gemini config edit
    ```

2.  **Start Typing:**
    Instead of pressing the `↓` (down arrow) immediately, start typing what you are looking for.
    *   *Example:* Type `tok`

3.  **Select and Edit:**
    The list will automatically filter down.
    *   Input: `tok`
    *   Result: `max_output_tokens` becomes highlighted.
    *   Press **Enter** to select and edit the value.

## 4. Walkthrough / Technical Deep Dive

### Under the Hood
This feature likely leverages a scoring algorithm (such as Levenshtein distance or a modified Smith-Waterman algorithm) to rank strings based on their similarity to the input pattern.

**How it functions:**
1.  **Input Listener:** The settings dialog creates an event listener on the standard input (stdin) that captures keystrokes without blocking the render loop.
2.  **Scoring & Filtering:** As each character is typed, the search engine compares the input string against the dictionary of available configuration keys.
    *   It looks for sequential matches (e.g., "m-d-l" matches "**m**o**d**e**l**").
    *   It assigns a weight/score to the match.
3.  **Real-time Re-rendering:** The CLI redraws the terminal view, hiding items with a low match score and bringing high-scoring items to the top of the selection list.

### Why "Fuzzy"?
Unlike a "Wildcard" search (which requires `*search*`) or "Exact" search, Fuzzy search allows for discontinuity and minor errors.
*   **Input:** `temprature` (spelled wrong) -> **Matches:** `temperature`
*   **Input:** `apik` -> **Matches:** `google_api_key`
