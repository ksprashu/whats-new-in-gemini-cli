# Gemini CLI Update: Streamlining Context and Configuration

**Date:** October 26, 2023
**Version:** *[Insert Version Number]*
**Report by:** Developer Relations Team

## 1. Feature Summary
This release focuses on **hygiene, explicit control, and standardization**. We have removed a suite of deprecated command-line flags to declutter the CLI’s invocation profile. 

The most significant changes are:
1.  **Removal of `--all-files` / `-a`:** Global context inclusion is now handled exclusively via `@` mentions (e.g., `@**/*`) directly within the prompt.
2.  **Removal of `--telemetry-*` flags:** Telemetry configuration has moved from per-command flags to a centralized `settings.json` configuration file (and supported environment variables).

These changes reduce the surface area of the CLI arguments and force a more intentional approach to context management.

## 2. Background & Context

### Why remove `--all-files`?
*Based on PR #11228*
The `-a` flag was a blunt instrument. It blindly included every file in the current directory as context. As repositories grow, sending the "full context" becomes inefficient, potentially exceeding token limits or introducing noise that degrades the quality of Gemini's responses. 

The engineering team undertook a significant refactoring effort to remove the `fullContext` logic. By shifting to `@` mentions, we are enforcing **Context Handling Refinement**. Users must now explicitly define what Gemini sees. This makes the codebase cleaner and aligns with best practices for Generative AI—providing only the relevant context yields better results.

### Why remove Telemetry flags?
*Based on PR #11318*
Previously, configuring telemetry required passing verbose flags (like `--telemetry-otlp-endpoint`) with every command or creating complex shell aliases. This made the argument parsing logic heavy and the user experience inconsistent.

By moving these options to `settings.json`, we achieve **Configuration Centralization**. This simplifies the CLI architecture and ensures that telemetry settings are persistent and consistent across sessions, rather than dependent on the specific flags passed during a single execution.

## 3. How-To Guide

### Context Management: From Flags to Mentions
If you previously used `-a` to ask Gemini to look at your whole project, you will now use glob patterns in your prompt.

**Deprecated (Old Way):**
```bash
gemini prompt "Summarize this project" --all-files
# OR
gemini prompt "Summarize this project" -a
```

**New Way (Explicit Context):**
To replicate the old behavior (include everything), use the glob pattern:
```bash
gemini prompt "Summarize this project @**/*"
```

To include specific folders or file types (Recommended):
```bash
gemini prompt "Find bugs in my controllers @src/controllers/*.ts"
```

### Telemetry Configuration: From Flags to Settings
You no longer need to pass telemetry endpoints as arguments. These should now be defined in your `settings.json` file.

**Deprecated (Old Way):**
```bash
gemini prompt "Hello" --telemetry --telemetry-otlp-endpoint="http://localhost:4318"
```

**New Way (Centralized Config):**
Edit your `settings.json` (usually located in your global configuration directory, e.g., `~/.gemini/settings.json` or project-specific `.gemini/` folder) to include your telemetry configuration.

*Example `settings.json`:*
```json
{
  "telemetry": {
    "enabled": true,
    "target": "otlp",
    "otlpEndpoint": "http://localhost:4318",
    "otlpProtocol": "http/protobuf",
    "logPrompts": false
  }
}
```
*Note: You may also utilize environment variables for these settings in CI/CD environments.*

## 4. Walkthrough / Technical Deep Dive

### Refactoring `fullContext` Logic
In **PR #11228**, the removal of the `-a` flag wasn't just a UI change; it was a cleanup of the internal architecture. 
*   **Previously:** The CLI had a specific branch of logic that triggers an environment context builder to scan the directory tree whenever `-a` was detected.
*   **Now:** The CLI relies entirely on the prompt parser. When the prompt string is analyzed, the application looks for the `@` token. If found, it resolves the file paths or glob patterns immediately. This unifies context resolution into a single pipeline rather than having a "flag-based" pipeline and a "prompt-based" pipeline.

### Argument Parsing Simplification
In **PR #11318**, the removal of six different telemetry flags significantly reduced the complexity of the argument parser. 
*   **Under the hood:** The application now initializes configuration *before* command execution by reading `settings.json`. The telemetry provider is instantiated based on this static config. This removes the need for the CLI to validate conflicting flags (e.g., passing a target but missing an endpoint) at runtime for every single command.
