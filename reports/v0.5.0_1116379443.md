# 🚀 What’s New: Experimental Tool Output Truncation

## 1. Feature Summary
The Gemini CLI has introduced an **experimental** configuration option: `enableToolOutputTruncation`. 

When enabled, this feature automatically detects when a shell command executed by the CLI produces excessive output. Instead of flooding the LLM’s context window with thousands of lines of logs, the CLI will now truncate the output sent to the model and save the **full, raw output to a separate file**. This ensures the model stays focused on the relevant data while preserving the complete logs for user review.

## 2. Background & Context
**The Problem:**
When using Gemini to execute shell commands (e.g., system diagnostics, builds, or reading files), specific commands can generate massive amounts of `stdout` or `stderr` data. 
*   **Context Window Exhaustion:** Passing a 5,000-line build log to the model consumes a significant portion of the token limit, potentially causing the model to "forget" earlier instructions.
*   **Cost & Latency:** Processing massive, low-value log data increases API costs and response latency.
*   **Model Confusion:** Too much noise can hallucinate the model or distract it from the actual error message, which is often located at the very end of the stream.

**The Solution:**
By implementing output truncation, we decouple the *human need* for full logs from the *model's need* for concise context. This change allows developers to run "noisy" commands without fear of breaking the conversation flow.

## 3. How-To Guide

### Enabling the Feature
This feature is currently opt-in. You must update your configuration to enable it.

1.  Open your Gemini CLI configuration file (typically `gemini.json` or passed via runtime config).
2.  Add the `enableToolOutputTruncation` key to the root or the tool-specific configuration block.

```json
{
  "experimental": {
    "enableToolOutputTruncation": true
  }
}
```

### Usage Example
Imagine you want Gemini to analyze a project's dependencies, which involves running a verbose installation process.

**User Prompt:**
> "Run `npm install` and check for critical vulnerabilities."

**Behavior WITHOUT Truncation:**
Gemini receives thousands of lines of progress bars and warnings, potentially hitting the token limit before it can even analyze the result.

**Behavior WITH Truncation:**
1.  Gemini executes `npm install`.
2.  The CLI detects the output exceeds the threshold.
3.  Gemini receives a system message:
    ```text
    [Output truncated. Full output saved to /tmp/gemini-output-x82ka.txt]
    ...
    added 850 packages in 12s
    found 3 vulnerabilities (1 moderate, 2 high)
    ```
4.  Gemini successfully parses the summary lines and reports back to you.

## 4. Walkthrough / Technical Deep Dive

Based on the file changes in `bundle/gemini.js` (+708 B), here is a look at the logic implementation:

1.  **Stream Interception:** The CLI wraps the standard shell execution tool. It hooks into the `stdout` and `stderr` streams of the spawned process.
2.  **Buffer Management:** As data flows in, the CLI maintains an internal character or token counter.
3.  **Threshold Logic:** Once the output exceeds a predefined "sanity limit" (likely hardcoded or heuristic-based in this experimental phase), the CLI stops appending to the string that will be sent to the LLM.
4.  **File Redirection:** Simultaneously, the *entire* stream is piped to a temporary file on the host machine.
5.  **Context Construction:** When the command finishes, the Tool Output returned to the LLM is modified. Instead of the raw string, it returns a composite message containing:
    *   The head (start) of the logs.
    *   A notification of truncation containing the file path.
    *   The tail (end) of the logs (crucial for catching error codes usually printed last).

*Note on Sandbox Files:* The changelog lists several `sandbox-macos-*.sb` files. While their size didn't change significantly, their presence in the context implies that this feature works within the constraints of the CLI's security sandbox, ensuring that writing the "overflow" file is a permitted operation.
