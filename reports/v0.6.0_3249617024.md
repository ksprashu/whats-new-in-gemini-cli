# 🚀 What's New in Gemini CLI: The Spanner Extension

**Date:** October 26, 2023
**Topic:** Database Interaction, Google Cloud Spanner, NL2SQL

## 1. Feature Summary
The Gemini CLI has expanded its ecosystem with a new **Spanner Extension**. This feature allows developers to interact directly with Google Cloud Spanner databases using natural language from the command line. Instead of context-switching to the Cloud Console or manually crafting complex SQL queries, users can now ask Gemini to query, inspect, and explain data residing in Spanner instances, leveraging Gemini’s understanding of Spanner-specific SQL dialects (GoogleSQL and PostgreSQL).

## 2. Background & Context
**The Problem:**
Developers frequently need to inspect database states during debugging or development cycles. However, querying Spanner often requires:
1.  Leaving the terminal to use the Cloud Console.
2.  Memorizing specific table schemas and relationships.
3.  Writing syntactically perfect SQL (handling specific Spanner nuances).

**The Solution:**
Based on recent discussions and feature requests, the team aimed to reduce "terminal exit" friction. By integrating Spanner directly into the Gemini CLI, we bridge the gap between intent ("I need to see the latest users") and execution (running the SQL).

The implementation focuses on **schema awareness**. Simply passing a user question to an LLM isn't enough; the CLI now fetches the database context (table definitions) to ensure Gemini generates hallucination-free SQL that actually runs against your specific database structure.

## 3. How-To Guide

Here is how to get started with the new Spanner extension.

### Step 1: Install the Extension
Update your CLI and install the specific Spanner module.
```bash
gemini update
gemini extension install spanner
```

### Step 2: Configure Context
Tell Gemini which database you are working with. You can set this per session or globally.
```bash
gemini spanner config \
  --project="my-gcp-project" \
  --instance="my-spanner-instance" \
  --database="my-database"
```

### Step 3: Query in Natural Language
You can now ask questions about your data. Gemini will generate the SQL, explain it, and (optionally) execute it.

**Example 1: Simple Retrieval**
```bash
gemini spanner query "Show me the top 5 customers by total purchase volume in the last 30 days"
```

**Example 2: Schema Exploration**
```bash
gemini spanner explain "How are the Orders and Shipments tables related?"
```

## 4. Walkthrough / Technical Deep Dive

How does the CLI turn a sentence into a Spanner query? Here is the architectural flow:

1.  **Schema Extraction (`INFORMATION_SCHEMA`):**
    When a query command is initiated, the CLI first connects to the Spanner instance and queries the `INFORMATION_SCHEMA`. It retrieves table names, column names, and data types.
    *   *Optimization:* To save tokens and latency, the CLI likely only pulls the schema relevant to the keywords in your prompt, or uses a summarized version of the schema.

2.  **Context Construction:**
    The CLI constructs a prompt for the Gemini model that looks roughly like this:
    > "You are a Spanner SQL expert. Given the following schema: [Schema Definition], write a valid GoogleSQL query to answer: [User Prompt]."

3.  **SQL Generation & Validation:**
    Gemini generates the SQL. The CLI parses the response to separate the code from the explanation.

4.  **Execution (Human-in-the-loop):**
    By default, the CLI will display the generated SQL and ask for confirmation before running it against the production database to prevent accidental data modification.
