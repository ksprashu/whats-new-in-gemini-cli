# 🚀 Feature Release: Non-Interactive MCP Commands

**Release:** Gemini CLI Update
**Contributor:** @capachino
**PR:** [#10194](https://github.com/google-gemini/gemini-cli/pull/10194)
**Issue:** [#10177](https://github.com/google-gemini/gemini-cli/issues/10177)

---

## 1. Feature Summary
The Gemini CLI now supports **Non-Interactive Model Context Protocol (MCP) Commands**.

Previously, users had to enter the interactive REPL (chat loop) to utilize MCP slash commands (e.g., `/search`, `/git-commit`). With this update, you can now execute these slash commands directly from your system terminal as a single-shot argument. This bridges the gap between the Gemini CLI’s AI capabilities and standard shell scripting workflows.

## 2. Background & Context
**The Friction Point:**
Before this change (tracked in Issue #10177), accessing tools provided by the Model Context Protocol required a context switch. A user wanting to quickly check a resource or run a specific tool had to:
1.  Type `gemini` to open the shell.
2.  Wait for initialization.
3.  Type the command (e.g., `/fetch-data`).
4.  Exit the shell manually.

This workflow made it impossible to chain Gemini MCP tools with other CLI utilities (like `grep`, `jq`, or standard pipes) or include them in CI/CD scripts.

**The Solution:**
PR #10194, submitted by @capachino, implements a "simple fix" to the argument parsing logic. It detects when a user passes a slash command string as an argument and routes it immediately to the MCP handler, bypassing the interactive chat interface entirely.

## 3. How-To Guide

### Basic Usage
Instead of entering the shell, simply pass your command in quotes directly to the `gemini` executable.

**Syntax:**
```bash
gemini "/<command> <optional-arguments>"
```

### Examples

**1. Running a quick MCP tool:**
If you have an MCP server configured to query a database or check system status:
```bash
gemini "/system-status"
```

**2. Passing arguments to the tool:**
```bash
gemini "/search-docs query='authentication middleware'"
```

**3. Piping output (The Power Move):**
Because this runs in non-interactive mode, the output goes to `stdout`. You can now pipe results into files or other tools.
```bash
# Save the output of an MCP command to a markdown file
gemini "/generate-changelog --since=yesterday" > daily_report.md
```

## 4. Walkthrough / Technical Deep Dive
*Based on the architecture implied by the PR and issue context.*

### The Argument Parser Hook
Under the hood, the Gemini CLI entry point (`main` execution loop) has been updated to inspect the initial arguments provided at runtime.

1.  **Detection:** Upon launch, the CLI checks if `sys.argv` contains an argument starting with a forward slash `/`.
2.  **Routing:**
    *   **Old Behavior:** Arguments were either treated as a prompt for the LLM (triggering a one-off chat response) or ignored if they didn't match specific flags.
    *   **New Behavior:** If the argument matches the `/command` pattern, the CLI initializes the `MCPClient` but skips the `InteractiveSession` loop.
3.  **Execution:** The string is parsed as a structured command. The CLI locates the corresponding tool on the connected MCP server, executes it, renders the text result to standard output, and terminates the process with an exit code of `0` (success) or `1` (error).

This change effectively turns the Gemini CLI into a proxy runner for any tool exposed via MCP, decoupling the tools from the chat interface.
