# 🛠️ Gemini CLI: Stability & Polish Update

This release focuses on hardening the core infrastructure of the Gemini CLI. While new features grab headlines, reliability builds trust. We have addressed critical friction points in agent orchestration, internationalization, and the terminal UI experience to ensure your workflows run smoothly from start to finish.

## 1. Feature Summary
This patch release (vX.X.X) targets **System Stability and UI Consistency**.
*   **Core Logic:** Fixed a critical race condition in subagent delegation that caused complex, multi-step workflows to hang or fail silently.
*   **Robustness:** resolved unhandled exceptions when processing Unicode characters (emojis, non-English languages) in prompt inputs and file parsing.
*   **User Experience:** Restored the "Sticky Header" functionality in the interactive terminal, ensuring context remains visible during long stream outputs.

## 2. Background & Context
*Based on recent Issue discussions and Pull Requests:*

*   **The Delegation Dilemma:** Users reporting "zombie processes" when using the `workflow` mode. Specifically, when the primary Orchestrator tried to hand off a task to a specialized subagent (e.g., the `coder` or `reviewer`), the state object wasn't persisting correctly. This resulted in the CLI waiting indefinitely for a response that would never come. This fix ensures the handshake between agents is atomic.
*   **The Unicode Crash:** As our global user base grew, so did reports of instant crashes when pasting code containing non-ASCII characters (like comments in Japanese or Mandarin) or using emojis in prompts. The crash was traced to a strict ASCII encoding expectation in the core logger, which has now been updated to full UTF-8 support.
*   **Sticky Header Regression:** A previous UI refactor inadvertently broke the calculation for the sticky header (which shows the current active model and token count). This made it difficult for developers to track context usage during long generation sessions.

## 4. Walkthrough / Technical Deep Dive

Here is a look at what changed under the hood to make this happen:

### 🔧 Fixing Subagent Delegation
The issue resided in the `AgentOrchestrator` class. Previously, the `handover_context` was being passed by reference, leading to a race condition where the subagent attempted to read the state before the parent had finished writing to it.
*   **The Fix:** We implemented an `async/await` lock on the state transfer and introduced a deep copy mechanism for the context object during handover. This ensures the subagent receives a pristine, immutable snapshot of the required data before beginning execution.

### 🌍 Handling Unicode Safely
The crash originated in the CLI’s logger wrapper, specifically `sys.stdout` handling on Windows environments and strict Docker containers.
*   **The Fix:** We forced the input/output streams to use `utf-8` encoding with error replacement strategies (`errors='replace'`).
*   **Code Insight:**
    ```python
    # Previous implementation (Prone to crash)
    print(user_input)

    # New implementation
    sys.stdout.buffer.write(user_input.encode('utf-8', 'replace'))
    ```

### 🖥️ UI Header Logic
The "Sticky Header" utilizes the `rich` library for TUI rendering. A previous optimization for render speed reduced the refresh rate of the layout table, causing the header to get "painted over" by new tokens.
*   **The Fix:** We isolated the Header into its own `Live` render group and adjusted the `z-index` equivalent in the TUI stack. We also reverted a change to the viewport calculation logic, ensuring the header row is excluded from the scrollable area calculations.
