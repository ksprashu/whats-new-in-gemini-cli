# 🚀 What's New: Introducing Skills to Gemini CLI

## 1. Feature Summary
The Gemini CLI has evolved from a text-generation interface into an **agentic command-line tool**. With the introduction of **Skills**, the CLI can now perform actions on your local machine or external networks based on your natural language prompts.

Instead of just telling you *how* to do something, Gemini can now have the permission to *do* it for you—whether that is reading local files, executing shell commands, or fetching data from URLs—transforming the CLI into an actionable AI coding assistant.

## 2. Background & Context
**The Problem:**
Previously, interactions with the Gemini CLI were passive. If you asked Gemini to "analyze the error logs in `app.log`," you had to manually copy the file content and paste it into the prompt. If you asked it to "fix the git conflict," it would output git commands that you then had to copy and run manually. This context-switching broke the developer "flow."

**The Solution:**
Based on the demand for "Agentic RAG" and automated workflows, this feature implements the **Gemini Function Calling API** directly into the terminal client.

*   **Goals:** Reduce friction between "asking" and "executing."
*   **Safety:** To prevent the AI from running dangerous commands (like `rm -rf`), a permission/confirmation layer is strictly enforced (discussed in the Deep Dive).

## 3. How-To Guide

### Prerequisites
Update your CLI to the latest version:
```bash
gemini update
```

### Basic Usage
Skills are often enabled via flags or defined in your configuration file.

**Example 1: The `fs_read` Skill (File System Reading)**
Instead of pasting code, let Gemini read it directly.
```bash
gemini "Explain the routing logic in my main.go file" --skill fs_read
```

**Example 2: The `shell_exec` Skill (Command Execution)**
Allow Gemini to run terminal commands to gather info.
```bash
gemini "List all docker containers related to redis and stop them" --skill shell_exec
```
*Note: The CLI will prompt you for confirmation before executing any shell command.*

### Creating a Custom Skill (Config Approach)
You can define custom skills in your `~/.gemini/config.yaml`:

```yaml
skills:
  - name: "weather"
    description: "Fetches current weather"
    command: "curl wttr.in/{{location}}?format=3"
```
**Usage:**
```bash
gemini "What is the weather in London?"
```

## 4. Walkthrough / Technical Deep Dive

Under the hood, this feature leverages **Gemini’s Native Function Calling** capabilities combined with a local execution sandbox.

### The Execution Loop
1.  **Schema Generation:** When you invoke the CLI with `--skill`, the CLI converts the available local tools (file reading, shell execution) into a JSON schema that describes the function signatures (name, description, arguments).
2.  **API Request:** The CLI sends your prompt *plus* these tool definitions to the Gemini API.
3.  **Model Reasoning:** The Gemini model determines it cannot answer with text alone; it recognizes it needs to use a tool. It returns a structured **Function Call** response (e.g., `call: fs_read(path="./main.go")`) instead of plain text.
4.  **Local Interception:** The CLI middleware intercepts this request. It pauses, executes the actual logic on your machine (reading the file), and captures the `stdout`.
5.  **Re-injection:** The CLI sends the output of the tool back to the Gemini API as a "Function Response."
6.  **Final Output:** Gemini processes the tool output and generates the final natural language answer for the user.

### Safety Mechanisms
*   **Human-in-the-Loop:** For high-risk skills (like `shell_exec`), the CLI implements a blocking prompt:
    `> Gemini wants to run: 'docker stop redis'. Allow? [y/N]`
*   **Sandboxing:** File system skills are restricted to the current working directory (CWD) by default to prevent unauthorized access to system files (like `/etc/shadow`).
