# 🚀 What's New: Interactive Shell Tool Calling

**Release Version:** (Associated with PR #11225)
**Date:** October 26, 2023

## 1. Feature Summary
The Gemini CLI has been upgraded to better detect its running environment. We have introduced **Conditional System Prompt Guidance**, which enables **Interactive Shell Tool Calling**. 

Previously, the CLI strictly instructed the underlying model to avoid interactive commands (like text editors or setup wizards) to prevent hanging processes. Now, the CLI detects if you are running in an interactive terminal session and removes those guardrails. This allows the model to execute tools that require user input (stdin) when you are present to provide it, while simultaneously optimizing token usage.

## 2. Background & Context
**The Problem:**
In previous versions of the Gemini CLI, the system prompt sent to the LLM contained a static "hard rule": *Do not use interactive commands.* This was a safety measure to ensure that if the CLI was running in a background job or CI/CD pipeline, the model wouldn't try to run a command like `npm init` or `apt-get install` (without `-y`), which would cause the process to hang indefinitely waiting for input that would never come.

However, for developers using the CLI directly in their terminal, this restriction was unnecessary. It prevented the model from assisting with tasks that naturally require a human-in-the-loop. Additionally, sending these instructions for every single request consumed unnecessary tokens.

**The Solution (PR #11225):**
As detailed in [Pull Request #11225](https://github.com/google-gemini/gemini-cli/pull/11225), the core system prompt is now dynamic. 
*   **Non-Interactive Mode:** The safety guidance remains.
*   **Interactive Mode:** The guidance is stripped out.

This change achieves two goals: it unlocks the ability to use interactive tools when appropriate, and it reduces the prompt size, saving costs and latency.

## 3. How-To Guide
This feature works out-of-the-box and requires no configuration changes. The CLI automatically detects your environment.

### Scenario: Running an Interactive Setup
You can now ask Gemini to run commands that will prompt you for input.

1.  Open your terminal.
2.  Run the Gemini CLI:
    ```bash
    gemini "Initialize a new package.json for this project using npm defaults but let me verify."
    ```
3.  **Old Behavior:** The model might have refused or tried to force flags to bypass interactivity.
4.  **New Behavior:** The model can execute `npm init`.
    *   The command starts.
    *   The process pauses and waits for *your* input in the terminal.
    *   You type your details and hit Enter.
    *   Gemini sees the command completion and continues its task.

### Scenario: Running a Python Input Script
If you have a script `ask_name.py`:
```python
name = input("What is your name? ")
print(f"Hello, {name}!")
```

You can instruct Gemini:
```bash
gemini "Run the python script ask_name.py"
```
The CLI will execute the script, you will see the prompt "What is your name?", type your response, and the execution will conclude successfully.

## 4. Walkthrough / Technical Deep Dive
The implementation relies on conditional logic injected into the prompt construction pipeline.

1.  **Environment Detection:** When the CLI starts, it checks the standard input/output streams (specifically verifying `isatty`).
2.  **Prompt Assembly:**
    *   **True (Interactive TTY):** The system builds the prompt *without* the block of text that warns against interactive commands (e.g., `nano`, `top`, or confirmation prompts).
    *   **False (CI/Pipe):** The system appends the specific safety instruction: "Avoid interactive commands."
3.  **Token Optimization:** By removing the warning paragraph in interactive sessions, the "Context Window" sent to the Gemini API is smaller. While the text reduction is minor per request, it adds up over thousands of interactions, resulting in lower token consumption and slightly faster Time-To-First-Token (TTFT) processing.
