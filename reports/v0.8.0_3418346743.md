# What’s New: The Gemini CLI Extensions Ecosystem

## 1. Feature Summary
The Gemini CLI is shifting from a standalone tool to an extensible platform. With this release, we are launching a comprehensive **Extensions Catalog**, allowing users to install add-ons built by Google, key launch partners, and the open-source community.

This feature introduces a new command namespace (`gemini extension` or `gemini ext`) that enables dynamic discovery, installation, and management of tools that extend the core capabilities of the Gemini CLI without bloating the main binary.

## 2. Background & Context
**Why was this change made?**
As the Gemini CLI adoption grew, two distinct friction points emerged in the developer feedback loop:
1.  **Feature Bloat:** Users requested integrations with hundreds of third-party services (Jira, Datadog, VS Code, etc.). Adding all these into the core Go/Python binary would make the CLI massive and hard to maintain.
2.  **Workflow Fragmentation:** Developers were writing complex shell scripts to pipe Gemini output into other tools. They wanted a native way to wrap these workflows into reusable commands.

**The Solution:**
By implementing an Extensions architecture, the Core CLI team can focus on prompt optimization and model interaction, while partners and community members can build domain-specific integrations. This change transforms the Gemini CLI into an **orchestrator** that allows the LLM to interact with your local environment and external APIs through modular plugins.

## 3. How-To Guide

Here is how to navigate the new ecosystem.

### Step 1: Discover Extensions
To see what is available in the new catalog (including the partner launch extensions), use the search or list command.

```bash
# List all featured extensions
gemini ext list

# Search for a specific topic (e.g., database tools)
gemini ext search database
```

### Step 2: Install an Extension
Once you find a tool you need (for example, a hypothetic `sql-optimizer` built by a partner), install it locally.

```bash
gemini ext install partner-name/sql-optimizer
```

### Step 3: Run the Extension
Extensions are added as subcommands to the main binary.

```bash
# Use the installed extension
gemini sql-optimizer analyze ./queries.sql
```

### Step 4: Managing Extensions
You can keep your toolkit fresh or remove unused tools easily.

```bash
# Upgrade all extensions
gemini ext upgrade --all

# Remove an extension
gemini ext remove sql-optimizer
```

## 4. Walkthrough / Technical Deep Dive

### How it works under the hood
The Extension system relies on a **federated binary execution model**.

1.  ** The Registry:** When you run `gemini ext search`, the CLI queries a public manifest (likely hosted on a central repository) that maps extension names to their GitHub repositories or artifact URLs.
2.  **Installation:** When you run `gemini ext install <repo>`, the CLI clones the repository or downloads the pre-compiled binary releases associated with that extension. It places them in a dedicated `~/.gemini/extensions` directory.
3.  **Execution (The "Shim"):** When you type `gemini my-extension`, the core CLI checks its manifest. If it finds `my-extension`, it acts as a proxy. It passes:
    *   `STDIN` (allowing you to pipe Gemini outputs into extensions).
    *   `STDOUT` (allowing the extension to return data to the user).
    *   **Context:** Crucially, the CLI can pass environment variables or auth tokens (if permitted) so the extension can utilize the authenticated Gemini session.

### Developer Experience (DX)
For developers creating extensions, the barrier to entry is low. An extension is essentially just an executable (written in Go, Python, Rust, or Bash) named `gemini-<name>`. This follows the standard Unix philosophy, allowing partners to build complex logic in their language of choice while the Gemini CLI handles the user interface and model connection.
