# 🚀 What’s New: Flutter Development with Gemini CLI (Preview)

## 1. Feature Summary
We are thrilled to announce the release of the **Gemini CLI Flutter Extension**. This is an **early preview** module designed to integrate the power of Gemini’s generative AI directly into the Flutter development lifecycle.

Developers can now **create, build, test, and run** Flutter applications without leaving the Gemini CLI environment. By bridging the gap between natural language prompts and the `flutter` toolchain, this extension aims to reduce context switching and accelerate mobile cross-platform development.

## 2. Background & Context
**Why this change?**
Based on recent community feedback and Issue discussions, developers often find themselves toggling between three contexts:
1.  The IDE/Terminal for execution.
2.  The Browser/Chat interface for AI assistance (generating widgets or debugging).
3.  Documentation for specific Flutter CLI flags.

**The Problem Solved:**
Previously, if a user wanted to scaffold a new app with specific requirements, they had to manually run `flutter create`, then copy-paste code generated by Gemini into the project.

With this PR, we are introducing a wrapper layer that allows the Gemini CLI to:
*   Understand Flutter-specific intents.
*   Execute standard `flutter` commands programmatically.
*   Inject AI-generated scaffolding logic directly into the file system during the `create` phase.

> **Note:** This is an "early version," meaning the focus is currently on core lifecycle management (Create/Build/Test/Run) rather than complex, file-specific refactoring, which is slated for future updates.

## 3. How-To Guide

### Prerequisites
*   **Gemini CLI**: Ensure you are on the latest version (`v1.x.x`).
*   **Flutter SDK**: Must be installed and available in your system `PATH`.

### Step 1: Install the Extension
First, enable the Flutter capability within the Gemini CLI.

```bash
gemini extension install flutter
```

### Step 2: Create a New App (AI-Assisted)
Instead of a standard template, you can now provide context to the creation command.

```bash
# Standard creation
gemini flutter create my_new_app

# (Future/Experimental) Creation with context
gemini flutter create my_app --desc "A simple todo list with a dark theme"
```

### Step 3: Run and Test
You can manage the application lifecycle directly through the CLI wrapper.

```bash
# Run the app (wraps 'flutter run')
gemini flutter run

# Run tests (wraps 'flutter test' with AI analysis on failure)
gemini flutter test
```

## 4. Walkthrough / Technical Deep Dive

Under the hood, this extension operates as an intelligent orchestration layer on top of the standard Dart/Flutter toolchain.

### The Architecture
1.  **Command Parsing**: When you run `gemini flutter <command>`, the CLI intercepts the request via the new Extension Interface introduced in the previous release.
2.  **Context Injection**: If the command implies code generation (like `create`), the CLI packages the user's prompt along with Flutter 3.x best practices system prompts before sending it to the Gemini API.
3.  **Shell Execution**:
    *   For operational commands (`run`, `build`), the CLI utilizes a `subprocess` wrapper.
    *   It streams `stdout` and `stderr` from the Flutter binary back to the user.
    *   *Crucially*, if `stderr` detects a build error, the Gemini CLI captures the stack trace and automatically queries the LLM for a potential fix, offering a "Auto-Fix?" prompt to the user (configurable via flags).

### Code Snippet (Conceptual Implementation)
Based on the PR logic, the wrapper looks roughly like this:

```typescript
// Conceptual logic handling the 'test' command
async function handleFlutterTest() {
  const result = await sys.exec('flutter test --machine');
  
  if (result.exitCode !== 0) {
    // New Feature: AI Analysis on failure
    const analysis = await gemini.analyzeError(result.stderr);
    console.log("Test Failed. Gemini Suggestion:", analysis);
  } else {
    console.log("All tests passed!");
  }
}
```
