# 🚀 Gemini CLI Release Notes: Programmatic Power with JSON Output

**Version:** [Latest Release]
**Contributor:** @jerop
**Pull Request:** [#8119](https://github.com/google-gemini/gemini-cli/pull/8119)

## 1. Feature Summary
The Gemini CLI now supports a dedicated **JSON Output Mode**. By adding the `--output-format json` flag to your commands, developers can now receive response data, usage statistics, and error messages in a structured, machine-readable format. This feature is designed specifically for "headless" environments, enabling seamless integration with automation scripts, CI/CD pipelines, and data post-processing tools.

## 2. Background & Context
**The Problem:**
Until now, the Gemini CLI was optimized primarily for human interaction. It outputted formatted Markdown, utilized interactive spinners, and often mixed standard output (stdout) with status messages. While excellent for interactive use, this posed significant challenges for developers trying to build on top of the CLI.
*   **Parsing fragility:** Scrapers and scripts relying on regex to extract answers would break if the CLI interface changed slightly (e.g., Issue #8022).
*   **Missing Metadata:** Users often wanted programmatic access to token counts and latency statistics, which were previously displayed only visually or logged to debug files.

**The Solution:**
Addressed in PR #8119 by @jerop, this update introduces a strict schema for output. By decoupling the data from the presentation layer, the CLI becomes a viable engine for complex automation workflows. This aligns with standard CLI design patterns (like `kubectl` or `aws-cli`) where JSON output is a requirement for advanced orchestration.

## 3. How-To Guide

### Basic Usage
To get a structured response, simply append `--output-format json` to your standard prompt command.

**Command:**
```bash
gemini prompt "Explain recursion in one sentence" --output-format json
```

**Output:**
```json
{
  "content": "Recursion is a process where a function calls itself as a subroutine to solve a problem by breaking it down into smaller, self-similar sub-problems.",
  "stats": {
    "duration_ms": 450,
    "input_tokens": 6,
    "output_tokens": 28
  },
  "status": "success"
}
```

### Advanced Scenario: Piping to `jq`
The real power of this feature is unlocked when combining the Gemini CLI with tools like `jq` to extract specific data points immediately.

**Extracting only the answer text:**
```bash
gemini prompt "Suggest a git commit message for a bug fix" --output-format json | jq -r '.content'
```

**Filtering based on Token Usage:**
You can now write scripts that monitor your API usage in real-time.
```bash
# Example: Warn if output tokens exceed 100
gemini prompt "Write a poem" --output-format json | \
jq 'if .stats.output_tokens > 100 then "WARNING: High Usage" else "OK" end'
```

## 4. Walkthrough / Technical Deep Dive
Based on the file changes in `bundle/gemini.js` (PR #8119), here is how the JSON mode functions under the hood:

1.  **Flag Detection & TTY Bypass:**
    When the CLI initializes, it checks for `--output-format json`. If detected, the CLI suppresses standard interactive elements. This means strictly no loading spinners, no Markdown syntax highlighting codes (ANSI colors), and no "welcome" banners that usually pollute `stdout`.

2.  **Structured Object Construction:**
    Instead of streaming text chunks directly to the console, the CLI aggregates the response. It constructs a payload object containing:
    *   **Response Body:** The raw text from the model.
    *   **Metadata:** It hooks into the API response headers to capture `usageMetadata` (token counts) and timing metrics.
    *   **Error Handling:** If the API call fails, instead of throwing a generic Node.js error trace to the console, it catches the exception and outputs a JSON object with `"status": "error"` and a `"message"` field. This prevents breaking JSON parsers in downstream tools.

3.  **Serialization:**
    Finally, the object is passed through `JSON.stringify()` and printed to `stdout`, while debug logs or non-critical warnings are likely routed to `stderr` to ensure the JSON remains valid and parsable.

## 5. Next Steps for Demos
As a Developer Advocate, here are three compelling demos you should create to showcase this feature:

1.  **The "Chain Reaction" Script:**
    *   *Concept:* Write a bash/python script that takes the JSON output of one Gemini prompt (e.g., "Generate a funny cat name") and feeds it immediately into a second prompt (e.g., "Write a haiku about [Cat Name]").
    *   *Why:* Proves the reliability of the parsing capabilities.

2.  **The "CI/CD Code Reviewer":**
    *   *Concept:* Use the CLI in a GitHub Action. Have it read a changed file, ask Gemini to review it, output the review as JSON, and use `jq` to post the review text back as a GitHub comment.
    *   *Why:* Demonstrates a real-world enterprise use case for headless CLI usage.

3.  **The "Cost Calculator":**
    *   *Concept:* Run a loop of 10 prompts. Parse the JSON `stats` field for input/output tokens, sum them up using a script, and calculate the estimated API cost.
    *   *Why:* Highlights the visibility into `stats` that was previously difficult to access.
