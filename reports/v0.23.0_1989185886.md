# 🚀 What's New: Experimental Agent Skills in Gemini CLI

**Date:** October 26, 2023
**Version:** `@google/gemini-cli@preview`
**Status:** Experimental / Public Preview

---

## 1. Feature Summary
The Gemini CLI has evolved from a text-generation tool into an action-oriented agent. With the introduction of **Agent Skills**, the CLI can now interface directly with your local environment, external APIs, and system tools.

Instead of just telling you how to perform a task, Gemini can now perform the task for you—whether that’s reading files, executing shell commands, or fetching data from the web—provided you have defined and enabled the necessary capabilities.

## 2. Background & Context
**The Problem:**
Previously, using the Gemini CLI was a strictly text-based experience. If you asked Gemini to "refactor `app.js`," it would output the refactored code block, requiring you to manually copy, paste, and save the file. Users consistently provided feedback that context-switching between the CLI output and their editor broke their flow.

**The Solution:**
Agent Skills bridge the gap between the Large Language Model (LLM) reasoning and local execution.
*   **Grounded in Function Calling:** This feature leverages the native Function Calling capabilities of the Gemini 1.5 Pro/Flash models.
*   **Extensibility:** By moving to a "Skills" architecture, we allow the community to build plugins. You aren't limited to what hard-coded features we ship; you can define a skill for your specific workflow.
*   **Human-in-the-Loop:** As discussed in early design issues, safety is paramount. The "Preview" nature of this release emphasizes that users must opt-in via settings, and the CLI maintains a permission layer before executing sensitive skills.

## 3. How-To Guide

### Step 1: Install the Preview Build
This feature is currently behind the preview tag. Update your CLI:

```bash
npm install -g @google/gemini-cli@preview
```

### Step 2: Enable Skills
For safety, skills are disabled by default. You can enable them via the interactive settings menu or directly via the config command:

```bash
gemini settings set features.skills.enabled true
```

### Step 3: Define a Skill (Example)
Skills are defined in a `~/.gemini/skills` directory (or your project's local configuration). Here is an example of a simple **"File Reader"** skill definition in JSON/JS:

```javascript
// ~/.gemini/skills/readFile.js
export const definition = {
  name: "readFile",
  description: "Reads the contents of a specific file on the user's system",
  parameters: {
    type: "object",
    properties: {
      path: { type: "string", description: "The relative path to the file" }
    },
    required: ["path"]
  }
};

export const handler = async ({ path }) => {
  const fs = await import('fs/promises');
  return await fs.readFile(path, 'utf-8');
};
```

### Step 4: Use the Skill
Once registered, you simply prompt Gemini naturally.

**User Input:**
> "Analyze the contents of package.json and tell me the version number."

**Gemini Response:**
> *Gemini detects the intent, executes `readFile`, and responds:*
> "I've checked `package.json`. The current version is **1.2.0**."

## 4. Walkthrough / Technical Deep Dive

How does the CLI turn natural language into JavaScript execution? Here is the lifecycle of a Skill request:

1.  **Schema Injection:** When the CLI initializes a chat session, it scans your `skills/` directory. It converts your skill definitions into valid JSON Schemas compatible with the Gemini API `tools` parameter.
2.  **Intent Recognition:** The user's prompt ("Check the logs") is sent to Gemini along with these schemas. The model determines if the prompt requires a tool.
3.  **The Stop Sequence:** Instead of generating text, the model generates a structured **Function Call request** (e.g., `call: readFile { path: "./logs.txt" }`) and pauses generation.
4.  **Local Execution (The Shim):**
    *   The CLI intercepts this request.
    *   It validates the arguments against your schema.
    *   It executes the local `handler` function (running in the Node.js context of the CLI).
5.  **Round Trip:** The output of the function (the contents of the log file) is sent back to Gemini as a "Function Response."
6.  **Final Synthesis:** Gemini reads the function response and generates the final natural language answer for the user.

**Note on Security:** In this preview build, all skills run with the same permissions as the user running the CLI. We are actively working on a sandboxing proposal for future releases.
