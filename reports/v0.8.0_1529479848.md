# 🚀 What's New in Gemini CLI: Extension Management

**Version Update:** Extension Control Support (`enable` | `disable`)

## 1. Feature Summary
The Gemini CLI now introduces granular control over AI extensions. With the new `gemini extensions enable` and `gemini extensions disable` commands, developers can now toggle specific capabilities (such as Google Workspace, Code Execution, or third-party data retrievers) on or off directly from the terminal.

This update moves the CLI from a static configuration to a dynamic environment, allowing users to tailor the context of their session without modifying global configuration files manually.

## 2. Background & Context
**The Problem:**
Previously, managing which tools and extensions the Gemini model could access was often a binary choice or required verbose configuration flags for every single prompt.
*   **Latency & Tokens:** having all extensions active by default increases the prompt size (token usage) and latency, as the model evaluates which tool to call.
*   **Privacy & Scope:** Users expressed a need to ensure the CLI *cannot* access personal data (like Drive or Gmail) when performing unrelated tasks (like code generation), without needing to completely unauthenticate.

**The Solution:**
This change introduces persistent state management for extensions. By implementing explicit `enable` and `disable` verbs, we allow the developer to curate their environment. This aligns the CLI with the web-based Gemini experience, where extensions can be toggled based on the user's intent.

## 3. How-To Guide

Here is how to manage your extension ecosystem effectively using the new commands.

### Viewing Current Status
Before toggling, it helps to know what is available. (Assuming `list` functionality exists alongside these changes):
```bash
gemini extensions list
```

### Enabling an Extension
To give Gemini access to a specific tool, use the `enable` command followed by the extension ID.

**Example: Enabling Google Workspace**
```bash
gemini extensions enable workspace
# Output: Extension 'workspace' enabled. Gemini can now access Docs, Drive, and Gmail.
```

Now, you can ask: *"Summarize the last email from my project manager."*

### Disabling an Extension
To restrict access or speed up simple text generation, disable specific tools.

**Example: Disabling Code Execution**
```bash
gemini extensions disable code_execution
# Output: Extension 'code_execution' disabled.
```

Now, the model will rely purely on its internal knowledge base rather than attempting to run Python code.

## 4. Walkthrough / Technical Deep Dive

How does this work under the hood?

1.  **Local Configuration Store:**
    When you run `gemini extensions enable <id>`, the CLI updates a local configuration file (typically located in `~/.gemini/config.yaml` or a local `.env` state). It toggles a boolean flag associated with that specific extension ID.

2.  **Request Construction:**
    When a prompt is sent to the Gemini API (`gemini prompt "..."`), the CLI middleware reads the current configuration state.
    *   **If Enabled:** The CLI appends the specific `tools` definition (schema) to the API request payload. This tells the Gemini model, "Here are the functions you are allowed to call."
    *   **If Disabled:** The schema is omitted from the API request entirely.

3.  **Token Optimization:**
    By disabling unused extensions, you are effectively reducing the "system instruction" overhead sent to the model. This results in:
    *   **Faster Time-to-First-Token (TTFT):** The model has less context to parse.
    *   **Reduced Hallucination:** Prevents the model from trying to invoke a tool when it shouldn't.
