# 🚀 What's New: Agent2Agent (A2A) Development Tools Extension (RFC)

**Release Date:** *[Insert Date]*
**PR Reference:** #7817
**Author:** @skeshive

## 1. Feature Summary
We are excited to announce the introduction of an **Agent2Agent (A2A) Development Tool Extension** framework. This release introduces a Request for Comments (RFC) implementation directly into the CLI, accompanied by the initial scaffolding for A2A capabilities.

In short, this feature lays the groundwork for Gemini to not just chat with you, but to **act** on your behalf by communicating with other agents or executing developer tools directly. It bridges the gap between generating code and executing development workflows.

## 2. Background & Context
### The Problem
Until now, the Gemini CLI has primarily functioned as a sophisticated conversationalist and code generator. Developers often face a "context gap":
1.  Ask Gemini for a solution.
2.  Copy the code.
3.  Switch to the terminal.
4.  Run tools (git, linters, compilers).
5.  Paste errors back into Gemini.

### The Solution
The **A2A (Agent2Agent)** approach changes this paradigm. By implementing this extension, we are enabling an architecture where the Gemini CLI can act as an orchestrator. It can delegate tasks to specific "tool agents" (e.g., a "Git Agent" or a "Linter Agent").

**Why PR #7817?**
This specific Pull Request (+10.7 kB to the bundle) introduces the structural definitions and the RFC document for this architecture. It is an invitation for the community to test the logic of tool delegation and provide feedback on the security and usability of letting an AI agent drive development tools.

## 4. Walkthrough / Technical Deep Dive
### The Architecture
The PR adds approximately **10.7 kB** to `gemini.js`. This lightweight addition suggests the inclusion of an **Interface Definition** and **Orchestration Logic**, rather than a heavy full-stack agent.

1.  **The Orchestrator:** The updated `gemini.js` now contains logic to parse "Tool Use" requests. When the LLM decides it needs to perform an action, this logic intercepts the token stream and routes it to the A2A extension.
2.  **Protocol:** The "Agent2Agent" naming implies a structured protocol (likely JSON-RPC or similar) where the Main Agent sends a payload to a Sub-Agent (the Dev Tool) and awaits a structured response.
3.  **Sandboxing (Crucial Security):**
    The GitHub context highlights the presence of macOS sandbox profiles (`sandbox-macos-permissive-*.sb`).
    *   Although these files are marked "Unchanged" in this specific diff, their existence is critical to A2A.
    *   **How it works:** When the A2A extension executes a command (like `npm install` or `git commit`), it likely spawns that process inside these pre-defined sandbox profiles to prevent the AI from accidentally (or maliciously) accessing sensitive parts of your OS (like `~/.ssh` or system settings).
