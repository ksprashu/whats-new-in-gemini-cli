# 🚀 What's New: Interactive Authentication & Secure Key Storage

**Release:** Gemini CLI Update  
**Contributor:** @galz10  
**PR:** [#11760](https://github.com/google-gemini/gemini-cli/pull/11760)

---

## 1. Feature Summary
The Gemini CLI has significantly upgraded its onboarding experience. We have introduced a **native, interactive authentication dialog** (`ApiAuthDialog`) that allows users to input their Gemini API key directly within the terminal UI.

More importantly, the CLI now includes **secure credential storage**. Once you enter your key, it is saved to your system's keychain/credential manager. You no longer need to manually set environment variables or re-enter your key for every session.

## 2. Background & Context
**The Problem:**
Previously, the Gemini CLI relied heavily on environment variables (e.g., `GEMINI_API_KEY`) for authentication. While standard for CI/CD environments, this created friction for local development and new users:
*   **High Friction:** Users had to leave the CLI, edit their shell profile (`.bashrc`/`.zshrc`), and reload their shell before running their first command.
*   **Repetition:** Without permanent environment variables, users were forced to paste their key repeatedly.
*   **Security Concerns:** Storing keys in plaintext shell history or config files is less secure than utilizing system-level encryption.

**The Solution:**
Addressed in **PR #11760** (and tracking issues #11312, #11313), this update shifts the burden of key management from the user to the CLI. By implementing a dedicated `ApiKeyCredentialStorage` service, the CLI now behaves like modern developer tools (e.g., `gcloud` or `gh`), treating authentication as a persistent state rather than a per-command configuration.

## 3. How-To Guide

Here is how the new flow works for a user setting up the CLI for the first time or on a new machine.

### Step 1: Run a Command
Simply try to use the CLI. If you haven't authenticated yet, the CLI will now pause and prompt you.

```bash
gemini chat
```

### Step 2: Interactive Input
Instead of an error message regarding missing variables, you will see the new dialog:

```text
? Please enter your Gemini API Key: [Hidden Input]
```
*(Note: You can paste your key here. The input is masked for security.)*

### Step 3: Persistence
Once you press **Enter**:
1. The CLI validates the input.
2. The key is securely stored in your OS Keychain (macOS Keychain, Windows Credential Manager, or Linux Secret Service).
3. The command `gemini chat` proceeds immediately.

### Step 4: Subsequent Runs
Close your terminal and open a new one. Run a command again:
```bash
gemini chat "Hello, world!"
```
**Result:** It runs instantly. No prompts, no exports needed.

## 4. Technical Deep Dive / Walkthrough

This update involved a significant refactor of the authentication architecture within the CLI.

### 🔐 ApiKeyCredentialStorage
The core of this update is the implementation of `ApiKeyCredentialStorage`. This module interfaces with the operating system's native credential management APIs. This ensures that the API key is encrypted at rest, adhering to security best practices.

### ⚛️ Component Refactoring
*   **`ApiAuthDialog`**: A new UI component was created specifically to handle the "Empty State." It detects if the storage is empty and interrupts the flow to request credentials.
*   **`TextInput`**: The underlying text input component was refactored into a **fully controlled component**. This improves the reliability of the UI rendering and makes the component reusable for other parts of the CLI that might require user input in the future.

### 🪝 The `useAuth` Hook
The authentication logic was centralized into a refactored `useAuth` React hook.
1.  **Initialization**: On startup, the hook attempts to load the key from `ApiKeyCredentialStorage`.
2.  **Fallback**: If the storage is empty, it checks for the legacy Environment Variable.
3.  **Prompt**: If both are missing, it triggers the `ApiAuthDialog`.
4.  **Reload**: A new `reloadApiKey` function allows the app to refresh the authentication state dynamically without restarting the process after the user inputs their key.
