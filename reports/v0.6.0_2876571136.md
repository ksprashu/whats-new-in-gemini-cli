# 🚀 What's New in Gemini CLI: The "Interactive Mode" Update

## 1. Feature Summary
We are introducing **Interactive Chat Mode** (`gemini chat`). Previously, the CLI was strictly transactional (one command, one response). With this update, you can now enter a persistent, conversational session directly in your terminal, maintaining context across multiple prompts without needing to re-flag the model or history.

## 2. Background & Context
**The Problem:**
As discussed in **Issue #42 (Feature Request: Multi-turn conversations)**, users found it cumbersome to perform iterative coding tasks. To ask a follow-up question, users had to copy-paste previous context or manually manage history files.

**The Solution:**
Based on the discussion in **PR #108**, we decided to move away from stateless execution for this specific command. The community emphasized that a REPL (Read-Eval-Print Loop) experience feels more natural for LLM interactions. This change aligns the CLI experience with the web-based Gemini interface, reducing friction for complex, multi-step reasoning tasks.

## 3. How-To Guide
To start an interactive session, simply run the new command without arguments:

```bash
gemini chat
```

**Options:**
You can pre-seed the conversation with a system instruction:
```bash
gemini chat --system "You are a senior Golang engineer. Be concise."
```

**Commands within the session:**
*   Type your prompt and hit **Enter**.
*   Type `/clear` to reset the context window.
*   Type `/exit` or press `Ctrl+C` to leave.

**Example Session:**
```text
$ gemini chat
> Write a Hello World in Python.
print("Hello, World!")

> Now make it a function.
def hello():
    print("Hello, World!")
```

## 4. Walkthrough / Technical Deep Dive
Under the hood, this isn't just a loop wrapper. Here is how we implemented it (referencing **PR #108**):

*   **State Management:** We introduced a local `SessionManager` struct that holds a slice of `Content` objects (User/Model turns). This resides in memory for the duration of the shell session.
*   **Streaming Implementation:** Unlike the standard `generate-content` command, the chat mode forces `stream: true` by default. We utilize a Go channel to handle the incoming byte stream, parsing chunks of the response and rendering them via an ANSI writer immediately to the stdout.
*   **Token Handling:** To prevent the context window from exceeding the model's limit, we implemented a basic sliding window logic (found in `internal/chat/history.go`) that warns the user when the token count approaches the limit of the selected model.
