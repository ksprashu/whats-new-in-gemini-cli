## 1. Feature Summary
**New Feature: Interactive Chat Mode (`gemini chat`)**

This release introduces a stateful **Interactive Chat Mode**. Previously, the CLI was limited to "one-shot" generation—you sent a prompt, got a result, and the context ended there. With the new `gemini chat` command, you can now enter a continuous conversational loop, allowing Gemini to remember previous turns of the conversation, refine code snippets, and maintain context, just like the web interface.

---

## 2. Background & Context
**Why was this change made?**

*   **The Problem:** Users reported in **Issue #128 ("Lack of conversation history")** that debugging code via the CLI was frustrating. If Gemini generated a function with a bug, the user had to copy-paste the entire previous context into a new prompt to ask for a fix.
*   **The Discussion:** In **PR #145**, the community emphasized that a CLI tool needs to support iterative workflows. One-off prompts are great for quick questions, but poor for complex problem-solving.
*   **The Solution:** We implemented a Read-Eval-Print Loop (REPL) that manages a localized history array in memory. This reduces token overhead for the user (you don't have to manually re-paste context) and creates a more seamless developer experience.

## 3. How-To Guide

### Starting a Chat Session
To enter the new interactive mode, simply run:

```bash
gemini chat
```

### Example Workflow
Once inside the shell, you can iterate on a problem.

**User:**
```text
> Write a Python function to calculate Fibonacci numbers efficiently.
```

**Gemini:**
```python
def fib(n):
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

**User (Refining the request):**
```text
> Can you add type hints to that?
```

**Gemini:**
```python
def fib(n: int) -> int:
    a, b = 0, 1
    for _ in range(n):
        a, b = b, a + b
    return a
```

### Exiting
To exit the chat loop and clear the history buffer:
*   Type `exit` or `quit`
*   Press `Ctrl+C`

## 4. Walkthrough / Technical Deep Dive

For the developers interested in how we built this, the implementation in **PR #145** utilizes the Node.js `readline` module to handle standard input streams.

**How Context Management Works:**
1.  **In-Memory Store:** When `gemini chat` initializes, we create a local `history` array.
2.  **The Loop:**
    *   **Input:** We capture `process.stdin`.
    *   **Payload Construction:** Instead of sending a single string, the CLI now constructs the full `messages` array (User + Model turns) required by the Gemini API `chatSession` endpoint.
    *   **Streaming:** The response is piped to `process.stdout` using a stream decoder to ensure characters appear instantly as they are generated, rather than waiting for the full buffer.
3.  **Token Limits:** Currently, the history is limited to the session duration. If the context window is exceeded, the CLI handles the `400` error by suggesting the user start a new session (Automatic rolling context windows are planned for the next preview).
