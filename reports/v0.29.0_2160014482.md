# 🚀 What’s New: Introducing Plan Mode for Gemini CLI

**Contributors:** @Adib234, @jerop

We are excited to unveil **Plan Mode**, a significant architectural enhancement to the Gemini CLI. This feature introduces a dedicated "thinking phase" to the agent's workflow, allowing it to research, architect, and design solutions in a safe, read-only environment before writing a single line of code.

---

## 1. Feature Summary

**Plan Mode** is a new comprehensive capability that separates the "planning" phase from the "execution" phase of software development within the CLI.

Key components of this release include:
*   **The `/plan` Command:** A user-facing slash command to manually enter Plan Mode and instantly review the most recent plan generated by the agent.
*   **The `enter_plan_mode` Tool:** A tool that allows the Gemini Agent to autonomously recognize when a task is complex and request to switch into Plan Mode.
*   **Read-Only Safety:** When in Plan Mode, the agent is restricted to read-only operations, preventing accidental file modifications during the research phase.

---

## 2. Background & Context

### The Problem
In complex coding tasks (e.g., large-scale refactoring or implementing new architectural patterns), AI agents often attempt to "fix it live." They might start modifying files immediately without fully understanding the repository structure. This can lead to:
*   Premature code changes that need to be reverted.
*   "Hallucinated" dependencies or file paths.
*   A lack of transparency regarding the agent's intended strategy.

### The Solution
Grounded in **PR #18324** and **PR #17698**, Plan Mode solves this by enforcing structured problem-solving.
*   **Safer Research:** As noted in PR #18324, this mode limits the agent to read-only tools. It can `read_file`, `search`, and `list_files`, but it cannot `edit_file` or run destructive shell commands.
*   **Human-in-the-Loop:** The transition to Plan Mode often requires user confirmation, and the generated plan serves as a contract between the user and the agent before execution begins.

## 3. How-To Guide

*Note: As this is an experimental feature, you must enable it in your configuration first.*

### Step 1: Enable Plan Mode
Add the following feature flag to your `.gemini/config.ts` (or equivalent configuration file):

```typescript
export default {
  experimental: {
    plan: true, // Enable Plan Mode
  },
  // ... other config
};
```

### Step 2: Using the Agent (Autonomous Mode)
When you assign a complex task, the Agent may now decide to enter Plan Mode.

**User:** "Refactor the authentication logic to use the new OAuth provider. Do not write code yet, just plan."

**Gemini:** *Determines the task is complex.*
> "I would like to enter Plan Mode to research the current authentication implementation."
> **[Confirmation Required]** Allow agent to enter Plan Mode? (y/n)

**User:** `y`

**Gemini:** *Enters read-only state, reads files, and generates a plan.*

### Step 3: Using the `/plan` Command
If you want to review the plan the agent just created, or if you want to force the CLI into this mode manually:

**User:**
```bash
/plan
```

**System Output:**
*   Switches internal state to `ApprovalMode.PLAN`.
*   Locates the most recent plan (markdown file) in the temporary directory.
*   Renders the markdown plan directly in your terminal for review.

## 4. Walkthrough / Technical Deep Dive

### Under the Hood: `enter_plan_mode` Tool
Introduced in **PR #18324**, this is the mechanism that restricts agent behavior.
1.  **Tool Registration:** The `EnterPlanModeTool` is registered only when `experimental.plan` is enabled.
2.  **State Management:** When executed, the tool changes the global state to `ApprovalMode.PLAN`.
3.  **Permissions:** The CLI checks this state before every tool execution. If `ApprovalMode.PLAN` is active, any tool classified as "write" or "execute" (like writing files) is blocked.
4.  **Confirmation:** The tool includes a `shouldConfirmExecute` method. It returns `ASK_USER`, triggering the CLI to pause and ask the human for permission before the mode switch occurs.

### Under the Hood: The `/plan` Command
Introduced in **PR #17698**, this handles the UI and retrieval aspects.
1.  **Plan Discovery:** The command logic scans a specific temporary directory where the agent stores its thought process/plans.
2.  **Error Handling:**
    *   If the experimental flag is off: Returns an informative error guiding the user to update their config.
    *   If no plan exists: Returns "No plan found," handling edge cases where the directory might be empty or missing.
3.  **Rendering:** It reads the markdown content of the latest plan file and prints it to `stdout`, allowing for a quick sanity check of the agent's strategy.
