# 🚀 What’s New in Gemini CLI: Simplified Extension Management

**Date:** October 26, 2023
**Feature:** Single-command Extension Installation
**Command:** `gemini extensions install`

---

## 1. Feature Summary

We are excited to introduce a major quality-of-life improvement for the Gemini CLI ecosystem. With the new **`gemini extensions install`** command, developers and users can now install extensions directly from a GitHub repository or a local directory with a single line of code.

This update removes the friction of manual installation, making it easier than ever to share, discover, and integrate community-built tools into your Gemini workflow.

---

## 2. Background & Context

### The Problem
Prior to this release, installing a community extension was a multi-step, manual process. Users had to:
1.  Manually `git clone` a repository.
2.  Move the folder to a hidden system directory (e.g., `~/.gemini/extensions`).
3.  Manually run dependency installation scripts (like `npm install` or `pip install`).
4.  Edit a configuration file to register the new extension.

This high barrier to entry discouraged users from trying new extensions and made it difficult for extension developers to distribute their work.

### The Solution
Grounded in recent community feedback and PR discussions, the goal was to achieve parity with modern CLI tools (like the GitHub CLI or VS Code). The `extensions install` command automates the entire lifecycle: fetching source code, resolving dependencies, and registering the plugin in the CLI's manifest.

This change transforms the extension ecosystem from a "power-user only" feature into a plug-and-play experience for everyone.

---

## 3. How-To Guide

Here is how you can use the new command to expand your CLI's capabilities.

### Scenario A: Installing from GitHub
This is the primary use case for users adding community tools. You no longer need to clone repos manually.

**Syntax:**
```bash
gemini extensions install <github-url>
```

**Example:**
To install a "SQL Helper" extension hosted on GitHub:
```bash
gemini extensions install https://github.com/community-user/gemini-sql-helper
```

### Scenario B: Installing from a Local Folder
This is ideal for **extension developers**. You can build an extension in your workspace and "install" it to test how it behaves in the actual CLI environment.

**Syntax:**
```bash
gemini extensions install <path-to-folder>
```

**Example:**
```bash
gemini extensions install ./my-new-weather-extension
```

## 4. Walkthrough / Technical Deep Dive

When you run `gemini extensions install`, the CLI performs a series of orchestrated operations under the hood to ensure the extension is safe and ready to run.

### Step 1: Source Validation
The CLI first detects if the argument is a URL or a file path.
*   **If URL:** It verifies the URL format and ensures `git` is available in the user's environment.
*   **If Path:** It checks if the directory exists and validates that a `manifest.json` (or equivalent config file) is present in the root of that target folder.

### Step 2: Fetching Strategy
*   **Remote:** The CLI performs a shallow git clone (`git clone --depth 1`) into the user's global extensions directory (typically `~/.gemini/extensions/<repo-name>`). This ensures the download is fast and doesn't pull unnecessary git history.
*   **Local:** It copies the files to the extensions directory. *Note: For developers, we are investigating a `--link` flag for future releases to use symlinks instead of copying.*

### Step 3: Dependency Resolution
Once the files are in place, the CLI inspects the extension folder.
*   If it sees a `package.json`, it triggers `npm install --production`.
*   If it sees a `requirements.txt`, it triggers `pip install`.
This ensures the extension has everything it needs to run immediately.

### Step 4: Registry Update
Finally, the CLI updates its internal registry map to recognize the new commands provided by the extension, making them available immediately without requiring a restart of the shell session.
