# 🚀 What's New: Model Visibility in Chat History

**Release Date:** *[Insert Date]*
**Contributor:** @scidomino
**PR Reference:** #13034

## 1. Feature Summary
A new configuration option has been added to the Gemini CLI that enhances the transparency of your past interactions. Users can now navigate to `/settings` and toggle a specific option to **display the model name** (e.g., *Gemini 1.5 Pro*, *Gemini 1.5 Flash*) alongside messages in their chat history.

This small but impactful UI change ensures that you always know which model intelligence was responsible for a specific code snippet, creative draft, or answer in your logs.

## 2. Background & Context
**The Problem:**
As the Gemini ecosystem expands, users frequently switch between different models depending on the task at hand—using *Flash* for speed and low latency, and *Pro* or *Ultra* for complex reasoning.

However, prior to this change (referenced in Issue #1064), the chat history was agnostic to these switches. Reviewing a past conversation provided the text, but lacked the context of *which* engine generated it. This made it difficult for developers to:
*   Benchmark previous results.
*   Remember which model successfully solved a specific bug.
*   Debug why a previous answer might have been hallucinated or suboptimal.

**The Solution:**
Contributor **@scidomino** addressed this by implementing a toggle in the settings menu. This allows users who prefer a clean interface to keep it hidden, while power users can enable metadata visibility to see exactly which model version was active during past turns of conversation.

## 3. How-To Guide

Here is how you can enable and use this feature:

### Step 1: Update your CLI
Ensure you are running the latest version of the Gemini CLI to access the changes merged in PR #13034.

### Step 2: Access Settings
Launch the CLI and enter the settings menu command:
```bash
/settings
```

### Step 3: Toggle the Feature
1.  Navigate through the menu using your arrow keys.
2.  Locate the option labeled **"Display model in chat history"** (or similar).
3.  Press **Enter** or toggle the value to `TRUE` / `ON`.
4.  Exit the settings menu.

### Step 4: Verify in History
Run the history command or scroll up in your current session:
```bash
/history
```
**Result:** You will now see tags (e.g., `[gemini-1.5-pro]`) adjacent to the AI's responses.

## 4. Walkthrough / Technical Deep Dive

**Under the Hood:**
The implementation involves a logic update within the core bundle (`./bundle/gemini.js`).

1.  **Metadata Persistence:** The CLI was likely already receiving metadata regarding the model version during the API handshake, but it was being discarded or hidden by the rendering layer after the session was active.
2.  **State Management:** A new boolean flag was added to the user configuration state to track the preference for `show_model_in_history`.
3.  **Conditional Rendering:**
    *   The render function for the history list was updated.
    *   It now checks the configuration flag.
    *   If true, it injects a string formatter (likely a bracketed tag or colored label) containing the `model_id` associated with that specific message object.
    *   This adds a negligible size increase to the bundle (+1.66 kB), indicating an efficient implementation that reuses existing UI components rather than importing heavy new dependencies.
