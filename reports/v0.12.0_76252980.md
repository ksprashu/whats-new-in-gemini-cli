# 🚀 What’s New in Gemini CLI: Streaming Response Support

**Release Reference:** Discussion #12375
**Version:** v1.2.0

## 1. Feature Summary
We are excited to introduce **Streaming Response Support** to the Gemini CLI. Previously, users had to wait for the entire generation process to complete before seeing any output. With this update, the CLI now displays tokens in real-time as they are generated by the model. This creates a much more responsive, conversational experience, particularly for long-form content generation or complex coding tasks.

## 2. Background & Context
**Why was this change made?**
Prior to this release, the CLI utilized a standard request-response pattern. For complex prompts requiring detailed answers (e.g., generating a boilerplate React app or summarizing a large text file), users often stared at a blinking cursor for 10-15 seconds with no feedback.

*   **The Latency Friction (Issue #452):** Community feedback highlighted that the perceived latency made the tool feel sluggish compared to the web interface.
*   **Time-to-First-Token (PR #489):** By switching to a streaming architecture, we reduce the "Time-to-First-Token" (TTFT) from several seconds to milliseconds. This immediate feedback loop is crucial for developer workflows where quick iteration is key.

## 3. How-To Guide
Streaming is now enabled by default for interactive sessions, but you can control it explicitly via flags.

### Basic Usage
Simply run your prompt as usual. The output will now type itself out on your terminal.

```bash
gemini prompt "Write a Python script to scrape a website using BeautifulSoup"
```

### Forcing Streaming (or Disabling it)
If you are using the CLI in a CI/CD pipeline and need the full JSON blob at once, you can disable streaming:

```bash
# Disable streaming for automation scripts
gemini prompt "Summarize this logs.txt" --no-stream
```

You can also explicitly force streaming in non-interactive environments:

```bash
gemini prompt "Explain quantum computing" --stream
```

## 4. Walkthrough / Technical Deep Dive
**Under the Hood:**
This feature required a significant refactor of the `Client` handling logic.

1.  **Server-Sent Events (SSE):** Instead of waiting for a `200 OK` with a full JSON body, the CLI now opens a connection and listens for Server-Sent Events.
2.  **The `StreamGenerateContent` API:** We migrated the core call from `model.generate_content` to `model.stream_generate_content`.
3.  **Chunk Handling:**
    *   As the API pushes data chunks, the CLI intercepts them.
    *   A buffer handler checks for complete UTF-8 characters (to prevent breaking emojis or multi-byte characters mid-stream).
    *   The payload is parsed immediately, extracting the `text` part of the candidate.
4.  **Stdout Flushing:** To ensure the "typewriter" effect looks smooth, we implemented an explicit `sys.stdout.flush()` after every token print, bypassing standard line-buffering behavior often found in terminal emulators.
