# What's New: SQL Server Extension for Gemini CLI

## 1. Feature Summary
The Gemini CLI ecosystem is expanding. We are thrilled to announce the release of the **SQL Server Extension**, a new module that allows developers to interact directly with Microsoft SQL Server databases from the command line.

This extension bridges the gap between your terminal workflow and your data. Users can now configure connection strings, execute queries, and—most importantly—pipe database schemas and query results directly into Gemini for context-aware AI analysis, all without switching tools.

1.  Open a separate GUI tool (SSMS, Azure Data Studio).
2.  Run a query.
3.  Export or copy the results.
4.  Paste the text into the Gemini CLI prompt.

## 3. How-To Guide

Here is how to get started with the SQL Server extension.

### Step 1: Install the Extension
First, update your CLI and pull the new extension.

```bash
gemini extensions install sql-server
```

### Step 2: Configure the Connection
You can set a global connection string or pass it per session. We recommend saving it to your configuration for ease of use.

```bash
# Interactive configuration
gemini sql configure --name "production-db"
> Enter Connection String: sqlserver://username:password@localhost:1433?database=mydb
```

### Step 3: Interaction
There are two primary ways to use this feature: **Direct Execution** and **AI-Assisted Interaction**.

**A. Run a raw query:**
```bash
gemini sql run --name "production-db" "SELECT TOP 5 * FROM Orders"
```

**B. Ask Gemini to write and run the query (The "Magic" Workflow):**
Pass the database context to the prompt using the `--context` flag.

```bash
gemini chat --context @production-db "Find the top 5 customers by revenue in 2023 and explain the trend."
```

## 4. Walkthrough / Technical Deep Dive

Under the hood, this implementation leverages the modular architecture introduced in version 2.0 of the CLI.

*   **Driver Implementation:** The extension wraps a standard Go SQL driver (likely `go-mssqldb`). When a command is issued, the CLI spawns a lightweight connection pool.
*   **Schema Introspection:** When you use the `--context @db` flag, the CLI performs a rapid "schema dump" (fetching table names and column types, but not row data) and injects this metadata into the system prompt. This allows the LLM to understand your database structure without hallucinating table names.
*   **Security:** Connection strings are stored in the OS-level credential manager (Keychain/Keyring), not in plain text config files, ensuring security compliance.
*   **Output Formatting:** Query results are serialized into JSON or Markdown tables before being passed to the LLM. This structured format helps the model analyze data trends more accurately than raw text dumps.
