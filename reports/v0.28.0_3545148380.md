# Gemini CLI Update: Enhanced Personalization & Adaptive Theming

**Date:** October 26, 2023
**Topic:** CLI Customization & UX
**Based on:** PR #17327, PR #17976

---

## 1. Feature Summary

The latest update to the Gemini CLI brings a significant upgrade to visual customization and user experience. We have introduced two complementary features designed to make the CLI feel more native to your workflow:

1.  **Extension-Based Custom Themes:** Extension developers can now bundle custom themes directly within their extensions. This allows for a richer plugin ecosystem where functionality can be paired with specific visual styles.
2.  **Automatic Theme Switching:** The CLI now intelligently adapts to your terminal's environment. It automatically toggles between Light and Dark modes by detecting the background color of your terminal, ensuring visual consistency without manual intervention.

---

## 2. Background & Context

### The Challenge: Visual Consistency & Extensibility
As the Gemini CLI ecosystem grows, two distinct friction points emerged regarding the visual interface:

*   **Static Theming in a Dynamic Environment:** Users frequently switch their OS or IDE settings between Light and Dark modes (often automatically based on time of day). Previously, the Gemini CLI remained static. If a user switched their terminal to a light background, a dark-themed CLI became difficult to read, requiring manual adjustment via settings.
*   **Limited Styling for Extensions:** Extensions add powerful capabilities to the CLI, but until now, they could not influence the visual presentation. Developers wanted to provide a cohesive experience (branding or syntax highlighting specific to their tool) but were limited to the user's existing theme configuration.

### The Solution
These updates solve these problems by making the `ThemeManager` more robust and "environment-aware."
*   **PR #17327** refactors how themes are loaded, allowing the `ExtensionManager` to inject themes dynamically. This promotes a modular architecture where themes are treated as pluggable assets.
*   **PR #17976** introduces environmental polling. By implementing standard escape sequences (OSC 11), the CLI can "see" the terminal it runs in, solving the readability consistency issue.

## 3. How-To Guide

### For Users: Using Automatic Theme Switching
This feature works out-of-the-box for most users, provided you are using the default styling.

1.  **Ensure you are using a Default Theme:** The auto-switching logic specifically hooks into the `'Default'` (Dark) and `'Default Light'` themes.
2.  **Configure your Terminal:** Ensure your terminal emulator supports OSC 11 queries (most modern terminals like iTerm2, VS Code Integrated Terminal, and Windows Terminal do).
3.  **Action:** Simply change your terminal's background color or switch your system theme. The Gemini CLI will update its appearance within approximately 3 seconds.

### For Developers: Adding Custom Themes to Extensions
If you are building an extension, you can now ship a custom theme with your package.

**Step 1: Define the Theme**
Create your theme structure. You can import the `CustomTheme` interface from the core package to ensure type safety.

**Step 2: Update `gemini-extension.json`**
Add a `themes` property to your extension manifest.

```json
{
  "name": "my-cool-extension",
  "version": "1.0.0",
  "main": "./dist/index.js",
  "themes": [
    {
      "name": "Neon Cyberpunk",
      "type": "dark",
      "colors": {
        "primary": "#00ff00",
        "secondary": "#ff00ff",
        "background": "#000000",
        "text": "#ffffff"
      }
    }
  ]
}
```

**Step 3: Accessing the Theme**
Once your extension is installed, users will see "Neon Cyberpunk" listed in the `ThemeDialog` alongside standard themes. The `ExtensionManager` handles the registration automatically.

## 4. Walkthrough / Technical Deep Dive

### Deep Dive: Automatic Theme Switching (Oscillating Stability)
The implementation of auto-switching (#17976) is clever because it avoids "flickering" when a user has a background color that is on the border of light and dark.

1.  **Polling via OSC 11:** Every 3 seconds, the CLI sends an OSC 11 escape sequence to the terminal. The terminal replies with an RGB hex string representing the background color.
2.  **Luminance Calculation:** The CLI parses this X11 color string and calculates relative luminance using **WCAG 2.0 standards**.
3.  **Hysteresis Implementation:** To prevent the theme from rapidly toggling back and forth if the background luminance is near the tipping point, the team implemented **hysteresis** (a lag between input and response).
    *   **Light Threshold (140):** The background must get significantly bright to trigger the Light theme.
    *   **Dark Threshold (110):** The background must get significantly dark to trigger the Dark theme.
    *   *Result:* If your background luminance is 125 (a gray middle-ground), the CLI stays in its current state rather than glitching.

### Deep Dive: Extension Theme Architecture
The architecture for theme management was significantly refactored in #17327 to support "Namespacing."

*   **Origin Tracking:** The `ThemeManager` now understands where a theme comes from: `User Settings`, `Extensions`, or `File Paths`.
*   **Conflict Resolution:** To prevent `Extension A` from overwriting a theme named "Dracula" provided by `Extension B`, the system namespaces these themes internally.
*   **Centralized Dialog:** The `ThemeDialog` was rewritten to pull from this new, unified `ThemeManager` source, meaning it dynamically aggregates core themes + extension themes into a single, seamless list for the user.
