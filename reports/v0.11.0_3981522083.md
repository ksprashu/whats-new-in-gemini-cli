# What’s New: Native JSON & Raw Content Support in Web Fetch

**Release:** Gemini CLI Update
**Contributor:** @abhipatel12
**Component:** `WebFetchTool`

---

## 1. Feature Summary
The Gemini CLI has significantly improved its ability to interact with the web. The **Web Fetch** tool now intelligently detects content types, allowing it to properly retrieve and process non-HTML content.

Previously, the tool attempted to render everything as a webpage. Now, when you point Gemini at a **JSON API**, a **raw text file**, or **source code**, it respects the format and provides the raw data to the model. This unlocks the ability to use Gemini CLI as a powerful API debugger and code analyzer for remote resources.

## 2. Background & Context
**The Problem:**
Prior to PR #11284, the `WebFetchTool` utilized a fallback mechanism that was arguably *too* aggressive. It indiscriminately applied an `html-to-text` conversion to every URL it fetched.

While this was great for reading blog posts or documentation, it resulted in data corruption when fetching structured data. For example, if you asked Gemini to fetch a JSON endpoint, the tool would strip out brackets and quotes, treating the JSON syntax as HTML tags or formatting, rendering the data unusable for the model.

**The Solution:**
This update introduces **intelligent content type detection**. The tool now inspects the HTTP headers of the response before deciding how to process the text. This ensures that a JSON object remains a JSON object, and Python source code remains executable syntax, while standard websites continue to be rendered as readable text.

## 3. How-To Guide
You don't need to change any configuration to use this feature; it works automatically whenever you ask Gemini to access a URL.

### Scenario A: Working with APIs
You can now ask Gemini to interact with public APIs directly to analyze data.

**Prompt:**
```bash
gemini "Fetch the data from https://jsonplaceholder.typicode.com/todos/1 and summarize the task status."
```

**Result:**
Gemini will receive the raw JSON (e.g., `{"userId": 1, "id": 1, "title": "delectus aut autem", "completed": false}`) rather than a mangled string, allowing it to accurately tell you the task is incomplete.

### Scenario B: Analyzing Raw Source Code
You can point Gemini at raw files on GitHub or other repositories.

**Prompt:**
```bash
gemini "Read the code at https://raw.githubusercontent.com/google-gemini/gemini-cli/main/README.md and tell me the installation steps."
```

**Result:**
Gemini treats the response as `text/plain` (or markdown) and preserves the formatting, allowing it to give you precise installation instructions.

## 4. Walkthrough / Technical Deep Dive
The core logic change resides in how the `WebFetchTool` handles the HTTP response body in its fallback mechanism.

### The Logic Flow:
1.  **Fetch Request:** The CLI executes a GET request to the target URL.
2.  **Header Inspection:** The tool inspects the `Content-Type` header returned by the server.
3.  **Conditional Processing:**
    *   **Case 1: HTML (`text/html`) or Missing Header:** The tool assumes the content is a webpage. It proceeds with the original logic, passing the body through the `html-to-text` converter to strip tags and format the page for the LLM.
    *   **Case 2: Non-HTML (`application/json`, `text/plain`, etc.):** The tool bypasses the converter entirely. It returns the **raw text content** of the response.

### Why this matters for Developers:
By respecting the `Content-Type` header, we reduce hallucinations caused by malformed input. The model no longer has to "guess" what the data used to look like before the HTML stripper ran over it; it sees exactly what the server sent.
