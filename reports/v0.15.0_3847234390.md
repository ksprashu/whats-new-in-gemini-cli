## 1. Feature Summary
The Gemini CLI has introduced **Native Image Rendering**. This update allows developers to view image inputs (for multimodal prompts) and image outputs directly within their terminal window, eliminating the need to context-switch to external image viewers or browsers.

The CLI now automatically detects your terminal emulator's capabilities and renders images using advanced graphics protocols (such as Sixel, iTerm2, and Kitty), bringing a "pixel-perfect" visual experience to the command line interface.

## 2. Background & Context
**The Problem:**
As developers increasingly rely on Gemini’s multimodal capabilities (Gemini Pro Vision), the CLI experience became fragmented. Users would upload an image for analysis but could only see the file path (e.g., `image.png`), or receive code that generates a plot but have no way to verify the visual result without leaving the terminal.
*   *DX Friction:* Discussions highlighted that constantly opening files in Preview/Explorer to verify the input image broke the "flow state."
*   *Blind Spots:* Users often sent the wrong image version to the API because they couldn't verify the visual content in the CLI buffer.

**The Solution:**
This change integrates robust terminal graphics detection. Instead of treating the terminal as a text-only grid, the Gemini CLI now treats it as a canvas. The implementation focuses on broadly supported protocols to ensure compatibility across different environments (VS Code, iTerm2, WezTerm, etc.).

## 3. How-To Guide

### Prerequisites
Ensure you are using a terminal emulator that supports graphics protocols (e.g., iTerm2 on macOS, WezTerm, or VS Code Terminal with Sixel support enabled).

### Scenario: Multimodal Image Analysis
When you pass an image to Gemini for analysis, the CLI will now echo the image back to you in high resolution.

**Command:**
```bash
gemini prompt "Describe the architectural style of this building" --image ./cathedral.jpg
```

**Output:**
1.  **[Visual Render of cathedral.jpg appears here inline]**
2.  **Gemini Response:** "This is a classic example of Gothic Revival architecture..."

### Configuration
If you are in a low-bandwidth environment or prefer text-only output, you can disable this feature via a flag or config:

```bash
# Per command
gemini prompt "..." --image ./img.png --no-render

# Global config
gemini config set render_images false
```

## 4. Walkthrough / Technical Deep Dive

The magic lies in how the CLI negotiates with the terminal emulator. Here is what happens under the hood when `gemini prompt --image` is executed:

1.  **Capability Detection:**
    The CLI inspects environment variables (like `$TERM_PROGRAM`, `$LC_TERMINAL`, or specific escape sequence queries) to identify the running terminal emulator.

2.  **Protocol Selection:**
    Based on the detection, the CLI selects the optimal rendering strategy:
    *   **iTerm2 Inline Image Protocol:** Uses a specific OSC 1337 escape sequence with base64 encoded image data.
    *   **Sixel:** Breaks the image into six-pixel high bands. This is widely supported (xterm, WezTerm).
    *   **Kitty Graphics Protocol:** A more modern, high-performance GPU-accelerated protocol.
    *   **Fallback:** If no graphics support is detected, it falls back to a safe ANSI block-character approximation or simply displays the filename.

3.  **Resizing & Downsampling:**
    To prevent the image from blowing out the terminal buffer, the CLI calculates the window dimensions (rows/columns) and resizes the image in memory before encoding it to the byte stream.
