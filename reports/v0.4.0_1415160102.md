# 🚀 What's New: Gemini CLI Configuration Streamlining

## 1. Feature Summary
The Gemini CLI is shifting its configuration philosophy. We are moving away from ephemeral command-line arguments in favor of persistent configuration via `settings.json`. This release deprecates several CLI flags, prompting users to define these preferences in their configuration file instead. While the flags still work for now, they will emit warnings and are scheduled for removal in a future release.

## 2. Background & Context
**Why was this change made?**
As CLIs mature, the number of flags required to customize a session often grows unwieldy. Users found themselves typing long, repetitive commands for every session (e.g., specifying specific context windows, output formats, or non-standard options).

**The Problem:**
*   **Cognitive Load:** Users have to remember obscure flag names.
*   **Repetition:** Typing the same arguments for every single `gemini chat` or `gemini run` command.
*   **Maintainability:** Managing logic for dozens of flags complicates the codebase.

**The Solution:**
By moving these options to `settings.json`, we ensure that your environment is "set and forget." This "CLI Streamlining" effort aligns with the changes seen in `src/config/settings.ts` and the associated schema files. This change ensures a cleaner terminal interface and a more personalized developer experience that persists across sessions.

## 3. How-To Guide

### Identifying Deprecated Arguments
When you run a command using a deprecated flag, the CLI will now alert you.
*   **Old Workflow:** `gemini chat --some-deprecated-flag`
*   **Result:** The command runs, but you will see a warning:
    > *Warning: Argument '--some-deprecated-flag' is deprecated and will be removed in a future release. Please use the 'someSetting' option in settings.json.*

### Migrating to `settings.json`
Instead of passing flags every time, configure them globally.

1.  **Open your settings:**
    Run the built-in settings command (referenced in `src/ui/commands/settingsCommand.ts`):
    ```bash
    gemini settings
    ```

2.  **Edit the configuration:**
    Locate the appropriate key in the JSON structure and update it. For example, if a flag regarding specific extension behavior is deprecated, you would add it to the config:

    ```json
    {
      "editor": "vscode",
      "experimentalFeatures": true,
      "deprecatedFlagReplacement": "new-value"
    }
    ```

3.  **Verify:**
    Run your command without the flag:
    ```bash
    gemini chat
    ```
    The CLI will automatically pick up the value from your JSON file.
