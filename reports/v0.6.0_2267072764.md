# 🚀 What's New in Gemini CLI: The MCP Toolbox

**Release:** MCP Toolbox Extension
**Focus:** Connectivity, Extensibility, Data Context

---

## 1. Feature Summary
The Gemini CLI now supports the **Model Context Protocol (MCP)**. This creates a universal "socket" that allows the CLI to connect to over 30+ external data sources—including GitHub, Slack, PostgreSQL, Google Drive, and local file systems—without requiring hard-coded integrations or complex custom plugin logic.

By configuring an MCP "Server" (a lightweight adapter), the Gemini CLI can now read, analyze, and manipulate data located outside its immediate training window, effectively turning the CLI into an agent capable of interacting with your entire technical ecosystem.

---

## 2. Background & Context
### The Problem: The "Siloed" LLM
Previously, if you wanted Gemini to analyze a specific row in a PostgreSQL database or summarize a thread in Slack, you had to:
1.  Manually export the data and paste it into the prompt.
2.  Write a custom, one-off script to fetch the data and pipe it into the CLI.

This approach was unscalable. Every new tool required a new integration, leading to feature bloat and maintenance headaches.

### The Solution: Model Context Protocol (MCP)
The team integrated MCP to solve the **N+1 integration problem**. Instead of the Gemini CLI building 30 separate integrations, it now implements the **MCP Client** standard. This decouples the model from the tools.

*   **Why this matters:** You can now bring your own tools. If the community builds an MCP server for a niche tool (e.g., a proprietary internal API), the Gemini CLI can use it immediately without a CLI update. This shifts the CLI from a simple chat interface to a fully extensible agentic runtime.

## 3. How-To Guide: Connecting Your First Tool

To use this feature, you need to define which "MCP Servers" the Gemini CLI should launch. This is done via the configuration file.

### Prerequisites
*   Latest version of Gemini CLI.
*   Node.js (since many MCP servers run on Node).

### Step 1: Install an MCP Server
For this example, we will use the **Filesystem MCP Server**, which gives Gemini secure access to read/write files in a specific directory.

```bash
npm install -g @modelcontextprotocol/server-filesystem
```

### Step 2: Configure the Gemini CLI
Edit your Gemini CLI configuration file (usually `~/.gemini/config.json` or defined via flags). Add a generic `mcpServers` block:

```json
{
  "mcpServers": {
    "filesystem": {
      "command": "npx",
      "args": [
        "-y",
        "@modelcontextprotocol/server-filesystem",
        "/Users/username/my-projects"
      ]
    },
    "git": {
      "command": "npx",
      "args": [
        "-y", 
        "@modelcontextprotocol/server-github"
      ],
      "env": {
        "GITHUB_TOKEN": "your-token-here"
      }
    }
  }
}
```

### Step 3: Run the CLI
Start the CLI. You will see a startup log indicating that MCP tools have been loaded.

```bash
gemini chat
> Connected to MCP Server: filesystem
> Connected to MCP Server: git
```

### Step 4: Prompt with Context
Now, ask Gemini to perform actions that require these tools.

> **User:** "Check the git logs for the last commit and create a markdown file in my project folder summarizing the changes."

> **Gemini:** *Calling tool `git_log`... Calling tool `write_file`...*
> "I've analyzed the commit and saved the summary to `summary.md`."

## 4. Walkthrough / Technical Deep Dive

How does the Gemini CLI achieve this without understanding the specific API of every tool?

### The Architecture
1.  **The Client (Gemini CLI):** When the CLI starts, it reads the config and spawns the defined servers as **sub-processes**.
2.  **Transport (Stdio):** The CLI communicates with these servers via standard input/output (stdio) using JSON-RPC messages.
3.  **Handshake:** The CLI asks the server: *"What tools do you have?"* The server responds with a JSON schema definition (e.g., `read_file`, `search_db`).
4.  **Injection:** The CLI injects these tool definitions into the Gemini API call as generic "Function Declarations."

### The Execution Loop
When you ask a question like "What's in the database?":
1.  **Intent Recognition:** The Gemini model recognizes it needs data and generates a **Tool Call** request (not text).
2.  **Routing:** The CLI intercepts this request. It sees the model wants to call `query_db`.
3.  **Delegation:** The CLI sends a JSON-RPC message to the specific MCP Server process responsible for the database.
4.  **Execution:** The MCP Server runs the SQL query and returns the JSON result to the CLI via stdout.
5.  **Synthesis:** The CLI feeds this result back to the Gemini model, which generates the final human-readable answer.

**Security Note:** The CLI acts as the gatekeeper. MCP servers run locally on your machine, so credentials (like API keys) stay local and are never sent to Google servers—only the specific tool outputs are sent to the model context.
