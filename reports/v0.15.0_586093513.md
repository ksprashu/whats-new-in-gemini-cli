# Feature Report: Enhanced Angular Integration in Gemini CLI

**Date:** October 26, 2023
**Release Reference:** PR #10252
**Contributor:** @MarkTechson

## 1. Feature Summary
The Gemini CLI has been updated to treat **Angular** as a first-class citizen within its project generation and recommendation engine. Previously, the CLI’s base prompt logic heavily favored other frameworks (such as React or Vue.js). With this update, the CLI now explicitly recognizes Angular as a preferred technology option for both standalone frontend applications and full-stack architectures.

## 2. Background & Context
**The Problem:**
Prior to this update, when users asked the Gemini CLI to scaffold a new web project or suggest a technology stack, the underlying prompt instructions led the AI to disproportionately suggest React or Vue.js. This created friction for the substantial community of developers who prefer opinionated, enterprise-grade frameworks like Angular.

**The Solution:**
This change (PR #10252) modifies the "Base Prompt"—the foundational instructions sent to the Gemini model when it acts as the CLI agent. By updating the definitions of "preferred technology," the team has ensured that Angular is now weighted equally alongside other modern frameworks. This aligns the CLI with the diverse reality of the modern web development landscape, offering true framework neutrality.

## 3. How-To Guide
You do not need to update your configuration files to use this feature; it is baked into the core logic of the CLI. Here is how you can leverage the new support:

### Scenario A: Generating a New Frontend
When you use the CLI to start a project, you can now expect Angular to appear in suggestions or be handled more accurately when requested.

**Command:**
```bash
gemini new "I want to build a dashboard for managing inventory."
```
**Result:**
The CLI may now ask: *"Would you like to use React, Vue, or **Angular** for this dashboard?"*

### Scenario B: Explicit Angular Requests
When you specifically ask for Angular, the CLI now has better context on how to scaffold it alongside other tools.

**Command:**
```bash
gemini scaffold --prompt "Create a full-stack app with a Go backend and an Angular frontend."
```
**Result:**
The CLI will generate a project structure that adheres to Angular best practices (e.g., proper separation of components, services, and modules) rather than trying to force React patterns into an Angular codebase.

## 4. Walkthrough / Technical Deep Dive
This feature is a **Prompt Engineering** update rather than a compiler or logic change in the CLI binary itself.

**Under the Hood:**
The Gemini CLI operates by sending a "System Prompt" (or Base Prompt) to the LLM before user input is processed. This prompt sets the persona and rules for the AI.

1.  **Before PR #10252:** The system prompt likely contained a list of "Modern Frontend Frameworks" that listed `['React', 'Vue']`. Consequently, the probabilistic nature of the LLM ignored Angular.
2.  **After PR #10252:** The definition was updated to something resembling `['React', 'Vue', 'Angular']`.

By explicitly adding Angular to the "preferred technology option" list in the system instructions, the model's temperature (creativity) is guided toward including Angular in full-stack recommendations. This ensures that when the CLI plans a directory structure or suggests dependencies (like `package.json`), it automatically retrieves the correct Angular CLI build artifacts and standard folder hierarchies (`src/app`, `src/assets`, etc.).
