# What’s New: Dataplex Extension for Gemini CLI

## 1. Feature Summary
The Gemini CLI has introduced a comprehensive extension for **Google Cloud Dataplex**. This new module allows data engineers and platform administrators to discover, manage, and govern distributed data and AI artifacts directly from the terminal.

This extension unifies distributed data stored in Google Cloud Storage (GCS) and BigQuery into a logical "Data Mesh," enabling users to manage data lakes, zones, and assets without context-switching to the Google Cloud Console.

## 2. Background & Context
**The Problem:**
Previously, managing the lifecycle of a Data Mesh—specifically Dataplex Lakes and Zones—required heavy usage of the web-based Cloud Console or verbose API calls. Developers often cited friction when attempting to automate the provisioning of data governance policies or when attempting to audit data assets across disparate projects during CI/CD workflows.

**The Solution:**
This change introduces a native CLI surface (`dataplex`) to the Gemini ecosystem. By exposing Dataplex primitives via the CLI, we solve several key issues:
*   **Automation:** Enables the scripting of Data Lake creation and Zone configuration.
*   **Discoverability:** Provides a quick way to list and inspect assets (tables, file sets) without navigating a UI.
*   **Governance at Scale:** Allows for the programmatic application of IAM policies and metadata across logical zones.

## 3. How-To Guide
To get started with the new Dataplex extension, ensure your CLI is updated to the latest version.

### Step 1: Install/Update the Extension
Depending on your installation method, ensure the Dataplex component is active:

```bash
gemini components update
gemini components install dataplex
```

### Step 2: Discovering Data Lakes
To view the logical data lakes currently available in your project and location:

```bash
gemini dataplex lakes list --location=us-central1
```

### Step 3: Inspecting a Specific Zone
Once you have identified a Lake ID (e.g., `marketing-lake`), you can drill down into its Zones (e.g., `raw-zone` or `curated-zone`) to see discovery status and asset definitions:

```bash
gemini dataplex zones describe raw-zone \
  --lake=marketing-lake \
  --location=us-central1
```

### Step 4: Managing Assets
You can attach a generic GCS bucket or BigQuery dataset to a zone as an "Asset" directly via the CLI:

```bash
gemini dataplex assets create sales-data-asset \
  --lake=marketing-lake \
  --zone=raw-zone \
  --location=us-central1 \
  --resource-type=STORAGE_BUCKET \
  --resource-name=projects/my-project/buckets/sales-data-raw \
  --discovery-enabled
```

## 4. Walkthrough / Technical Deep Dive
Under the hood, the Gemini CLI Dataplex extension acts as a thin client wrapper around the **Dataplex Control Plane API**.

1.  **Command Parsing:** When a user executes `gemini dataplex...`, the CLI parses the logical hierarchy (Lake -> Zone -> Asset).
2.  **Authentication:** It utilizes the active application default credentials (ADC) to generate a bearer token.
3.  **API Interaction:**
    *   For **Discovery**, the CLI polls the Dataplex API to retrieve metadata regarding the "Physical" data (where it lives) versus the "Logical" data (how it is organized in the mesh).
    *   For **Governance**, the CLI abstracts complex IAM bindings. When you manage permissions via the CLI, it translates these into Dataplex-specific IAM policy bindings that propagate down to the underlying storage resources (GCS buckets or BQ datasets).
4.  **Asynchronous Operations:** Operations like `assets create` are often long-running. The CLI implements an asynchronous polling mechanism (Operation Polling) to provide a spinner/progress bar until the Dataplex control plane confirms the resource is active and discovery jobs have started.
