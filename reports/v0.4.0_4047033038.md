# What’s New in Gemini CLI: `hideContextSummary`

## 1. Feature Summary
The latest update to the Gemini CLI introduces a new configuration option: **`hideContextSummary`**. This setting allows developers to suppress the verbose metadata output that typically precedes the model's response. By enabling this option, users can hide the list of files, code snippets, and token counts included in the context window, resulting in a cleaner, more focused terminal experience.

## 2. Background & Context
**The Problem:**
As users began leveraging the Gemini CLI for more complex tasks—specifically when ingesting entire repositories or large sets of documentation—the CLI’s default behavior was to print a summary of every piece of "context" sent to the model.

While useful for debugging, this summary became intrusive for power users. In scenarios where a user added 50+ files to the context, the terminal would be flooded with file paths and token statistics, pushing the actual answer from Gemini off the screen.

**The Solution:**
Based on community feedback asking for a "silent" or "quiet" mode, the `hideContextSummary` boolean was introduced. This solves two specific problems:
1.  **Screen Real Estate:** It prevents metadata from cluttering the UI on small laptop screens.
2.  **Automation/Piping:** It ensures that when piping Gemini CLI output to other tools (like files or other scripts), the output remains pure and isn't contaminated by context logs.

## 3. How-To Guide

You can enable this feature in your global configuration file.

### Step 1: Locate your Configuration
Open your Gemini CLI configuration file (typically located at `~/.gemini/config.yaml` or `%USERPROFILE%\.gemini\config.yaml`).

### Step 2: Update the Configuration
Add the `hideContextSummary` key and set it to `true`.

```yaml
# ~/.gemini/config.yaml

# Existing settings...
model: "gemini-1.5-pro"
temperature: 0.7

# NEW SETTING
hideContextSummary: true
```

### Step 3: Verify
Run a command that normally includes context (e.g., passing a file).

**Before (Default):**
```bash
$ gemini ask "Explain this code" --file app.js
> Context added: app.js (1.2kb)
> Total context tokens: 450
> ... [Gemini Response] ...
```

**After (With `hideContextSummary: true`):**
```bash
$ gemini ask "Explain this code" --file app.js
> ... [Gemini Response] ...
```

## 4. Walkthrough / Technical Deep Dive
Under the hood, this change affects the CLI's presentation layer (the View) rather than the logic layer (the Controller).

1.  **Context Construction:** When you run a command, the CLI still gathers all referenced files, reads their contents, and calculates token counts using the tokenizer.
2.  **The Check:** Before the `ContextPrinter` class (or equivalent output handler) iterates through the list of loaded files to print them to `stdout`, it now checks the global config object for the `hideContextSummary` flag.
3.  **The API Call:** Crucially, **this setting does not alter the payload sent to the Gemini API.** The model still receives all the files and context necessary to answer your question. The suppression is purely cosmetic on the client side.

This separation ensures that turning off the summary does not degrade the quality of the answer; it simply changes the verbosity of the CLI feedback loop.
