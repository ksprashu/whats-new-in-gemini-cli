# 🚀 What’s New in Gemini CLI: Workflow Velocity & UI Polish

This release focuses heavily on **Developer Experience (DX)**. We’ve tackled two distinct friction points that occur during extended coding sessions: "interruption fatigue" caused by frequent tool approvals, and "terminal flooding" caused by pasting large context blocks.

## 1. Feature Summary

*   **Queued Tool Confirmations:** The CLI now intelligently batches tool execution requests. Instead of interrupting you for permission before *every* single step in a multi-step workflow, Gemini creates a queue of pending actions. You can review the plan and authorize the sequence in one go, maintaining safety while significantly speeding up agentic tasks.
*   **Expandable Large Text Pastes:** Pasting massive code blocks or logs no longer hijacks your terminal history. Large inputs are now automatically detected and collapsed into a discrete UI element (e.g., `... 150 lines pasted ...`), keeping your workspace clean while retaining the full context for the model.

---

## 2. Background & Context

### The "Permission Fatigue" Problem
**Context:** As users began utilizing Gemini CLI for more complex agentic tasks (e.g., "Refactor this directory" or "Analyze these 5 files"), the safety guardrails became a bottleneck.
**The Issue:** Previously, if a prompt required Gemini to read three files and write one, the CLI would halt for user input four separate times (`[y/N]`).
**The Fix:** Based on community feedback regarding "chatty" permissions, we moved to a **Queued Confirmation** model. This aligns with the Principle of Least Surprise—users want to approve the *intent* of the workflow, not micromanage every API call, provided the actions are visible.

### The "Wall of Text" Problem
**Context:** Developers frequently paste stack traces, JSON blobs, or entire configuration files into the CLI to debug errors.
**The Issue:** Pasting a 200-line error log pushes the original prompt and previous conversation off-screen. This "context scrolling" makes it difficult to reference what you were actually asking about.
**The Fix:** We implemented a heuristic to detect large pastes. By collapsing them by default, we ensure the "Chat" aspect of the CLI remains readable, treating the pasted text more like an attached file attachment than a spoken sentence.

## 3. How-To Guide

### Using Queued Tool Confirmations

**Scenario:** You want Gemini to clean up a specific project directory.

1.  **Enter a complex prompt:**
    ```bash
    > Check the current directory for .tmp files and delete them.
    ```
2.  **View the Queue:**
    Instead of executing immediately or asking once, Gemini processes the logic and presents the queue:
    ```text
    Gemini is requesting to perform the following actions:
    1. [Tool: List Directory] path="./"
    2. [Tool: Delete File] path="./debug.tmp"
    3. [Tool: Delete File] path="./test_run.tmp"

    > Confirm execution of 3 actions? (y/n/details)
    ```
3.  **Execute:** Type `y` to run the batch.

### Using Expandable Pastes

**Scenario:** You need to debug a long React component.

1.  **Copy your code** (e.g., 300 lines of JavaScript).
2.  **Paste into the CLI prompt.**
3.  **Observe the UI:**
    The CLI instantly recognizes the volume.
    ```bash
    > Can you find the memory leak in this code?
    >
    > 📄 [Pasted Text: 342 lines, 12kb] (Press <Tab> to expand/collapse)
    ```
4.  **Send the prompt.** The model receives the full text, but your terminal window remains clean.

## 4. Walkthrough / Technical Deep Dive

### The Confirmation Queue Logic
Under the hood, the `ToolUse` loop has been refactored.
*   **Previous Behavior:** `Model Request -> Middleware Intercept -> Prompt User -> Execute -> Return Output`.
*   **New Behavior:** The loop now supports a `Lookahead` state. When the model generates a chain of thought involving multiple tool calls (parallel function calling), the CLI middleware intercepts the *list* of tool calls before execution.
*   It renders these calls into a structured table in the TUI (Terminal User Interface).
*   **Safety Check:** We still halt on "High Risk" actions (like `exec_shell`) individually if configured, but "Low Risk" actions (like `read_file`) are batched.

### Paste Buffer Handling
We are utilizing standard stdin buffer monitoring.
*   **Detection:** Upon detecting a paste event (distinguished from typing by the speed of character entry ~<10ms per char), the CLI buffers the input.
*   **Thresholds:** If the input exceeds a configurable line count (default: 20 lines) or character count, the rendering engine switches to a "Summary View."
*   **ANSI Control:** We use ANSI escape codes to rewrite the current line, replacing the streaming text with the summary block. The full payload is stored in a hidden buffer variable passed to the API context window, decoupling the *display* representation from the *model* representation.
