# 🚀 What's New in Gemini CLI: Enhanced Interactive Shell Focus

**Release Reference:** PR #13341  
**Contributor:** @galz10

## 1. Feature Summary
The interactive shell experience within the Gemini CLI has received a significant ergonomic upgrade with the introduction of **Click-to-Focus** capabilities.

Users utilizing the "Use Alternate Buffer" setting can now intuitively manage input focus using their mouse. Clicking within the embedded shell output area instantly directs keyboard input to that shell process. Conversely, clicking back on the main CLI input prompt restores control to Gemini. This update also includes polished handling for command cancellations, ensuring your session history remains clean.

## 2. Background & Context
**The Problem:**
Previously, interacting with embedded shells (such as running servers or interactive scripts) inside the Gemini CLI could feel rigid. Switching context between sending commands to the active process and asking Gemini a new question often required specific keyboard navigation, creating friction in the developer workflow. Additionally, cancelling a running shell command occasionally left "ghost" entries or duplicate artifacts in the session history.

**The Solution:**
This change aligns the CLI's behavior with standard GUI terminal expectations. By implementing mouse-event handling for focus states, the interface becomes "mode-less" in feeling—users simply click where they want to type. The backend logic was also refactored to handle the termination of shell streams more gracefully, solving the history pollution issue.

## 3. How-To Guide

To utilize the new Click-to-Focus feature, ensure you have the **"Use Alternate Buffer"** setting enabled in your configuration.

### Workflow Example:
1.  **Start an Interactive Process:**
    Ask Gemini to run a command that requires interaction, such as a Python script or a local server.
    ```bash
    > run python interactive_script.py
    ```
2.  **Focus the Shell (The New Way):**
    When the script output appears in the embedded window, simply **click anywhere inside the output box**.
    *   *Visual Cue:* The main prompt at the bottom may dim or lose its cursor.
    *   *Action:* Type directly into the running Python script.
3.  **Return to Gemini:**
    To ask Gemini a follow-up question without killing the script, **click on the main input prompt** at the bottom of the screen.
    *   *Action:* Focus returns to the CLI; you can now type `/gemini help` or other commands.

## 4. Walkthrough / Technical Deep Dive
This feature is not merely a UI overlay; it involves significant changes to the application's global state management.

### Global Focus State Management
The core of this update is the introduction of `setEmbeddedShellFocused` within the `UIActionsContext`. Instead of relying on local component state, the CLI now centrally tracks where the user's intent is directed.
*   **`ToolMessage` Component:** Now listens for click events. When triggered, it dispatches the global action to shift focus to the embedded shell.
*   **`InputPrompt` Component:** Similarly, clicking the primary input area dispatches an "unfocus" action, reclaiming the keystrokes for the main CLI.

### Improved Stream Handling
The PR refines the logic in `useGeminiStream` and the `shellCommandProcessor`.
*   **Cancellation Logic:** When a user cancels a command (via `Ctrl+C` or UI interaction), the processor now traps this state more effectively.
*   **History Sanitation:** By preventing the commitment of incomplete or interrupted states to the history log, the UI prevents duplicate entries that used to occur during rapid context switching.

### Testing
Reliability was a priority. New unit tests were added specifically for:
*   **`ToolMessage`**: Verifying click handlers correctly toggle the focus state.
*   **`InputPrompt`**: Ensuring focus is correctly stolen back from the embedded shell.
