# What’s New: Explicit Extension Restart Command

## 1. Feature Summary
We are introducing a new command to the Gemini CLI: `/extensions restart`. This feature allows developers to manually trigger a restart of their installed extensions without needing to restart the entire CLI or IDE session. This command empowers users to immediately apply updates or reset the state of an extension, providing a more responsive and controlled development environment.

## 2. Background & Context
**The Problem:**
Previously, managing the lifecycle of extensions—specifically applying updates or recovering from weird states—could be opaque. Users often relied on "automatic extension reloading" (an experimental feature) or had to resort to fully restarting their environment to ensure changes took effect. When an extension was updated in the background, the UI might display an "updated, needs restart" status, leaving the user in limbo until a reload occurred.

**The Solution:**
As detailed in **PR #12739**, this change decouples the ability to restart extensions from the automatic reloading experiment. By introducing a manual command, we provide a deterministic, universal method for users to refresh their tools. This ensures that whether you prefer auto-reloading or manual control, you have a direct path to getting your extensions into a "clean" state.

## 3. How-To Guide

Using the new feature is straightforward. It is designed to be used whenever you have updated an extension or suspect an extension is behaving incorrectly and needs a refresh.

### Step-by-Step:
1.  **Open the Gemini CLI.**
2.  **Check Extension Status (Optional):** If you have recently updated an extension, you might see a status indicator suggesting an extension is "updated, needs restart."
3.  **Run the Command:**
    Type the following command into the input bar:
    ```bash
    /extensions restart
    ```
4.  **Verification:**
    The CLI will reload the extensions. Upon success, the UI status for any pending extensions will change from **"updated, needs restart"** to **"updated"**, indicating they are active and running the latest version.

## 4. Walkthrough / Technical Deep Dive
The implementation of `/extensions restart` goes beyond a simple "off/on" switch. Here is how it handles state management under the hood:

*   **Command Independence:** The logic for this command is isolated from the `automatic extension reloading` configuration. This means the command is universally available to all users, regardless of whether they have opted into the auto-reload experiment.
*   **State Transitioning:**
    1.  When the command is executed, the CLI initiates a teardown of the running extension instances.
    2.  It re-initializes the extensions from the disk (picking up any new code changes).
    3.  **The UI Event Loop:** Crucially, the PR introduces a new `RESTARTED` event type. When the restart completes, this event is fired to the frontend.
    4.  The UI listens for this specific event to update the visual indicator. It explicitly transitions the extension's metadata status from a "dirty" state (`updated, needs restart`) to a "clean" state (`updated`).

## 5. Next Steps for Demos
To effectively showcase this feature in a video or live demo, consider the following scenarios:

*   **Scenario A: The "Hot" Update:**
    1.  Have the Gemini CLI running with a custom local extension.
    2.  Modify the extension's code (e.g., change the output string of a command) in your text editor.
    3.  Show that the CLI *doesn't* immediately have the new behavior.
    4.  Run `/extensions restart`.
    5.  Run the extension command again to prove the code change is live instantly.

*   **Scenario B: UI State Cleanup:**
    1.  Simulate a state where an extension is flagged as "Updated, needs restart" (if possible in the demo environment).
    2.  Highlight the warning in the UI.
    3.  Execute `/extensions restart`.
    4.  Zoom in on the UI to show the status resolving to "Updated" without the user closing the window.
