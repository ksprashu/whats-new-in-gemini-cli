# What's New: Chronosphere Observability Extension

**Date:** October 26, 2023
**Component:** Extensions / Integrations
**Status:** Available Now

## 1. Feature Summary
The Gemini CLI now supports a direct integration with **Chronosphere**, the cloud-native observability platform. By installing the new Chronosphere Model Context Protocol (MCP) extension, developers can use the Gemini CLI to query their observability data using natural language.

You can now interact with logs, metrics, traces, events, and specific infrastructure entities directly from your terminal, allowing Gemini to act as an intelligent SRE assistant that can diagnose issues, generate PromQL, and summarize system health in real-time.

## 2. Background & Context
**The Problem:**
Developers and SREs often struggle with context switching during incident response or routine debugging. To check system health, one usually has to leave the terminal/IDE, log into the Chronosphere UI, remember specific PromQL syntax, or manually hunt for trace IDs. This friction slows down Mean Time To Resolution (MTTR).

**The Solution:**
This update introduces a bridge between the Gemini CLI and the Chronosphere API via the Model Context Protocol (MCP). By wrapping the Chronosphere Go SDK into an MCP server, we allow the Large Language Model to "see" and "call" tools that retrieve observability data.

**Why this matters:**
*   **Democratization of Querying:** You no longer need to be a PromQL expert to get value out of your metrics. You can simply ask, "Why is the cart service slow?"
*   **Unified Workflow:** Troubleshooting happens right where you code.
*   **Contextual Awareness:** Gemini can ingest the raw data (logs/traces) and provide a summary or root cause analysis, rather than just dumping raw JSON.

## 3. How-To Guide

### Prerequisites
*   Gemini CLI installed and authenticated.
*   A valid Chronosphere API Token.
*   Your Chronosphere Tenant identifier.

### Step 1: Install the Extension
Use the `extensions install` command to pull the MCP server directly from the repository.

```bash
gemini extensions install https://github.com/chronosphereio/chronosphere-mcp
```

### Step 2: Configuration
The extension requires environment variables to authenticate with your specific Chronosphere instance. You will likely be prompted to set these, or you can export them in your shell configuration (check the specific repo `README` for exact variable names, but they typically follow this pattern):

```bash
export CHRONOSPHERE_API_TOKEN="your-api-token"
export CHRONOSPHERE_ORG="your-org-domain"
```

### Step 3: Usage Examples
Once installed, you can start a chat session or use one-off prompts. Gemini will automatically route relevant requests to the Chronosphere tool.

**Scenario A: Metrics (PromQL generation)**
> **User:** "Show me the error rate for the `payment-service` over the last 30 minutes."
>
> **Gemini:** *Calls `query_metrics` with generated PromQL.*
> "Here is the error rate graph data. I see a spike starting at 10:05 AM..."

**Scenario B: Tracing**
> **User:** "Find recent traces with latency > 500ms in the `frontend` service."
>
> **Gemini:** *Calls `query_traces`.*
> "I found 5 traces matching that criteria. The bottleneck appears to be in the database span..."

**Scenario C: Events & Logs**
> **User:** "Did any deployment events happen in the last hour?"

## 4. Walkthrough / Technical Deep Dive

The Chronosphere extension is built upon the **Model Context Protocol (MCP)**. Here is how the flow works under the hood when you run a command:

1.  **Tool Discovery:** When the Gemini CLI starts with the extension loaded, it queries the Chronosphere MCP server for a list of available `tools`. The server returns capabilities such as:
    *   `query_prometheus`: Executes PromQL queries.
    *   `search_traces`: Queries the tracing backend (Jaeger/OTel format).
    *   `read_logs`: Fetches log streams based on label matching.
    *   `list_events`: Retrieves change events (deployments, config changes).

2.  **Intent Recognition:** When you type "Why is the API slow?", Gemini analyzes the prompt. It recognizes that "slow" implies high latency and that it needs data to answer. It selects the `query_metrics` or `search_traces` tool.

3.  **Argument Generation:** Gemini creates the necessary arguments for the function call. For example, it might translate your request into a PromQL query like `histogram_quantile(0.99, sum(rate(http_request_duration_seconds_bucket[5m])) by (le))`.

4.  **Execution:** The Gemini CLI sends this request to the local Chronosphere MCP process. This process uses the configured API Token to make a secure HTTPS request to the Chronosphere SaaS backend.

5.  **Context Injection:** The raw JSON result from Chronosphere is returned to the CLI. Gemini reads this result (which is now part of its context window) and synthesizes a human-readable answer.
