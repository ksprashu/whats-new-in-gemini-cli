Here is the "What’s New" report for the Gemini CLI, focusing on the removal of the `--all-files` flag and the standardization of context management.

# Gemini CLI Report: Context Management Standardization

## 1. Feature Summary
The Gemini CLI has deprecated and removed the `--all-files` (and its shorthand `-a`) command-line flag. This flag was previously used to indiscriminately add all files in the current directory to the context window. 

Moving forward, the CLI unifies context management through the existing **`@` mention syntax**. Users who wish to include the entire codebase or specific directories must now use explicit glob patterns (e.g., `@**/*`) directly within their prompt.

## 2. Background & Context
**Why was this change made?**
Previously, the Gemini CLI supported two distinct methods for ingesting file context:
1.  **Flags:** Using `--all-files` to sweep the whole directory.
2.  **Mentions:** Using `@filename` or `@path/to/files/*` inside the prompt.

This duality created technical debt and maintenance overhead. According to **PR #11228**, the goal of this refactoring was to:
*   **Streamline Context Logic:** By removing the distinct `fullContext` logic associated with the flag, the application now relies on a single, unified mechanism (prompt parsing) for context gathering.
*   **Encourage Best Practices:** The `--all-files` flag was often a "blunt instrument." It filled the context window with potentially irrelevant files, consuming token limits and distracting the LLM. Shifting to `@` mentions encourages users to be more intentional about what they feed the AI (though "all files" is still possible via globbing).
*   **Clean Up the Codebase:** This change allowed for the removal of argument parsing logic, configuration interfaces, and specific environment builders associated with the deprecated flag.

## 3. How-To Guide

### The Old Way (No Longer Supported)
Previously, you might have run a command like this to fix a bug using the context of the whole folder:
```bash
gemini -a "Find the bug in the authentication flow"
# OR
gemini --all-files "Find the bug in the authentication flow"
```
*Attempting to use this flag now will result in an "unknown argument" error or the flag being ignored, depending on your version.*

### The New Way (Standardized)
To achieve the same result (including all files recursively), use the recursive glob pattern (**`@**/*`**) inside your prompt string.

**Example: Including the entire directory**
```bash
gemini "Find the bug in the authentication flow @**/*"
```

**Example: A better, more granular approach**
Because you are now using standard glob patterns, you can easily refine the context to save tokens:

```bash
# Only include files in the src directory
gemini "Refactor the login logic @src/**/*"

# Only include Python files
gemini "Check for PEP-8 compliance @**/*.py"
```

## 4. Walkthrough / Technical Deep Dive
This update is a "cleanup" operation that simplifies the architecture of the CLI.

**Internal Changes:**
*   **Flag Removal:** The CLI argument parser no longer listens for `-a` or `--all-files`.
*   **Logic Removal:** The `fullContext` logic—a specific code path designed to iterate over the file system solely for the flag—has been deleted.
*   **Unified Pipeline:** Now, when a prompt is received, the CLI strictly parses the string for `@` tokens.
    1.  The CLI receives: `"Explain this code @src/utils.ts"`.
    2.  The tokenizer identifies `@src/utils.ts`.
    3.  The file resolver loads that content.
    4.  If the user wants *everything*, they type `@**/*`. The CLI treats this simply as a glob pattern that happens to match everything, rather than triggering a special "all files" mode.

This reduces the cyclomatic complexity of the context builder, as it no longer needs to merge "flag-based context" with "prompt-based context."

## 5. Next Steps for Demos
As a Developer Advocate, here is how you should frame this in upcoming video demos or live streams:

1.  **The "Oops" Moment (Education):** Start by typing `gemini -a` and showing that it no longer works. Use this to pivot into the *why*—that we want explicit control over context.
2.  **The "Power User" Move (Globbing):** Show how `@**/*` replaces the old flag, but immediately pivot to a "better" way. Demonstrate how selecting specific subfolders (e.g., `@src/components/*`) results in a faster, more accurate response than dumping the whole repo.
3.  **Context Hygiene:** Use this feature to talk about "Context Hygiene." Explain that while you *can* use `@**/*` to simulate the old flag, the new syntax makes you visually aware of how much data you are throwing at the CLI, encouraging developers to be more selective.
