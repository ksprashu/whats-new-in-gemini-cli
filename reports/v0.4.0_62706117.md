# 🚀 What's New: Gemini CLI Footer Customization

## 1. Feature Summary
The latest update to the Gemini CLI introduces granular control over the application's footer visibility. Users can now customize the look and feel of their CLI interface by toggling specific information elements on or off via `settings.json`.

This update allows you to hide:
*   The **Current Working Directory (CWD)**.
*   The **Sandbox Status** indicator.
*   The **Current Model** information.
*   The **Context Summary** (token usage/request context).

## 2. Background & Context
**The Problem:**
As the Gemini CLI has grown in functionality, the footer has become a hub for vital system information. However, for many developers, screen real estate is at a premium. Additionally, "information overload" can distract from the primary chat interface.

**The Use Cases:**
1.  **Privacy/Streaming:** Developers recording their screens or streaming coding sessions often leak their system paths (CWD) inadvertently.
2.  **Minimalism:** Power users who already know their environment (Model: Pro 1.5, Sandbox: Local) often prefer a "Zen mode" with fewer visual distractions.
3.  **Small Viewports:** On smaller terminal windows, the footer can wrap or clutter the display.

**The Solution:**
Pull Request #7419 (authored by @miguelsolorio) addresses this by decoupling these UI elements. Instead of a hardcoded footer, the CLI now respects user preferences defined in the configuration schema.

## 3. How-To Guide

To customize your footer, you need to modify your `settings.json` file.

**Step 1: Open your settings**
You can open the settings file in your default editor using the CLI command:
```bash
gemini config edit
```

**Step 2: Add the visibility flags**
Insert the new keys into your JSON configuration. You can mix and match which elements you want to hide.

**Example Configuration (The "Minimalist" Setup):**
```json
{
  "footer": {
    "hideCWD": true,
    "hideSandboxStatus": true,
    "hideModelInfo": true,
    "hideContextSummary": false
  }
}
```

**Available Options:**
| Key | Description | Default |
| :--- | :--- | :--- |
| `hideCWD` | Hides the path of the directory you are currently working in. | `false` |
| `hideSandboxStatus` | Hides the indicator showing if the sandbox environment is active. | `false` |
| `hideModelInfo` | Hides the name of the AI model currently in use (e.g., Gemini 1.5 Pro). | `false` |
| `hideContextSummary` | Hides the token count and context window usage statistics. | `false` |

**Step 3: Save and Reload**
Save the file. The Gemini CLI should pick up the changes immediately on the next render or command.

## 4. Walkthrough / Technical Deep Dive

Based on the code coverage report and PR analysis, here is how the implementation works under the hood:

**The Configuration Layer**
Changes were made to `src/config/settingsSchema.ts` and `src/config/settings.ts`. This ensures that the new boolean flags are strictly typed and validated when the CLI loads. If a user inputs an invalid key, the schema validator will likely reject it or fall back to default values.

**The UI Rendering Logic**
The core changes reside in `src/ui/components/Footer.tsx`.
*   **Coverage Insight:** The `Footer.tsx` file maintains a high coverage rate (~86% statements). This suggests the logic for conditional rendering has been well-tested against various configuration states.
*   **Component Structure:** The `Footer` component acts as a container. Previously, it unconditionally rendered child components like `DirectoryDisplay`, `UsageDisplay`, and `ModelDisplay`.
*   **The Patch:** The component now subscribes to the user's settings context. Before rendering each child component, it checks the corresponding `hide...` boolean.

**Affected Components:**
*   `DirectoryDisplay.tsx` (Controlled by `hideCWD`)
*   `UsageDisplay.tsx` (Controlled by `hideContextSummary`)
*   `ModelDisplay.tsx` (Controlled by `hideModelInfo`)
