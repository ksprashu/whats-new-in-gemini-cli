# 🚀 What's New: The Gemini CLI Extension Ecosystem

**Date:** October 26, 2023
**Feature:** Dynamic Extension Installation
**Reference:** `gemini extensions install`

## 1. Feature Summary
The Gemini CLI has transitioned from a monolithic tool into an extensible platform. With the release of the **Extension Manager**, developers can now install community-driven or private tools directly from GitHub repositories.

The first official extension available via this method is **Jules**, accessible via the command:
`gemini extensions install https://github.com/gemini-cli-extensions/jules`

## 2. Background & Context
### The Problem: Monolithic Bloat vs. Niche Needs
Prior to this update, adding new functionality to the Gemini CLI required updating the core codebase. This led to two main issues discussed in recent architecture reviews:
1.  **Bloat:** The core binary was growing too large with features that only a subset of users needed.
2.  **Release Velocity:** Community contributors had to wait for core release cycles to see their tools shipped.

### The Solution: A Decentralized Plugin Architecture
This change decouples core CLI functionality from add-on utilities. By introducing a generic installer (`gemini extensions install`), the team has laid the groundwork for a federated ecosystem.
*   **Decentralization:** Extensions can live in their own repositories (like `gemini-cli-extensions/jules`).
*   **Speed:** Updates to extensions like "Jules" can be pushed immediately without requiring a version bump of the main Gemini CLI.

## 3. How-To Guide

Here is how to get started with the new extension system using the **Jules** toolkit as an example.

### Step 1: Check your version
Ensure you are running the latest version of Gemini CLI that supports the `extensions` namespace.
```bash
gemini --version
```

### Step 2: Install the Extension
Run the install command pointing to the valid Git repository.
```bash
gemini extensions install https://github.com/gemini-cli-extensions/jules
```

**Expected Output:**
```text
> Cloning jules...
> Installing dependencies...
> ✅ Extension 'jules' installed successfully.
```

### Step 3: Verify Installation
List your installed extensions to confirm Jules is active.
```bash
gemini extensions list
```

### Step 4: Run the Extension
You can now access the extension directly through the main CLI.
```bash
gemini jules --help
```

## 4. Walkthrough / Technical Deep Dive
**How it works under the hood:**

When you run `gemini extensions install <URL>`, the CLI performs a specific sequence of operations designed to safely integrate external code:

1.  **Repository Cloning:** The CLI uses the local system's `git` binary to shallow-clone the target repository into a hidden user directory (typically `~/.gemini/extensions/`).
2.  **Manifest Parsing:** The installer looks for a specific manifest file (likely `gemini.yml` or `extension.json`) in the root of the cloned repo. This file defines the entry point command (e.g., mapping `jules` to a specific binary or script).
3.  **Dependency Resolution:** If the extension requires a build step (defined in the manifest), the CLI attempts to run it (e.g., `npm install` or `go build`).
4.  **Path Registration:** The CLI updates its internal registry map, linking the namespace `jules` to the local path of the installed extension.

**Security Note:**
Because this feature executes code from remote URLs, the CLI currently restricts installation to HTTPS URLs to ensure transport security, though users should still verify the integrity of the repository owner before installing.
