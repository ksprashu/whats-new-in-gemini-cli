# 🚀 What's New: Granular Conversation Control in Gemini CLI

**Release Reference:** PR #10844 | **Author:** @silviojr

## 1. Feature Summary
This update introduces precise control over conversation history ("turns") within the Gemini CLI. Users can now manage how much context the model retains during a session. This functionality is accessible via two methods:
*   **Interactive UI:** A new menu option within the `/settings` command to Enable, Disable, or set a numeric Limit on turns.
*   **Advanced Configuration:** Direct manipulation of the `settings.json` file for persistent, fine-tuned environment setup.

## 2. Background & Context
### The Problem
Prior to this update, managing the context window in long-running CLI sessions was rigid. Users often faced two extremes:
1.  **Infinite Context:** The CLI remembered everything, eventually consuming the model's token limit, increasing latency, and driving up costs.
2.  **No Context:** Implementing a "fresh start" often required restarting the CLI entirely.

### The Solution
Based on community feedback and the PR implementation, this change solves the "context drift" and token consumption issues. By allowing users to limit turns (e.g., "only remember the last 5 interactions"), developers can maintain a relevant "working memory" without overloading the context window.

The addition of `settings.json` support implies a move towards more professional, reproducible workflow configurations, allowing teams to share standard setups (e.g., a "strict" config for testing distinct queries vs. a "chat" config for brainstorming).

## 3. How-To Guide

### Method A: Interactive Settings (The Easy Way)
For on-the-fly changes during a session:

1.  **Open the Menu**: inside the CLI, type:
    ```bash
    /settings
    ```
2.  **Navigate**: Look for the new **"Conversation Turns"** or **"History"** option.
3.  **Select a Mode**:
    *   **Enable**: Keeps history active (standard chat behavior).
    *   **Disable**: Switches to "Stateless" mode. The model treats every prompt as a brand new interaction.
    *   **Limit**: You will be prompted to enter a number (e.g., `5`). The model will only remember the last 5 exchanges.

### Method B: Advanced Configuration (The Power User Way)
To make these changes persistent across sessions, edit your global `settings.json` file.

1.  Locate your `settings.json` (usually in `~/.gemini-cli/` or equivalent config path).
2.  Add or modify the conversation configuration keys.
    *   *Note: Based on standard implementation patterns in this PR:*
    ```json
    {
      "conversation": {
        "history": true,
        "limit_turns": 10
      }
    }
    ```
    *(Set `"history": false` to disable context entirely, or adjust `limit_turns` to your preference.)*

## 4. Walkthrough / Technical Deep Dive

### The Logic Change
The size increase of **+2.64 kB** in `gemini.js` indicates the introduction of a sliding window logic mechanism within the message buffer.

**How it works under the hood:**
1.  **State Management**: The CLI maintains an array of message objects: `[{ role: 'user', parts: ... }, { role: 'model', parts: ... }]`.
2.  **Pre-Flight Check**: Before sending a new prompt to the Gemini API, the CLI now checks the `settings.json` or current session state.
3.  **Slicing**:
    *   If **Disabled**: The array is cleared or ignored; only the current prompt is sent.
    *   If **Limited (N)**: The CLI applies a slice operation, likely keeping the `system_instruction` (if present) and appending the last `N` messages from the history array.
4.  **Serialization**: The logic ensures that `settings.json` is parsed immediately upon CLI initialization, overriding defaults but allowing runtime overrides via `/settings`.

### Sandbox Integrity
The file list confirms that while the core logic (`gemini.js`) changed, the security sandbox definitions (`.sb` files) remained untouched. This ensures that while the *memory* capability of the tool has expanded, the *permissions* (file access, network scope) remain secure and consistent with previous versions.

## 5. Next Steps for Demos

As a Developer Advocate, here are three high-impact demos you can record to showcase this feature:

**Demo 1: The "Goldfish" Test (Stateless Mode)**
*   **Setup**: Use `/settings` to **Disable** turns.
*   **Action**: Tell Gemini, "My name is [Name]."
*   **Action**: Immediately ask, "What is my name?"
*   **Result**: Gemini will not know.
*   **Takeaway**: Demonstrate how to test prompts in isolation without context pollution.

**Demo 2: The "Sliding Window" (Limit Mode)**
*   **Setup**: Set the limit to **2 turns**.
*   **Action**: Provide 3 distinct facts in 3 separate prompts.
*   **Action**: Ask about the 1st fact.
*   **Result**: Gemini will have "forgotten" the 1st fact but remembers facts 2 and 3.
*   **Takeaway**: Show how to manage token usage while keeping recent context alive.

**Demo 3: Config Persistence**
*   **Setup**: Edit `settings.json` to hardcode a limit.
*   **Action**: Boot the CLI and type `/settings`.
*   **Result**: Show that the menu reflects the value set in the JSON file.
*   **Takeaway**: Demonstrate how developers can create standard environments for their teams.
