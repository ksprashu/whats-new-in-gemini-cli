# 🚀 What's New: Agent Skills & Remote Architectures

**Date:** October 26, 2023
**Release Version:** [Latest Version]
**Contributors:** @NTaylorMullen, @adamweidman

## 1. Feature Summary
This release transforms the Gemini CLI from a standalone tool into an extensible platform for AI orchestration. We are introducing **Agent Skills**, a new framework that allows users to modularly add specialized expertise to the CLI.

Simultaneously, we have deployed infrastructure for **Remote Agents**. This allows the Gemini CLI to delegate tasks to externally hosted AI services (such as those on Vertex AI Agent Engine) using the Agent-to-Agent (A2A) protocol. Whether the intelligence lives locally on your machine or in the cloud, Gemini CLI can now coordinate it seamlessly.

## 2. Background & Context
Prior to these changes, the Gemini CLI’s capabilities were largely defined by its core codebase or monolithic configurations. As usage grew, two specific needs emerged from the community and internal teams:

*   **The Need for Modular Expertise (PR #15869):** Users wanted to "turn on" specific personas or capabilities (like an API Auditor or a Security Scanner) without loading every possible tool into the global context. We needed a way for extensions to bundle these capabilities and for users to discover and manage them dynamically.
*   **The Need for Distributed Automation (PR #16013):** Not all agents should run locally. Some require massive context windows, specialized hardware, or integration with secure cloud environments. The CLI needed a standard protocol to "proxy" requests to these remote brains while maintaining conversational state.

These updates bridge the gap, effectively turning the Gemini CLI into a flexible interface for both local utilities and distributed AI agents.

## 3. How-To Guide

### Managing Agent Skills
We have introduced a suite of commands to manage skills directly from the terminal.

**List available skills:**
```bash
gemini skills list
```

**Enable a specific skill:**
```bash
gemini skills enable <skill-name>
```

**Disable a skill:**
```bash
gemini skills disable <skill-name>
```

**Interactive Management:**
You can also manage skills via the TUI (Text User Interface). Simply run the settings command inside an interactive session:
```text
/settings
```
*Navigate to the new "Agent Skills" section to toggle skills on or off visually.*

### Configuring Remote Agents
To connect to a remote agent (e.g., hosted on Agent Engine), you need to update your `agents.toml` configuration file.

**Example `agents.toml` setup:**
```toml
[[agent]]
name = "EnterpriseSQLHelper"
kind = "remote"  # New kind supported
url = "https://your-agent-endpoint.com/v1/query"
```

### Hot Reloading
Did you add a new skill or update a configuration file? You no longer need to restart the CLI.
```text
/skills reload
```
*Or programmatically via `reloadSkills` in the core configuration.*

## 4. Walkthrough / Technical Deep Dive

### The Agent Skills Framework (PR #15869)
The new architecture allows extensions to **bundle** their own Agent Skills. This creates a hierarchy of precedence where the CLI aggregates skills from core, user configuration, and installed extensions.

*   **Discovery:** The system scans for skills at startup.
*   **Toggle State:** Activation states are persisted, meaning if you disable a noisy skill, it stays disabled across sessions.
*   **Documentation:** A new "Getting Started" tutorial has been added to the docs, exemplified by an `API Auditor` skill, teaching developers how to build their own.

### Remote Agent Infrastructure (PR #16013)
This is a significant under-the-hood upgrade enabling the **Agent-to-Agent (A2A) protocol**.

1.  **RemoteAgentInvocation:** A new tool invocation type acts as a proxy. When the CLI decides to use a remote agent, it doesn't execute logic locally; it serializes the request.
2.  **Context Persistence:** The CLI manages `contextId` and `taskId` to ensure the remote agent remembers previous turns in the conversation.
3.  **Protocol Adapter:** A specialized fetch adapter (`createAdapterFetch`) was built to bridge the gap between the CLI (TypeScript/JS) and common remote agent backends (often Python ADK). It handles:
    *   Dialect mapping (request/response normalization).
    *   Task state enum conversion.
4.  **Authentication:** Security is handled via an **ADCHandler** (Application Default Credentials), ensuring that calls to Google Cloud-hosted agents are authenticated automatically using your local gcloud credentials.

## 5. Next Steps for Demos

To showcase these features effectively in a video or live demo, I recommend the following three scenarios:

1.  **The "Skill Store" Experience:**
    *   Start with a bare-bones CLI.
    *   Run `/settings`, enable a "Code Reviewer" skill.
    *   Immediately show the CLI performing a complex review that it couldn't do seconds prior.
    *   *Highlight:* Ease of extensibility.

2.  **The "Hybrid" Hand-off:**
    *   Ask the CLI a local question (e.g., "What files are in this folder?").
    *   Then, ask a heavy-duty question requiring a Remote Agent (e.g., "Query the production database for last week's logs using the EnterpriseSQLHelper agent").
    *   Show the logs indicating the switch from local execution to the `RemoteAgentInvocation`.
    *   *Highlight:* Seamless delegation to the cloud.

3.  **Hot Reloading Development Loop:**
    *   Open the code for a custom skill in an IDE.
    *   Modify the skill's prompt or logic.
    *   Run `/skills reload` in the running CLI.
    *   Demonstrate the behavior change immediately.
    *   *Highlight:* Developer experience and speed.
