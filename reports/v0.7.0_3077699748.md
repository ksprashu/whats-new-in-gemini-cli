# What’s New: Experimental "Todos" for Complex Task Management

**Date:** October 26, 2023
**Feature Status:** 🧪 Experimental
**Contributor:** @anj-s

---

## 1. Feature Summary
The Gemini CLI has introduced a new experimental feature designed to enhance performance on complex, multi-step workflows. Dubbed **"Experimental Todos,"** this feature allows the Gemini model to create, track, and display a managed checklist of tasks during execution.

When enabled, the CLI does not just stream text; it visualizes the model’s plan, checking off items as they are completed and modifying the plan dynamically if requirements change.

## 2. Background & Context
**The Problem:**
Large Language Models (LLMs) are excellent at reasoning, but during long-running or multifaceted tasks (e.g., "Refactor this entire directory" or "Analyze these 5 SQL files and generate a report"), they can suffer from "drift." They may skip steps, lose context, or fail to adhere to the original order of operations.

**The Solution:**
According to the discussion in **PR #8761**, this feature introduces a mechanism to ground the model. While it may seem counterintuitive that a "noop" (No Operation) tool—one that doesn't actually touch the file system or run code—would improve performance, the impact is cognitive rather than mechanical.

By forcing the model to utilize a specific tool to "write down" its plan, we achieve two goals:
1.  **Forced Planning:** It encourages the model to formulate a concrete strategy before executing code.
2.  **State Management:** It encourages the model to explicitly update its plan as tasks are completed or realized to be obsolete.

As noted in the PR review, while system prompts can encourage planning, providing a specific tool structure yields a stronger "performance impact" by formalizing the reasoning loop.

## 3. How-To Guide

Because this feature is currently **experimental**, it is disabled by default. You must explicitly opt-in via your configuration.

### Step 1: Enable the Feature
Add the following key-value pair to your Gemini CLI configuration file (e.g., `config.json` or within your project-specific settings):

```json
{
  "useWriteTodos": true
}
```

### Step 2: Prompting for Complex Tasks
This feature shines when the model recognizes a task requires multiple steps.

**Example Prompt:**
```bash
gemini "Review the src/utils directory. For every TypeScript file, add JSDoc comments to exported functions and create a corresponding unit test file in tests/utils."
```

### Step 3: Observing the Output
Once the process begins, instead of a raw stream of text, you should see a structured list appear in your terminal that updates in real-time:

```text
> Planning execution...
[ ] Read files in src/utils
[ ] Generate JSDoc for dateHelper.ts
[ ] Create tests/utils/dateHelper.test.ts
[ ] Generate JSDoc for stringFormatter.ts
[ ] Create tests/utils/stringFormatter.test.ts
```
*As the model proceeds, these checkboxes will turn to `[x]`.*

## 4. Walkthrough / Technical Deep Dive

Technically, the "Todos" feature operates as a **Tool Use** (Function Calling) implementation.

1.  **The "Noop" Tool:** The CLI exposes a tool definition to the model (let's call it `manage_todos`). This tool accepts arguments describing a list of tasks and their status (pending/done).
2.  **The Reasoning Loop:**
    *   **Input:** The user asks for a complex refactor.
    *   **Thought:** The model analyzes the request and determines it cannot be done in one shot.
    *   **Action:** The model calls the `manage_todos` tool to register an initial plan.
    *   **Execution:** The CLI renders this state to the user. The tool returns "success" to the model (acting as a no-op).
    *   **Work:** The model performs the first actual task (e.g., `fs.readFile`).
    *   **Update:** The model calls `manage_todos` again to mark item #1 as complete.
3.  **Why this works:** By externalizing the state of the task list, the model is constantly reminded of what it has done and what remains. It reduces the context burden of "remembering" where it is in the process, shifting that burden to the tool history.
