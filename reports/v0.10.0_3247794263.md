# What’s New: Granular Diff Telemetry for File Operations

**Release:** Gemini CLI Update
**Tracking:** [PR #10819](https://github.com/google-gemini/gemini-cli/pull/10819), [Issue #9220](https://github.com/google-gemini/gemini-cli/issues/9220)
**Contributor:** @jerop

---

## 1. Feature Summary
We are introducing enhanced observability for file-modifying tools within the Gemini CLI. This update integrates detailed **Diff Statistics** into our OpenTelemetry (OTEL) pipeline.

Specifically, the CLI now tracks the exact number of lines added or removed by the **AI Model** versus the number of lines modified by the **User** during the same operation. These insights are captured as attributes within the `gemini_cli.tool.call.count` metric, allowing developers and platform admins to measure the actual utility and accuracy of AI-generated code changes.

---

## 2. Background & Context
**The Problem:**
Previously, our telemetry could tell us *that* a file-editing tool was used, but it lacked insight into the *quality* of that interaction. We couldn't easily distinguish between a scenario where the AI wrote perfect code (accepted as-is) and a scenario where the AI suggested code that the user had to completely rewrite.

**The Solution:**
To bridge this gap, PR #10819 introduces logic to calculate line-by-line differences during the tool execution lifecycle. By decoupling "Model Changes" from "User Changes," we provide a data-driven way to answer questions like:
*   *How often do users accept AI suggestions without modification?*
*   *Which prompts result in the heaviest user-side refactoring?*

This change shifts our analytics from simple "Usage Counting" to "Impact Measurement."

## 3. How-To Guide
Because this feature is part of the CLI's internal telemetry system, it works out of the box for any user with telemetry enabled. Here is how to verify and utilize the data.

### Step 1: Ensure Telemetry is Enabled
Ensure your environment is configured to export OTEL data.
*(Note: If you are running the CLI locally without a collector, you may not see these metrics, but they are generated internally.)*

### Step 2: Perform a File Operation
Run a command that triggers a file modification.
```bash
gemini edit src/main.py --prompt "Add a logging function to the start of the script"
```

### Step 3: Review/Accept Changes
*   If the model proposes 5 lines of code.
*   And you edit 1 line before saving.
*   The telemetry event is triggered upon completion.

### Step 4: Visualize (For Admins/Maintainers)
In your observability backend (e.g., Prometheus, Grafana, Honeycomb), query the `gemini_cli.tool.call.count` metric. You can now filter or group by the new attributes to visualize "AI vs. Human" code contribution ratios.

## 4. Walkthrough / Technical Deep Dive
The implementation hooks into the `gemini_cli.tool.call.count` metric instrumentation. Here is how the data flow operates under the hood:

1.  **Baseline Capture:** When a tool is invoked (e.g., `edit_file`), the CLI records the initial state of the file.
2.  **Model Proposal:** The LLM generates a proposed change. The system calculates the diff between the *Original* and the *Model Proposal*.
3.  **User Interaction:** If the tool allows for interactive review, the user may apply edits to the proposal.
4.  **Final Diff Calculation:** The system calculates the final diff attributes based on the final saved state.

### New OTEL Attributes
The following optional attributes are now attached to the metric:

| Attribute Name | Description | Data Type |
| :--- | :--- | :--- |
| `model_added_lines` | Number of lines introduced purely by the AI. | Integer |
| `model_removed_lines` | Number of lines deleted purely by the AI. | Integer |
| `user_added_lines` | Number of lines added by the human user during review. | Integer |
| `user_removed_lines` | Number of lines deleted by the human user during review. | Integer |

**Technical Logic:**
By analyzing the delta between `model_added_lines` and `user_removed_lines`, we can mathematically derive an "Acceptance Rate." For example, if `model_added_lines = 10` and `user_removed_lines = 0`, the acceptance rate is 100%.
