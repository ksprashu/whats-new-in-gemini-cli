# 🚀 What's New: Endor Labs Extension for Gemini CLI

**Date:** October 26, 2023
**Version:** Extension Release `v1.0`
**Component:** Extensions / Security

## 1. Feature Summary
The Gemini CLI ecosystem now supports **Endor Labs** via a new first-party extension. This integration brings supply chain security, vulnerability scanning, and dependency analysis directly into your terminal, accessible through natural language prompts.

Instead of parsing complex JSON logs or navigating external dashboards, developers can now simply ask Gemini to "check for vulnerabilities" or "analyze dependency health," and the CLI will leverage Endor Labs' reachability analysis to provide context-aware security insights.

## 2. Background & Context
### The Problem
Modern software development relies heavily on open-source dependencies. Traditionally, checking these dependencies for security risks involves:
*   Context switching to web dashboards.
*   Running rigid CI/CD pipeline scanners that produce verbose, hard-to-read logs.
*   Dealing with "noise"—alerts for vulnerabilities in functions that the code doesn't even actually use (false positives).

### The Solution
By wrapping Endor Labs' API in a Gemini CLI extension, we are "shifting left" more effectively.
*   **Conversational Security:** The integration allows developers to have a dialogue about security. You don't just get a list of CVEs; you get an explanation of *why* a package is risky and *how* to fix it.
*   **Workflow Integration:** It meets the developer where they are—in the terminal—reducing friction for running ad-hoc security checks before committing code.

## 3. How-To Guide

### Prerequisites
*   Gemini CLI installed and authenticated.
*   An active Endor Labs account.
*   Endor Labs API credentials (configured via environment variables, e.g., `ENDOR_NAMESPACE`, `ENDOR_API_KEY`).

### Step 1: Install the Extension
Use the Gemini CLI extension manager to pull the integration directly from the repository.

```bash
gemini extensions install https://github.com/endorlabs/gemini-extension
```

### Step 2: Verification
Verify the extension is active and ready to accept prompts.

```bash
gemini extensions list
# You should see 'endorlabs' in the active list
```

### Step 3: Natural Language Workflows
Once installed, you can interact with Endor Labs using natural language. Here are three common patterns:

**A. General Health Check**
> "Analyze the current directory for security vulnerabilities using Endor Labs."

**B. Specific Dependency Query**
> "Does my project rely on any deprecated versions of 'lodash', and are they reachable?"

**C. Remediation Advice**
> "I have a critical vulnerability in 'requests'. How do I upgrade it safely without breaking changes?"

## 4. Walkthrough / Technical Deep Dive

### How it Works Under the Hood
This feature utilizes the **Gemini Function Calling** architecture.

1.  **Intent Recognition:** When you type a prompt like *"Scan for bugs,"* the Gemini CLI's router identifies that this request requires external domain knowledge regarding security.
2.  **Tool Execution:** The CLI invokes the Endor Labs extension. The extension utilizes the `endorctl` (or direct API calls) to perform a scan of the manifest files (e.g., `package.json`, `go.mod`, `pom.xml`) located in the working directory.
3.  **Reachability Analysis:** Unlike standard scanners that just match versions to a CVE database, Endor Labs analyzes the call graph. It determines if your code *actually imports and uses* the vulnerable function.
4.  **LLM Synthesis:** The raw JSON data returned by Endor Labs (containing CVE IDs, risk scores, and reachability flags) is fed back into the Gemini context window.
5.  **Human-Readable Output:** Gemini synthesizes this technical data into a summary, prioritizing "Reachable" vulnerabilities and filtering out noise, providing the user with a clean, actionable summary.

## 5. Next Steps for Demos

If you are creating a video or live demo for this feature, I recommend utilizing the following **"Hero Scenarios"**:

### Demo Arc 1: The "Noise Reduction" (Reachability)
*   **Setup:** Use a project with a known vulnerability in a library, but ensure the code *does not* call the vulnerable function.
*   **Action:** Ask Gemini: "Do I have any reachable vulnerabilities?"
*   **Payoff:** Show that while a standard audit might panic, the Endor/Gemini integration correctly identifies that the risk is low/unreachable, saving the developer time.

### Demo Arc 2: The Conversational Fix
*   **Setup:** A project with a reachable critical CVE.
*   **Action:**
    1.  User: "Scan project." -> Gemini identifies the CVE.
    2.  User: "Explain why this is dangerous and suggest a fix."
*   **Payoff:** Showcase the LLM explaining the specific attack vector (e.g., "This allows Remote Code Execution via deserialization...") and providing the specific upgrade command (e.g., `npm install package@x.y.z`).

### Demo Arc 3: Project Health/Score
*   **Action:** Ask: "What is the operational risk of using this open source project?"
*   **Payoff:** Have Endor return metrics on the library's maintenance (e.g., "This library hasn't been updated in 2 years and has no active maintainers"), demonstrating that security is about more than just CVEs—it's about software hygiene.
