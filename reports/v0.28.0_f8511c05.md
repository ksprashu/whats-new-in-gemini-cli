## The Headline
The Gemini CLI has received a significant visual intelligence upgrade, transforming how it integrates with developer environments. In a move to reduce visual friction, the tool now features an adaptive theming engine that automatically synchronizes with the user's terminal background. Rather than forcing a static color palette, the CLI detects whether the terminal is in light or dark mode and adjusts its contrast accordingly. Furthermore, the ecosystem has been opened up to designers and plugin creators: extensions can now ship with their own custom themes, allowing for a fully immersive, branded, or accessible experience that goes beyond the default settings.

## Quick Start / How to Try It Out
Users can experience these changes immediately without complex configuration, as the adaptive features are enabled by default for standard themes.

*   **Automatic Switching:**
    *   Simply open your terminal settings and change the background color from black to white (or vice versa).
    *   Wait approximately 3 seconds. The Gemini CLI will detect the luminance change and swap the interface between 'Default' (Dark) and 'Default Light'.
*   **Extension Themes:**
    *   Install an extension that includes a `themes` definition in its manifest.
    *   Navigate to the theme selection menu (typically accessed via settings or configuration prompts) to select the newly imported styles.

## Use Cases (Why you need this)
*   **Seamless Day/Night Cycles:** Developers who rely on OS-level "Auto" appearance settings (switching to Dark Mode at sunset) no longer need to manually reconfigure the CLI to maintain legibility.
*   **Corporate Branding & Design Systems:** Internal platform teams can now distribute a Gemini CLI extension that forces the tool to adhere to specific company color palettes or accessibility contrast requirements.
*   **Contextual Switching:** Users working in different environments (e.g., a "Production" terminal with a red background vs. "Dev" with green) will find the CLI automatically adjusting text contrast to remain readable against the backdrop.

## What to Expect (Things to Look Out For)
*   **Polling Delay:** The automatic background detection polls the terminal every 3 seconds. Users should expect a momentary delay between changing their terminal background and seeing the CLI update.
*   **Stability Logic:** To prevent the interface from flickering "disco-style" when a background color is on the borderline between light and dark, the system uses hysteresis. It requires a significant shift in luminance (thresholds at 140 for light, 110 for dark) to trigger a switch.
*   **Scope:** Auto-switching specifically targets the `Default` and `Default Light` themes. Custom or hard-coded themes may not react to terminal background changes.

## Technical Deep Dive (Admin)
The architecture behind these updates involves two distinct engineering efforts: a refactor of the `ThemeManager` and the implementation of OSC 11 polling.

**Automatic Theme Switching:**
This feature relies on the **OSC 11 escape sequence**, which queries the terminal for its background color. The CLI polls this value every 3 seconds.
*   **Luminance Calculation:** Raw X11 RGB color strings are parsed into hex and then processed through WCAG 2.0 relative luminance formulas.
*   **Hysteresis Implementation:** To ensure stability, the engineering team implemented a hysteresis loop. The system will only switch to a light theme if luminance exceeds 140, and only revert to dark if it drops below 110. This prevents rapid toggling in mid-tone environments.

**Extension Theme Architecture:**
The `ExtensionManager` has been upgraded to scan `gemini-extension.json` files for a new `themes` property.
*   **Namespacing:** The `ThemeManager` was refactored to handle themes from multiple sources (User, Extension, File). It now applies proper namespacing to extension-contributed themes to prevent naming collisions (e.g., two extensions both trying to register a theme named "Dracula").
*   **Core Migration:** The `CustomTheme` interface was relocated to `@google/gemini-cli-core`. This exposes the type definition to extension developers, ensuring type safety and easier integration for third-party contributors.
*   **Lifecycle Management:** Themes are automatically registered upon extension activation and unregistered upon deactivation, ensuring the theme registry remains clean.

## Background & Context (Admin)
Prior to this release, the Gemini CLI's visual appearance was static. If a user's environment changed—common in modern workflows where IDEs and OSs toggle between light and dark modes based on time of day—the CLI could become unreadable (e.g., white text on a white background). This created friction and required manual intervention.

Additionally, the extension ecosystem was limited to functionality. Developers could add commands but not visual styles. By decoupling themes from the core binary and allowing extensions to inject them, the maintainers have aligned the Gemini CLI with modern extensible tools like VS Code, where "Theme Packs" are a popular category of community contribution.
