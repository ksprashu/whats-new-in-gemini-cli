# What’s New: Gemini 3 Support for Zed Users

## 1. Feature Summary
We are excited to announce that **Gemini 3 is now available within the Zed editor integration**. Previously limited to standard CLI workflows, the advanced capabilities of the Gemini 3 model can now be accessed directly within Zed. This update unifies the model selection logic between the Gemini CLI Core and the Zed integration, ensuring that Zed users always have access to the latest models and preview features as soon as they are available.

## 2. Background & Context
**The Problem:**
Prior to this update, the Zed integration relied on a custom, isolated function (`resolveModel`) to determine which AI model to use. This created a disconnect between the core CLI capabilities and the Zed extension. When new models (like Gemini 3) were introduced to the Core CLI behind feature flags, the Zed integration couldn't automatically "see" or utilize them because its logic was hardcoded and separate.

**The Solution (PR #13398):**
The engineering team refactored the Zed integration to abandon its custom logic. Instead, it now adopts the shared `getEffectiveModel` utility from the `@google/gemini-cli-core`.

**Why this matters:**
*   **Consistency:** Zed now behaves exactly like the core CLI regarding model selection.
*   **Future-Proofing:** As we add new preview models to the CLI Core, Zed users will gain access to them instantly without requiring specific updates to the Zed integration code.
*   **Technical Debt:** We removed redundant code, making the extension lighter and easier to maintain.

## 3. How-To Guide
To start using Gemini 3 in Zed, you need to enable the feature flag within your CLI configuration.

**Prerequisites:**
*   Ensure you are running the latest version of the Gemini CLI.
*   Ensure you have the Zed integration installed.

**Steps:**
1.  **Open Settings:** Navigate to your CLI settings page (accessible via `/settings`).
2.  **Enable Preview Features:** Locate the **"Preview Features"** toggle and switch it to **ON**.
3.  **Launch Zed:** Open the Zed editor. The integration will now automatically detect the configuration change and route your queries through the Gemini 3 model.

*> **Note:** If you wish to revert to the stable model, simply toggle "Preview Features" off in your settings. No restart is required.*

## 4. Walkthrough / Technical Deep Dive
For those interested in the architecture, here is how the refactor works under the hood.

### Before (The Old Way)
The Zed integration used a standalone function called `resolveModel`. This function contained static logic determining which model to use. It was unaware of the broader CLI configuration regarding "Preview" states.

```javascript
// Pseudo-code of the old logic
function resolveModel() {
  // Hardcoded logic
  return "gemini-1.5-pro"; 
}
```

### After (The New Way)
The integration now imports `getEffectiveModel` directly from the Core library. This utility is the "brain" of model selection for the entire platform.

```javascript
import { getEffectiveModel } from '@google/gemini-cli-core';

// Inside the request handler
const model = getEffectiveModel(userConfig); 
// If userConfig.previewFeatures is true -> returns "gemini-3.0"
// If userConfig.previewFeatures is false -> returns "gemini-1.5-pro"
```

By delegating this decision to the Core, the Zed integration no longer needs to know *what* Gemini 3 is—it simply asks for the "effective model" based on the user's current settings. This dramatically simplifies the codebase and aligns behavior across all interfaces.
