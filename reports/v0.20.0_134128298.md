# 🚀 What's New: Seamless Multi-File Drag & Drop

**PR:** [#14832](https://github.com/google-gemini/gemini-cli/pull/14832) | **Contributor:** [@jackwotherspoon](https://github.com/jackwotherspoon)

## 1. Feature Summary
The Gemini CLI now supports robust **Multi-file Drag & Drop**. Users can select multiple files (specifically images) from their operating system's file explorer and drag them directly into the terminal window. The CLI intelligent parses the input, automatically handling file paths with spaces and prefixing every valid file path with the required `@` symbol.

## 2. Background & Context
**The Problem:**
Previously, adding visual context to a prompt was a high-friction task. Users had to manually type the path to a file or drag files in one by one. Furthermore, standard terminal behavior when dropping files usually results in a raw path string (e.g., `/Users/me/image.png`). However, the Gemini CLI specifically requires the `@` prefix (e.g., `@/Users/me/image.png`) to recognize the input as a file rather than raw text.

**The Solution:**
This update bridges the gap between the OS GUI and the CLI. By intercepting the "paste" event generated by a drag-and-drop action, the CLI now standardizes the input format automatically. This removes the need for manual cursor navigation to add prefixes or escape characters, significantly speeding up multimodal workflows.

## 3. How-To Guide

Here is how to utilize the new workflow:

1.  **Launch the CLI:** Open your terminal and start the Gemini CLI.
2.  **Select Files:** In your OS file manager (Finder, Explorer, etc.), select multiple image files.
    *   *Tip: Try selecting a file with spaces in the name, like `screenshot 1.png`.*
3.  **Drag & Drop:** Drag the selection into the active terminal window and release.
4.  **Observe the Magic:**
    *   **Before:** You would have seen raw text like `/path/to/img1.png /path/to/screenshot\ 1.png`.
    *   **Now:** The CLI instantly converts this to:
        ```bash
        @/path/to/img1.png @/path/to/screenshot\ 1.png
        ```
5.  **Prompt:** Type your prompt (e.g., "Describe the differences between these images") and hit Enter.

## 4. Walkthrough / Technical Deep Dive

This feature is more than just a simple UI binding; it involves intelligent string parsing to handle the quirks of terminal inputs.

### The `useTextBuffer` Hook
The core logic resides in an update to the `useTextBuffer` hook. When a user drops files, the terminal interprets the action as a text paste operation. The hook now intercepts this data stream before it renders to the prompt.

### Intelligent Parsing (`splitEscapedPaths`)
Standard string splitting on "space" characters fails when filenames contain spaces (e.g., `My Document.png`).
*   The PR introduces a new utility, `splitEscapedPaths`.
*   It analyzes the incoming string for escaped spaces (backslashes followed by a space, commonly generated by terminals).
*   It correctly tokenizes the string into individual file paths, preserving the integrity of filenames with spaces.

### Validation and Prefixing
Once tokenized, the system utilizes new validation utilities (`looksLike` and `get` functions) to inspect the paths.
*   It verifies if the path points to a valid, supported file type (specifically checking for image formats).
*   If valid, it automatically prepends the `@` symbol.
*   Non-file text pasted alongside files remains untouched, allowing for mixed-content pastes.
