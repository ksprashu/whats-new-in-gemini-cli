# 🚀 Gemini CLI Update: The Extensions Ecosystem

## 1. Feature Summary
The Gemini CLI is evolving from a standalone tool into an extensible platform. With the introduction of the **`gemini extensions`** command suite, developers can now expand the CLI's capabilities beyond the core codebase.

This release introduces three critical subcommands that manage the lifecycle of external plugins:
*   **`gemini extensions install`**: Fetch and install community or verified extensions.
*   **`gemini extensions uninstall`**: Cleanly remove extensions.
*   **`gemini extensions link`**: A developer-focused command to symlink local projects into the CLI for rapid extension development.

## 2. Background & Context
**Why this change?**
As the Gemini CLI adoption grew, we identified two competing needs in our GitHub Issues and feedback channels:
1.  **Feature Bloat vs. Niche Use-Cases:** Users wanted specific integrations (e.g., specific database connectors or framework scaffolds) that were too niche to bundle into the core binary.
2.  **Velocity:** The community wanted to iterate on features faster than the core CLI release cycle allowed.

**The Solution:**
By implementing an Extensions architecture (inspired by patterns seen in the GitHub CLI and VS Code), we are decoupling "Core" from "Contrib."
*   **For Users:** This keeps the core binary lightweight while allowing power users to opt-in to complex functionality.
*   **For Developers:** The `link` command specifically addresses the "Inner Loop" problem, allowing extension authors to test their code against the actual Gemini CLI binary without rebuilding the entire CLI or messing with manual file paths.

## 3. How-To Guide

Here is how to manage your extensions using the new commands.

### Installing an Extension
To add new functionality to your environment, use the install command with a repository URL or a registered extension name.

```bash
# Syntax: gemini extensions install <repo_or_name>
gemini extensions install gemini-community/sql-generator
```
*Result: The CLI downloads the release, verifies the manifest, and makes the command available globally.*

### Developing Locally (`link`)
If you are building your own extension, you don't want to publish it just to test it. Use `link` to point the Gemini CLI to your local source code.

```bash
# 1. Navigate to your extension project
cd ~/projects/my-custom-gemini-tool

# 2. Link the current directory to the CLI
gemini extensions link .

# 3. Run your new command immediately
gemini my-custom-tool run
```

### Removing an Extension
If an extension is no longer needed or if you want to unlink a local development version:

```bash
gemini extensions uninstall sql-generator
```

## 4. Walkthrough / Technical Deep Dive

Under the hood, the `gemini extensions` command manages a specialized directory structure (typically located in `~/.config/gemini/extensions` or `~/.gemini/extensions`).

**The `install` Process:**
1.  **Resolution:** The CLI resolves the argument to a GitHub repository or registry entry.
2.  **Fetch:** It downloads the appropriate binary or source script for your OS/Arch.
3.  **Manifest Parsing:** It reads a `gemini.manifest.json` (or similar) to understand which commands the extension exposes.
4.  **Registration:** These commands are added to the CLI's internal command tree at runtime.

**The `link` Mechanism:**
This is the technical highlight of this release. Instead of copying files, `link` creates a **symbolic link** from the CLI's extension directory pointing directly to your local folder.
*   **Hot Reloading:** Because it is a symlink, changes you make to your code in your IDE are reflected immediately the next time you run `gemini <extension-command>`. No compilation or re-installation of the CLI is required.

**Isolation:**
Extensions run in a separate process from the core CLI. This ensures that a crashing extension does not take down the main application, providing a layer of stability and security.
