# What’s New: Interactive Model Selection in Gemini CLI

**Release:** Gemini CLI Update  
**Contributor:** @abhipatel12  
**PR Reference:** [#8940](https://github.com/google-gemini/gemini-cli/pull/8940)

---

## 1. Feature Summary

We are excited to introduce a dynamic new way to control your AI experience directly within the terminal. The Gemini CLI now supports a **`/model` slash command**, allowing users to interactively switch between different Gemini model variants (Auto, Pro, Flash, and Flash-Lite) during their session.

This update brings a dedicated Text User Interface (TUI) dialog for selection, ensuring that you can match the right model capability to your specific coding task—whether you need rapid responses or deep reasoning capabilities.

---

## 2. Background & Context

**The Problem:**
Previously, users of the Gemini CLI generally interacted with a default model configuration. If a user wanted to switch from a high-reasoning model to a low-latency model, it likely required editing configuration files manually or restarting sessions with specific flags. There was no native, in-flow mechanism to change the "brain" behind the CLI while working.

**The Solution:**
This change addresses the need for **user control and flexibility**. Different development tasks require different AI profiles:
*   **Flash/Flash-Lite:** Ideal for quick syntax lookups, boilerplate generation, or low-latency requirements.
*   **Pro:** Essential for complex architectural reasoning, debugging, and refactoring.

By introducing the `/model` command, we bridge this gap, allowing developers to context-switch their AI tools as fast as they context-switch their coding tasks.

## 3. How-To Guide

### Prerequisites
Because this feature is being rolled out in a controlled manner, you must ensure feature gating is enabled in your configuration.

1.  Open your Gemini CLI user configuration.
2.  Ensure the setting `useModelRouter` is set to `true`.

### Switching Models
Once configured, changing your model is simple:

1.  **Invoke the Command:**
    Inside your active Gemini CLI session, type the following and hit Enter:
    ```bash
    /model
    ```

2.  **Select via UI:**
    A full-screen interactive dialog will appear.
    *   Use the **Up/Down Arrow keys** to navigate the list (Auto, Pro, Flash, Flash-Lite).
    *   The dialog provides a title and description for each model to help you choose.
    *   Press **Enter** to confirm your selection.

3.  **Confirmation:**
    The CLI will persist your choice via the Config service, and subsequent prompts in the session will utilize the selected model.

## 4. Walkthrough / Technical Deep Dive

For the developers and contributors interested in the architecture of this feature, here is how PR #8940 implements it under the hood:

### The `useModelCommand` Hook
The logic is encapsulated in a new custom hook, `useModelCommand`. This creates a clean separation of concerns, handling:
*   The state of the dialog (open/closed).
*   Retrieving the current model from the configuration.
*   Persisting the new user selection back to the Config service.

### Reusable UI Components
The visual interface is built using a generic **`DescriptiveRadioButtonSelect`** component.
*   **Why this matters:** This isn't a hardcoded menu just for models. It is a reusable UI element that supports keyboard navigation, titles, and descriptions. This paves the way for future CLI settings to be adjusted via similar interactive dialogs without reinventing the wheel.

### Feature Gating Architecture
The implementation follows strict feature-flagging best practices. The `/model` command is conditionally loaded. The application checks the `useModelRouter` configuration before even registering the slash command. This ensures stability for users who do not have the feature enabled and allows for a safe, gradual rollout.
