# 🚀 Gemini CLI Update: Intelligent Terminal Background Detection

**PR Reference:** [#15132](https://github.com/google-gemini/gemini-cli/pull/15132)  
**Author:** @jacob314  
**Impact:** +9.67 kB bundle size (negligible impact)

---

## 1. Feature Summary
The Gemini CLI has introduced **Automatic Terminal Background Color Detection**. In this latest update, the CLI no longer blindly outputs colored text; instead, it intelligently queries your terminal environment to determine whether you are using a light or dark background. Based on this detection, it automatically selects the most compatible syntax highlighting theme and issues accessibility warnings if the contrast ratio is below readable standards.

## 2. Background & Context
### The Problem: The "Invisible Text" Syndrome
Before PR #15132, the Gemini CLI likely relied on default color schemes or hardcoded ANSI escape codes. This creates significant friction for developers who customize their environments. 

*   **Scenario A:** A developer using a "Solarized Light" terminal theme might see white text outputs that are invisible against the light background.
*   **Scenario B:** A developer using a high-contrast dark theme might encounter dark blue error messages that blend into the black background.

This issue (tracked in context of #14385) represents a barrier to accessibility. Developers shouldn't have to squint or manually configure color flags just to read logs or generative outputs.

### The Solution
By adding logic to detect the background luminance, the CLI ensures that the output is legible regardless of the user's setup (e.g., iTerm2, VS Code Terminal, standard macOS Terminal).

## 3. How-To Guide

The beauty of this feature is that it is **zero-configuration**. It works out of the box.

### Usage
Simply run your standard Gemini CLI commands.

```bash
# Run a standard prompt
gemini prompt "Explain how a binary search tree works"
```

### Observing the Behavior
1.  **Open your Terminal settings.**
2.  **Change your profile** to a "Light" theme (e.g., white background).
3.  **Run a command.** Notice that code snippets and text automatically shift to darker colors to maintain contrast.
4.  **Change your profile** to a "Dark" theme (e.g., black or dark grey background).
5.  **Run the command again.** Notice the text shifts to pastels or bright colors for readability.

### Accessibility Warnings
If you are using a terminal background color that is mathematically difficult to support (e.g., a mid-grey that conflicts with both white and black text), the CLI will now output a warning:

> ⚠️ **Warning:** Terminal background contrast is low. Please adjust your terminal theme for optimal readability.

## 4. Walkthrough / Technical Deep Dive

### Implementation Analysis
Based on the file changes in `./bundle/gemini.js` (an increase of ~9KB), the implementation likely utilizes a query-response mechanism standard in modern CLI tools.

1.  **OSC Querying:** The CLI likely sends an **OSC 11** (Operating System Command) escape sequence to the terminal.
    *   *Sequence:* `\x1b]11;?\x07`
    *   *Meaning:* "Hey Terminal, report back your background color."
2.  **Asynchronous Parsing:** The terminal responds via `stdin` with an RGB or Hex string (e.g., `rgb:0000/0000/0000`).
3.  **Luminance Calculation:** The CLI parses this response and calculates the **relative luminance**.
    *   If Luminance > 0.5 (Light Mode) → Load `light-theme.json` (darker text colors).
    *   If Luminance < 0.5 (Dark Mode) → Load `dark-theme.json` (lighter text colors).
4.  **Fallback Strategies:** For terminals that do not support OSC queries (or if the query times out), the CLI likely defaults to a safe, neutral palette or checks environment variables (like `COLORFGBG`).

### Sandbox Considerations
The changelog notes several unchanged sandbox files (`.sb` extensions). This indicates that while the logic for *rendering* changed, the security permissions required to run the CLI on macOS (files like `sandbox-macos-restrictive-closed.sb`) did not need modification. The background detection operates strictly within standard standard input/output streams.
