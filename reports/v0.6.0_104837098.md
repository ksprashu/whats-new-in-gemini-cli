# 🚀 What’s New: Interactive Loop Detection Management

**PR Reference:** [#8231](https://github.com/google-gemini/gemini-cli/pull/8231)  
**Author:** @SandyTao520  
**Impact:** +3.66 kB to bundle size (Minor)

---

## 1. Feature Summary
The Gemini CLI has improved its safety mechanisms regarding infinite loops. Previously, loop detection might have strictly halted execution or required a configuration restart. With this update, the CLI now introduces an **interactive confirmation dialog**.

When the system detects a potential infinite loop (e.g., Agent A calling Agent B, who calls Agent A recursively), the CLI will pause execution and present the developer with a choice: **Disable loop detection for the current session** or abort. This puts control back in the hands of the developer, allowing for intentional recursive workflows while preventing accidental token burns.

---

## 2. Background & Context
**The Problem:**
In complex agentic workflows, "loops" are not always bugs. While infinite loops are generally dangerous (leading to high API costs and stalled processes), recursive logic—such as "Refine this code until it passes tests"—is a valid use case.

Prior to this change, strict loop detection could result in:
*   **False Positives:** Valid recursive workflows being blocked automatically.
*   **Frustrating UX:** Users having to restart the CLI with different flags or configurations to bypass safety checks.

**The Solution:**
By moving to a "User-in-the-Loop" confirmation model, the CLI solves the ambiguity problem. The software no longer assumes every loop is an error; instead, it flags the anomaly and asks the human operator for context. This aligns with the Developer Experience (DX) goal of making the CLI a more flexible tool for advanced prompting strategies.

## 3. How-To Guide

Here is how you can trigger and interact with the new feature.

### Prerequisites
Ensure you are running the latest version of the Gemini CLI containing PR #8231.

### Step 1: Create a Recursive Scenario
Define a scenario where two agents or prompts depend on each other cyclically. For example:
*   **Agent 1:** "Ask Agent 2 for a review."
*   **Agent 2:** "Ask Agent 1 for a revision."

### Step 2: Execute the Command
Run your standard Gemini CLI command to initiate the workflow.

```bash
gemini run --file recursive-workflow.yaml
```

### Step 3: Handle the Dialog
When the CLI detects that the execution path has entered a loop, the process will pause, and you will see a prompt similar to this:

```text
⚠️ Loop Detected: The workflow appears to be repeating steps [Step A -> Step B -> Step A].

? Do you want to disable loop detection for this session? (Y/n)
```

*   **Select `Yes`:** The CLI will ignore this loop and any future loops for the duration of this session, allowing the recursion to continue until your defined exit criteria are met.
*   **Select `No`:** The CLI will terminate the process to save resources.

## 4. Walkthrough / Technical Deep Dive

While the bundled code change in `gemini.js` is relatively small (+3.66 kB), it represents a significant shift in the runtime execution flow.

**Under the Hood:**
1.  **State Tracking:** The CLI maintains a stack or history of executed nodes/prompts.
2.  **Pattern Matching:** Before executing the next step, the engine compares the proposed step against the history stack. If a repeating sequence (e.g., A-B-A) is identified, the `LoopDetected` event is triggered.
3.  **The Interceptor:** Previously, this event likely threw a fatal error. The new logic injects an **interactive middleware**.
    *   It suspends the `async` execution flow.
    *   It renders the CLI UI dialog (likely using a library like `inquirer` or `prompts`, accounting for the slight bundle size increase).
4.  **Session Flags:** If the user approves the loop, a flag (e.g., `DISABLE_LOOP_CHECK = true`) is set in the runtime memory. The engine then bypasses step 2 for the remainder of the process lifecycle.

**Performance Impact:**
The size increase (+0.03%) is negligible. The logic only triggers when a loop is actually found, meaning there is zero latency penalty for standard, non-recursive operations.
