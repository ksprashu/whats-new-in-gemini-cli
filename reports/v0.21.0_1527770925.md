# 🚀 What's New: Gemini CLI Extensions (Rill & Browserbase)

The Gemini CLI is evolving from a text-generation tool into an agentic command center. With the latest update, we have introduced support for two powerful extensions via the **Model Context Protocol (MCP)**: **Rill** for operational intelligence and **Browserbase** for headless web automation.

## 1. Feature Summary
This release introduces seamless integration with external developer tools directly from your terminal.

*   **Rill Extension:** Allows developers and data analysts to query Rill dashboards using natural language. You can explore metrics, dimensions, and trends without writing a single line of SQL or navigating the UI.
*   **Browserbase Extension:** Equips Gemini with a headless browser. It can navigate URLs, take screenshots, extract text from complex JavaScript-heavy sites, and perform automated interaction logs.

## 2. Background & Context
*Why was this change made?*

As the Gemini CLI matures, a recurring theme in user feedback (and internal GitHub discussions) is the "Context Gap." LLMs are powerful, but they are isolated from the developer's runtime environment and live data.

*   **The Data Friction Problem:** Previously, to analyze data in Rill, a user had to leave the terminal, open the Rill UI, filter views, export data, and paste it back into Gemini for analysis. This context switching breaks flow. The **Rill Extension** solves this by exposing Rill's semantic layer directly to the CLI.
*   **The Live Web Problem:** Standard LLM web scraping is often blocked by anti-bot measures or fails on client-side rendered (CSR) applications. **Browserbase** offers a robust, server-side infrastructure for browser automation. Integrating this enables Gemini to "see" and "act" on the web with the reliability of a headed browser session, useful for QA testing and data extraction tasks.

## 3. How-To Guide

Here is how to set up and utilize the new extensions.

### Prerequisite
Ensure you have the latest version of the Gemini CLI installed.

### 📊 Setting up Rill
1.  **Install the Extension:**
    Run the following command in your terminal:
    ```bash
    gemini extensions install https://github.com/rilldata/rill-gemini-extension
    ```
2.  **Usage:**
    Once installed, you can simply ask questions about your running Rill projects.
    ```bash
    gemini "Show me the total revenue for last week broken down by product category."
    ```
    *Gemini will interpret the intent, query the Rill metrics layer, and return a summarized text answer along with the data table.*

### 🌐 Setting up Browserbase
1.  **Install the Extension:**
    ```bash
    gemini extensions install https://github.com/browserbase/mcp-server-browserbase
    ```
2.  **Configuration:**
    You will likely need to export your Browserbase API key (check the repo `README` for specific environment variable names, usually `BROWSERBASE_API_KEY`).
3.  **Usage:**
    Instruct Gemini to perform browser actions.
    ```bash
    gemini "Go to news.ycombinator.com, take a screenshot, and list the top 3 headlines."
    ```

## 4. Walkthrough / Technical Deep Dive

These integrations are made possible by the **Model Context Protocol (MCP)**. Here is what happens "under the hood" when you run a command:

1.  **Tool Discovery:** When you start the Gemini CLI, it handshakes with the installed extensions (Rill and Browserbase). These extensions act as MCP Servers, broadcasting a list of available **Tools** (e.g., `rill_query_metrics`, `browserbase_navigate`, `browserbase_screenshot`) to the Gemini CLI (the MCP Client).
2.  **Intent Recognition:** When you type *"Analyze trends in Rill,"* the Gemini model analyzes the prompt and recognizes that it cannot answer from its training data. It determines that the `rill_query_metrics` tool is required.
3.  **Tool Execution:**
    *   The CLI sends a structured request to the Rill extension.
    *   The Rill extension translates this into a specific query against the Rill semantic layer (leveraging Rill's rigorous metric definitions).
    *   The raw data JSON is returned to the CLI.
4.  **Synthesis:** Gemini takes the raw JSON result and synthesizes it into a human-readable response for your terminal output.

**Why this architecture matters:** It decouples the model from the tool logic. If Rill updates their API or Browserbase adds new navigation features, the extension is updated, but the core Gemini CLI remains stable.
