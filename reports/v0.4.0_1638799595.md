# 🚀 What's New in Gemini CLI: Embedded Context in Custom Commands

**Release Update** | **Pull Request:** #6716 | **Issue:** #6651

## 1. Feature Summary
The Gemini CLI has introduced a powerful new syntax for **Custom Commands**. You can now embed the content of local files or entire directories directly into your saved custom command prompts using the `@{path}` syntax. 

This brings the dynamic context capabilities of the interactive chat mode into your reusable command configuration, allowing for smarter, context-aware automation.

## 2. Background & Context
**The Problem:**
Previously, Custom Commands in the Gemini CLI were largely static. To include specific project context (like a style guide, a specific interface definition, or a documentation folder), users had to manually paste that context into the chat or the command definition, or rely solely on the currently open file.

**The Solution:**
Addressed in **Issue #6651** and delivered via **PR #6716**, this feature standardizes the `@` symbol usage. By parsing `@{path}` tokens within the command definition string, the CLI can now dynamically "hydrate" your prompts with up-to-date file content at runtime. This turns static prompts into dynamic workflows that adapt as your project files change.

## 3. How-To Guide

### Prerequisites
Ensure you have the latest version of the Gemini CLI installed.

### Defining a Context-Aware Command
You can define these commands in your user settings (typically `~/.gemini/config.json` or via the settings UI).

**Syntax:** `@{path/to/file}` or `@{path/to/directory}`

#### Example 1: Automated Code Review against Style Guidelines
If you have a `CONTRIBUTING.md` or a style guide in your repo, you can create a command to check your code against it specifically.

**Command Name:** `check-style`
**Prompt:**
```text
Review the current code buffer. Ensure it adheres strictly to the coding standards defined in @{docs/coding_standards.md}. Point out any violations.
```

#### Example 2: Generating Documentation from Source
You can embed an entire directory to give Gemini context about the project structure.

**Command Name:** `write-readme`
**Prompt:**
```text
Read the source code in @{src/core/}. Write a comprehensive README.md file that explains the architecture and how these files interact.
```

### Running the Command
Once saved, simply run the command from the CLI prompt:

```bash
> check-style
```
The CLI will automatically read `docs/coding_standards.md`, inject its content into the prompt, and send the request to the model.

## 4. Walkthrough & Technical Deep Dive

Based on the code coverage report provided in the release context, this feature heavily utilizes the `src/prompt-processors` and `src/services` modules.

### The Mechanism
1.  **Command Loading:** When the CLI starts, `CommandLoader.ts` (100% coverage) loads your custom configurations.
2.  **Template Parsing:** When you execute a command, the string is passed through the `TemplateProcessor.ts` (100% coverage). This processor scans the string for the regex pattern matching `@{...}`.
3.  **Path Resolution:** The path provided inside the braces is resolved relative to the current working directory. The feature leverages `src/tools/read-file.ts` and potentially `src/tools/ls.ts` (for directory expansion) to fetch the raw content.
4.  **Context Injection:** The `@{path}` token is replaced in-memory with the actual text content of the target file(s).
5.  **Execution:** The fully hydrated prompt is sent to the `CommandService`, which manages the interaction with the Gemini API.

### Code Coverage Highlights
The robustness of this feature is supported by high test coverage in critical areas:
*   **`src/prompt-processors/TemplateProcessor.ts`**: **100%** statement coverage. This indicates the logic for parsing and replacing the `@{path}` syntax is fully tested.
*   **`src/config/settings.ts`**: **88.25%** coverage, ensuring the saving and retrieving of these new command formats work reliably.
*   **`src/tools/read-file.ts`**: **98.66%** coverage, ensuring reliable file access when fetching the embedded content.
