# What's New: Transmit Security Integration for Gemini CLI

## 1. Feature Summary
The Gemini CLI ecosystem has expanded with a powerful new extension in partnership with Transmit Security. This update introduces the **Transmit Security Journey Builder extension**, accessible via the `gemini extensions install` command.

This feature allows developers to instantly scaffold, validate, and repair production-ready authentication and identity workflows (Customer Identity and Access Management - CIAM) directly from the terminal. It moves beyond simple templating by offering context-aware validation and automated fixes for common configuration errors.

## 2. Background & Context
**The Problem:**
Integrating secure authentication into modern applications is notoriously difficult. Developers often struggle with:
*   **Context switching:** Moving between the IDE, vendor portals, and documentation.
*   **Configuration drift:** Discrepancies between local environment variables and remote identity provider settings.
*   **Security gaps:** implementing "happy path" login flows while missing critical validation steps or error handling.

**The Solution:**
Based on the repository `transmit-security-journey-builder`, this extension bridges the gap between the Transmit Security platform and the local developer environment.

The motivation behind this change is to treat **Identity as Code**. By wrapping the Transmit Security integration into a Gemini extension, we are solving the "Day 0" setup friction. The mention of "automated fixes" in the changelog indicates that this tool doesn't just generate code; it acts as a linter for identity logic, ensuring that the scaffolding provided is not just syntactically correct, but operationally valid against Transmit’s best practices.

## 3. How-To Guide

Here is how to get started with the new extension to secure your application.

### Prerequisites
*   Gemini CLI installed (latest version recommended).
*   A Transmit Security tenant (optional for installation, required for deployment).

### Step 1: Install the Extension
Run the following command in your terminal to fetch the extension from the official repository:

```bash
gemini extensions install https://github.com/TransmitSecurity/transmit-security-journey-builder
```

### Step 2: Initialize a Workflow
Once installed, the extension exposes new capabilities within the CLI. You can now generate authentication flows (Journeys). *Note: Syntax may vary based on your specific project structure.*

```bash
# Example usage to scaffold a standard login/signup flow
gemini transmit scaffold --type login-signup
```

### Step 3: Validate Configuration
One of the core features of this release is validation. Run the check command to ensure your environment variables and journey definitions match.

```bash
gemini transmit check
```
*If errors are found (e.g., missing Client IDs), the CLI will prompt to apply automated fixes.*

1.  **Environment Detection:** It scans your `.env` files to verify that Transmit Security credentials exist.

3.  **Automated Fixes:** If the CLI detects a mismatch—for example, if your code references a Journey ID that doesn't exist in your configured Tenant—the "automated fix" capability likely attempts to either update the local config to match the remote tenant or prompts to create the missing resource remotely via API.
