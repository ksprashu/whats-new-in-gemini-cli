# 🚀 What’s New in Gemini CLI: Raw Markdown Toggle

**Release:** Latest Nightly / Patch
**Contributor:** @srivatsj
**Related PR/Issue:** [#10383](https://github.com/google-gemini/gemini-cli/pull/10383), [#6499](https://github.com/google-gemini/gemini-cli/issues/6499)

---

## 1. Feature Summary
The Gemini CLI now supports a **Markdown Toggle** feature. This enhancement allows users to instantly switch the output display between **rendered markdown** (formatted text, bolding, syntax highlighting) and **raw markdown** (plain text with syntax symbols) without regenerating the response.

By utilizing the shortcuts `Alt+m` or `Ctrl+m`, developers can now inspect the underlying syntax of Gemini’s responses on the fly.

## 2. Background & Context
**The Problem:**
Previously, the Gemini CLI defaulted strictly to a "prettified" rendered view. While visually appealing, this presented several friction points for developers identified in Issue #6499:
*   **Copy-Paste Fidelity:** Copying rendered text from a terminal window often results in broken formatting when pasted into editors or other markdown files.
*   **Ambiguity:** It was occasionally difficult to distinguish between Gemini’s actual text output and artifacts created by the CLI’s rendering engine (such as table borders or code block backgrounds).

**The Solution:**
Community contributor @srivatsj addressed this by introducing a view-layer toggle. This gives power back to the user, allowing them to access the raw string data exactly as it was received from the API, facilitating easier debugging and copy-pasting of complex structures like tables or code snippets.

## 3. How-To Guide

Using the new toggle is seamless and works on the current active response buffer.

**Prerequisites:** Ensure you are running the latest version of the Gemini CLI.

**Steps:**
1.  **Launch the CLI** and send a prompt to Gemini.
    ```bash
    gemini "Create a markdown table comparing Python and Go"
    ```
2.  **View Rendered Output:** By default, you will see the table formatted with borders and aligned columns.
3.  **Toggle to Raw View:**
    *   Press **`Alt+m`** (macOS/Linux preferred)
    *   Or press **`Ctrl+m`**
4.  **Observe Change:** The table borders will disappear, replaced by pipes (`|`) and hyphens (`-`), and bold text will show asterisks (`**text**`).
5.  **Toggle Back:** Press the keystroke again to return to the rendered view.

## 4. Walkthrough / Technical Deep Dive
*Based on the architecture of the CLI and the nature of PR #10383.*

Under the hood, this change modifies the **Terminal User Interface (TUI)** render loop.

1.  **State Management:** The application now maintains a boolean state flag (likely `viewRaw` or `showMarkdown`).
2.  **Input Handling:** The event listener loop has been updated to intercept specific key codes. It’s worth noting that mapping `Ctrl+m` can be tricky in terminal environments, as it is historically interpreted as a Carriage Return (`CR` / Enter). The implementation likely intercepts the signal before the default terminal behavior triggers in the context of the viewer.
3.  **The Rendering Pipeline:**
    *   **Rendered Mode (Default):** The API response string is passed through a Markdown renderer (e.g., `glamour` or similar Go-based libraries), which parses AST nodes and applies ANSI escape codes for colors and styling.
    *   **Raw Mode:** The pipeline bypasses the parser. The string is sanitized for basic terminal safety but is otherwise printed literally.

This implementation is efficient because it does not require a re-fetch from the API; it simply repaints the UI using the cached response string in memory.
