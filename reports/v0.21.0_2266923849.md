# 🚀 Gemini CLI Update: comprehensive Quota Visibility

**Release:** *Latest Version*
**Contributor:** @sehoon38

## 1. Feature Summary
The Gemini CLI has significantly upgraded its introspective capabilities. The `/stats` command has been overhauled to provide a **comprehensive quota dashboard**.

Previously, the CLI primarily tracked session-specific statistics (like token usage for the current conversation). With this update, `/stats` now proactively fetches and displays the rate limits and quota status for **all available models** associated with your API key—even those you haven't interacted with in the current session.

## 2. Background & Context
*Based on the changelog and community feedback loops:*

**The Problem:**
Developers working with LLMs frequently encounter "Rate Limit Exceeded" (HTTP 429) errors. These errors often come as a surprise because rate limits (RPM - Requests Per Minute, TPM - Tokens Per Minute) vary significantly between models (e.g., `gemini-1.5-flash` vs. `gemini-1.5-pro`) and user tiers (Free vs. Pay-as-you-go).
Previously, developers had to leave the terminal and check the Google Cloud console or wait for a crash to know they were hitting a ceiling.

**The Solution:**
This change moves the feedback loop directly into the terminal. By exposing the quota limits programmatically via the CLI, developers can make informed decisions about which model to use *before* sending a heavy prompt.

**Key Contributor:**
Credit to **@sehoon38** for implementing this logic, ensuring that the CLI acts not just as a prompt interface, but as a resource management tool.

## 3. How-To Guide

Here is how to utilize the new quota visibility features in your workflow.

### Prerequisites
Ensure you have updated to the latest version of the Gemini CLI.

### Step-by-Step
1.  **Start a Chat Session:**
    Launch the CLI as you normally would.
    ```bash
    $ gemini chat
    ```

2.  **Check Stats:**
    At any point in the conversation, type the slash command:
    ```bash
    >>> /stats
    ```

3.  **Interpret the Output:**
    You will now see a structured table displaying limits for every model accessible to your API key.

    **Example Output:**
    ```text
    [Current Session Stats]
    Tokens Used: 450
    Messages: 4

    [Global Model Quotas]
    --------------------------------------------------------
    Model               | RPM Limit | TPM Limit | RPD Limit
    --------------------------------------------------------
    gemini-1.5-flash    | 15        | 1,000,000 | 1,500
    gemini-1.5-pro      | 2         | 32,000    | 50
    gemini-1.0-pro      | 60        | Unlimited | Unlimited
    --------------------------------------------------------
    ```

## 4. Walkthrough / Technical Deep Dive

How does the CLI achieve this without slowing down your session?

**Under the Hood:**
When you invoke `/stats`, the CLI performs a distinct API call to the Generative AI client's model listing endpoint (likely `genai.list_models()` or the equivalent REST endpoint `GET /v1beta/models`).

**The Logic Flow:**
1.  **Retrieval:** The CLI requests metadata for all models, not just the one currently defined in your configuration.
2.  **Filtering:** It iterates through the returned model objects, specifically looking for the `outputTokenLimit`, `inputTokenLimit`, and significantly, the user-specific quota metadata if available via the headers or the model object properties.
3.  **Aggregation:** It aggregates this data alongside your local session state (which tracks local token count).
4.  **Rendering:** The data is formatted into a human-readable table using standard CLI formatting libraries (like Rich or standard f-strings), ensuring alignment regardless of model name length.

*Note: This check is done on-demand (lazy loading) when the command is run, ensuring there is no latency added to your standard generation (chat) loops.*
