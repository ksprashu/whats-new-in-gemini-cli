## 1. Feature Summary
**Citations are now enabled by default for all users.**

Previously a restricted or experimental feature, the Gemini CLI now automatically provides source citations for grounded responses. When the model retrieves information from external sources (such as Google Search or documentation repositories) to answer a prompt, the CLI will explicitly list these sources. This ensures transparency, improves trust, and allows developers to verify the information provided by the model immediately.

---

## 2. Background & Context
### The Problem
Large Language Models (LLMs) are powerful, but they can occasionally "hallucinate" or present outdated information as fact. For developers working in the terminal, verifying the accuracy of a generated command, configuration snippet, or fact usually required context-switching to a browser.

### The Solution
Issue #8300 tracked the initiative to bring grounding and citations to the command line experience. By exposing source metadata, we allow users to audit the model's reasoning.

### The Change (PR #8570)
This Pull Request marks the graduation of the feature. The key indicator here is the **size change of -131 B**.
*   **Why a size reduction?** Typically, enabling a feature globally means removing "gatekeeping" logic. The code that previously checked `if (userIsBetaTester)` or `if (featureFlagEnabled)` has been removed, making the citation logic the default execution path for everyone. This simplifies the codebase and ensures a consistent experience for all users.

## 3. How-To Guide
Because this feature is now "enabled for all," you do not need to pass specific flags to turn it on. It activates automatically when the model determines external information is necessary to answer your prompt.

### Step 1: Update the CLI
Ensure you are running the latest build where PR #8570 is merged.
```bash
npm install -g @google-gemini/gemini-cli@latest
```

### Step 2: Ask a Fact-Based Question
Citations appear most frequently with queries requiring current knowledge or specific documentation.

**Example Command:**
```bash
gemini "What are the new features in Next.js 14?"
```

### Step 3: Review the Output
The CLI will output the answer, followed by a list of references.

**Sample Output:**
```text
Next.js 14 introduces Server Actions (stable), Partial Prerendering (preview), and separated metadata blocking.

Sources:
[1] nextjs.org/blog/next-14
[2] vercel.com/blog/nextjs-14
```

## 4. Walkthrough / Technical Deep Dive
While the PR context shows a binary bundle update, here is how the citation engine functions under the hood within the CLI architecture:

1.  **Prompt Construction:** When you send a prompt, the CLI interacts with the Gemini API. If the model determines it needs external data (grounding), it queries the Google Search index (or other configured tools).
2.  **Metadata Payload:** The API response includes the generated text candidate *and* a metadata payload containing `citationMetadata`.
3.  **Parsing & Rendering:**
    *   The CLI intercepts this payload.
    *   It parses the `startIndex` and `endIndex` of the citations to map them to the generated text.
    *   The rendering engine (in `gemini.js`) appends a formatted footer to the standard output (`stdout`).
4.  **The "Un-gating" (PR #8570):**
    *   Previously, the logic inside `gemini.js` likely contained a conditional check.
    *   PR #8570 removed this conditional wrapper. The negative file size diff (`-131 B`) confirms that code was deleted (the guardrails) rather than added, making the feature native to the core bundle.
