# 🚀 What's New: Smart Status Indicators for Interactive Shells

### 1. Feature Summary
The Gemini CLI has significantly improved the user experience within **Interactive Shell** sessions. We have replaced generic "witty" loading phrases with a context-aware status indicator. 

When the CLI detects that an interactive shell (e.g., a running server or a REPL) has been idle for a short period, it will now explicitly display: **"Interactive shell awaiting input... press Ctrl+f to focus shell."** This removes ambiguity, letting you know exactly when the CLI is processing and when it is waiting on you.

### 2. Background & Context
**The Problem:**
Previously, the Gemini CLI relied on a cycle of general, witty phrases within its loading spinner to indicate that the application was running. However, this created confusion during interactive sessions. Users would see the spinner rotating with messages like "Contemplating the universe..." and assume the CLI was still performing a backend task or generation, even when the underlying shell was actually paused and awaiting user input.

**The Solution:**
Addressed in **PR #12535** (and referencing User Issue #11765), this update introduces logic to distinguish between "active processing" and "awaiting input." By providing an accurate application status, we reduce user cognitive load and friction. Users no longer have to guess if the CLI has hung or if it simply needs a keystroke.

### 3. How-To Guide
This feature is automatic, but here is how you can observe the new behavior in your workflow:

1.  **Start a Task:** Run a Gemini CLI command that triggers a long-running interactive process. 
    *   *Example:* `gemini run "Start a local Python http server"`
2.  **Observe Processing:** Initially, you will see the standard loading spinner and phrases while the command initiates.
3.  **Wait for Idle:** Once the server starts and output stops flowing to the console, simply wait for **5 seconds**.
4.  **See the Status:** The loading text will switch to the new hint:
    > *Interactive shell awaiting input... press Ctrl+f to focus shell*
5.  **Take Action:** Press `Ctrl+f` (or your configured binding) to interact with the shell directly, or issue a new prompt to Gemini.

### 4. Walkthrough / Technical Deep Dive
This feature implements a "quiet detection" mechanism within the CLI's frontend hooks. Here is how the logic works under the hood:

*   **Output Time Tracking:** The system now tracks a `lastOutputTime` timestamp. This variable monitors both standard shell command stdout/stderr and tool outputs. Every time the shell emits a log line or a character, this timestamp is updated.
*   **The 5-Second Threshold:** The `useLoadingIndicator` hook monitors the delta between the current time and `lastOutputTime`. 
    *   If the delta is **< 5 seconds**, the CLI assumes the process is active and displays standard/witty loading phrases.
    *   If the delta is **> 5 seconds** AND the CLI is in an interactive mode, the `usePhraseCycler` hook overrides the standard messages with the specific "Awaiting input" prompt.
*   **Auto-Reset:** The logic is dynamic. If the underlying shell suddenly prints a log (e.g., a server receives a request), `lastOutputTime` updates, and the UI immediately switches back to the standard processing indicator until the 5-second idle window is met again.
