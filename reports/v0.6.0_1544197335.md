# 🚀 What's New: Unlocking Higher Limits for Gemini CLI

## 1. Feature Summary
We are thrilled to announce a significant infrastructure upgrade for our power users. Starting immediately, developers with **Google AI Pro** and **AI Ultra** subscriptions can access **2.5x higher quota limits** within the Gemini CLI.

This update directly addresses throughput bottlenecks, allowing for more frequent API calls, larger context window usage without throttling, and a smoother, uninterrupted coding workflow. The CLI now automatically detects your subscription tier during authentication and dynamically adjusts your rate limits (RPM and TPM) on the backend.

## 2. Background & Context
**The Problem:**
As developers moved from experimenting with Gemini to building production-grade applications and performing heavy code refactoring, they began hitting the standard tier rate limits.
*   **Issue:** frequent `429: Too Many Requests` errors during rapid iteration cycles.
*   **Impact:** This broke the "flow state," forcing developers to wait for quota resets when chaining complex prompts or analyzing large codebases.

**The Solution:**
This change aligns the CLI capabilities with the premium web-based Gemini Advanced experience. By tripling the effective capacity (approximate), we are shifting the CLI from a "trial" tool to a robust daily driver for professional engineering work. This ensures that paying subscribers get the raw throughput necessary for tasks like automated test generation across entire repositories or heavy data transformation scripts.

## 3. How-To Guide
To take advantage of these new limits, you generally do not need to update the CLI binary, but you **must refresh your authentication state** to ensure the backend recognizes your subscription status.

### Step 1: Verify Subscription
Ensure your Google account is currently subscribed to the **Google AI Pro** or **AI Ultra** plan via the Google One or Google Cloud console.

### Step 2: Re-authenticate the CLI
Run the login command to refresh your OAuth tokens. This forces the API gateway to re-evaluate your user claims.

```bash
gemini auth login --reauth
```

### Step 3: Verify Quota Status (Optional)
If you want to check which tier is currently active for your session, you can use the status command (depending on your specific CLI version):

```bash
gemini quota status
# Output should indicate: "Tier: AI Ultra / Limit: High"
```

### Step 4: Run High-Volume Tasks
You can now execute scripts that require higher concurrency. For example, processing a batch of files:

```bash
# Example: Summarizing multiple log files in rapid succession
for file in logs/*.txt; do
  gemini prompt "Summarize this log error trace" --file "$file"
done
```

## 4. Walkthrough / Technical Deep Dive
*How the quota increase works under the hood.*

While the CLI tool acts as the client, the heavy lifting for this feature happens at the **API Gateway and Identity Awareness** layer.

1.  **Identity Propagation:** When you run `gemini auth login`, the CLI obtains an OAuth 2.0 access token. Previously, this token simply validated that you were a registered Google user. Now, the scope includes checking specific entitlement claims associated with Google One/Google Cloud subscriptions.
2.  **Dynamic Quota Buckets:**
    *   **Standard Tier:** Uses a standard "Leaky Bucket" algorithm with a conservative refill rate (e.g., 60 requests per minute).
    *   **Pro/Ultra Tier:** Upon receiving the request, the API Gateway detects the `subscription_tier` claim. It routes the request to a high-priority traffic lane with a bucket size and refill rate set to **2.5x** the standard capacity.
3.  **Token Counting:** This update is particularly effective for TPM (Tokens Per Minute). Because Ultra subscribers often use larger models (like Gemini 1.5 Pro) with massive context windows, the accounting system has been adjusted to allow for bursts of high-token usage without immediately triggering a cooldown period.
