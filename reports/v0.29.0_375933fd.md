## The Headline
The training wheels are officially off. The Gemini CLI team has flipped the switch, making Gemini 3 the default intelligence engine for all users. Previously hidden behind a "preview" flag for early adopters, this upgrade brings the latest model architecture to the forefront of the developer experience. Users no longer need to dig into configuration files or memorize experimental flags to access the smartest version of the tool. With this update, every standard interaction—from code generation to complex reasoning—now harnesses the power of Gemini 3 automatically.

## Quick Start / How to Try It Out
Because this feature changes the default behavior, the setup process is essentially zero-config.

*   **Prerequisites:** Simply update the Gemini CLI to the latest version.
*   **Flags:** None. The previous experimental flags for Gemini 3 have been deprecated.
*   **Commands:** Run your standard prompts.
    ```bash
    gemini prompt "Explain the benefits of Rust over C++"
    ```
    *The output is now generated by Gemini 3 automatically.*

## Use Cases (Why you need this)
*   **Immediate Access to State-of-the-Art:** Developers instantly gain access to improved reasoning and context handling without needing to manually configure their environment.
*   **Simplified Onboarding:** New users installing the CLI for the first time are immediately greeted by the most capable model, rather than an older, legacy version.
*   **Standardized Team Environments:** Eliminates "works on my machine" issues caused by some team members having experimental flags enabled while others remain on the old default.

## What to Expect (Things to Look Out For)
*   **Response Variations:** Users accustomed to the previous default model may notice changes in the tone, formatting, or verbosity of answers as Gemini 3 takes over.
*   **Flag Deprecation:** If you previously had `gemini_3_preview: true` (or similar) in your config, the CLI will simply ignore it, though it is recommended to clean up your config file.
*   **Stability:** As the preview flag has been removed, the team considers this model stable for daily production use.

## Technical Deep Dive (Admin)
The implementation of this change, led by contributor @sehoon38 in PR #18414, involves a straightforward but significant refactor of the model selection logic. The codebase previously utilized a conditional check against a user's configuration (specifically a preview flag) to determine whether to instantiate the Gemini 3 client or fallback to the previous version.

This logic has been streamlined:
*   **Default Constant Update:** The internal constant defining the `DEFAULT_MODEL` has been updated to target the Gemini 3 API identifier.
*   **Flag Removal:** The boolean check for the preview flag has been excised, reducing the cyclomatic complexity of the initialization routine.
*   **Fallback Logic:** While the default is now Gemini 3, the architecture likely retains the ability to specify older models via explicit flags if legacy support is needed, though the *implicit* default is now the newest model.

## Background & Context (Admin)
The move to make Gemini 3 the default follows a standard software release lifecycle. Initially introduced under a feature flag (tracked in discussions surrounding issues #17487 and #19530), the model underwent a period of community testing. This "Preview" phase allowed the maintainers to gather telemetry on latency, error rates, and response quality without disrupting users who rely on the stable release.

The execution of PR #18414 signals that the maintainers are confident the model has reached feature parity and stability superiority over its predecessor. This update also coincides with a push for stricter contribution guidelines, as noted in the PR comments, ensuring that future model swaps are rigorously tracked via issues.
