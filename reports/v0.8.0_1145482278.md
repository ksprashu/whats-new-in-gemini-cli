# What’s New in Gemini CLI: The Extension Ecosystem

## 1. Feature Summary
We are thrilled to announce the rollout of **Gemini CLI Extensions**, a major architectural shift that transforms the Gemini CLI from a standalone tool into a platform.

With this release, users can now install, manage, and run community-sourced commands directly through the CLI. Rather than waiting for core updates to get new integrations (like SQL generation, Git commit message crafting, or specific language linting), developers can now build and share their own custom Gemini workflows via the new `gemini ext` command suite and the registry at [geminicli.com/extensions](https://geminicli.com/extensions).

## 2. Background & Context
### The Problem
As the Gemini CLI adoption grew, the core repository saw an influx of feature requests for niche use cases. Issues discussions highlighted a common pattern:
*   *User A* wanted a specific flag to parse Python docstrings.
*   *User B* wanted to pipe logs directly into Gemini for error analysis.
*   *User C* needed a dedicated mode for generating Jira tickets.

Attempting to bake all these features into the core binary was causing bloat and maintenance bottlenecks. The maintainers recognized that a monolithic approach doesn't scale with the creativity of the developer community.

### The Solution
Inspired by discussions on repository modularity, the team decided to decouple "core logic" (authentication, API communication, stream handling) from "domain logic" (specific prompts and workflows).

By implementing an Extensions API, we allow the core tool to remain lightweight and stable, while empowering the community to solve edge cases. This shifts the paradigm from "Gemini CLI does X" to "Gemini CLI can be programmed to do anything."

## 3. How-To Guide

Here is how you can start using extensions immediately.

### Installing an Extension
Browse the registry at `geminicli.com/extensions` to find a tool you need. For this example, let's use a hypothetical `pr-review` extension.

```bash
# Install an extension by name or URL
$ gemini ext install pr-review
```

### Using the Extension
Once installed, the extension becomes a first-class citizen command.

```bash
# Run the command
$ gemini pr-review --branch feature/login-page
```

### Managing Extensions
You can easily audit what tools you have loaded:

```bash
# List installed extensions
$ gemini ext list

# Update all extensions
$ gemini ext upgrade --all

# Remove an extension
$ gemini ext remove pr-review
```

### Creating Your Own
We’ve added scaffolding to help you build tools fast:

```bash
$ gemini ext create my-new-tool
```
*This generates a directory with a `manifest.yml` and a script file.*

## 4. Walkthrough / Technical Deep Dive
### Architecture
Under the hood, Gemini CLI Extensions function as **local repositories**. When you run `gemini ext install <repo>`, the CLI clones the repository into a managed configuration directory (typically `~/.config/gemini/extensions`).

### The Manifest File
The backbone of every extension is the `manifest.yml`. This file tells the Gemini CLI how to map the command to the executable.

```yaml
name: pr-review
version: 1.0.0
description: "Analyzes git diffs and suggests improvements using Gemini Pro"
entry_point: bin/run.sh
permissions:
  - read_files
  - network
```

### Execution Flow
When a user executes `gemini pr-review`, the following happens:
1.  **Lookup:** The CLI checks the extension registry map for `pr-review`.
2.  **Context Injection:** The CLI spins up a subprocess for the `entry_point` script. Crucially, it injects environment variables containing the user's active Gemini API session.
3.  **Proxying:** The extension script runs its logic (e.g., grabbing a git diff) and pipes the data back into the main Gemini binary for processing, or makes direct API calls using the injected session token.

This design ensures that extensions can be written in any language (Bash, Python, Go, Node), provided the user’s machine has the runtime to execute the entry script.
