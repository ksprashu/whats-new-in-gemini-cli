# What's New in Gemini CLI: Custom Commands in Headless Mode

**Release Date:** *[Current Date]*
**Contributors:** @capachino
**Related PRs:** [#8305](https://github.com/google-gemini/gemini-cli/pull/8305) | **Issue:** [#5435](https://github.com/google-gemini/gemini-cli/issues/5435)

---

## 1. Feature Summary
The Gemini CLI now supports executing **Custom Commands** directly in **Headless Mode** (non-interactive).

Previously, custom "slash commands" (pre-defined prompts or macros defined in your config) were primarily accessible only while inside the interactive TUI session. With this update, users can trigger these commands directly from their terminal shell as a one-liner.

**The new syntax:**
```bash
gemini "/command_name arguments"
```

---

## 2. Background & Context
**The Problem:**
Users define powerful custom commands (like `/commit`, `/refactor`, or `/joke`) to automate repetitive prompting. However, using these required entering the interactive `gemini` shell, typing the command, and waiting for the output. There was no easy way to script these commands or run them quickly from a standard shell environment.

**The Design Discussion (PR #8305):**
This feature involved significant discussion regarding User Experience (UX) philosophy:
*   **The Debate:** There was a debate between maintaining "CLI Purity" vs. "TUI Consistency."
    *   *Option A (CLI Standard):* Using flags, e.g., `gemini --command="joke args"`.
    *   *Option B (TUI Consistency):* Using positional arguments, e.g., `gemini "/joke args"`.
*   **The Decision:** Ultimately, the implementation landed on **Option B**. While flags are standard for CLI tools, allowing the `/` syntax creates a seamless mental model for users. If you know how to type it in the interactive mode, you know how to type it in the terminal.

**Scope Note:**
Initial drafts of this feature included support for file context via `@filename`. However, to keep this update stable and focused strictly on command execution, file processing was decoupled and removed from this specific PR.

## 3. How-To Guide

Here is how to utilize the new headless custom commands.

### Prerequisites
Ensure you have a custom command defined in your `config.yaml`.
*Example Config:*
```yaml
custom_commands:
  - name: joke
    prompt: "Tell me a programming joke about {{1}}"
```

### Basic Usage
Run the command directly from your terminal.

**Old Workflow (Interactive):**
```bash
$ gemini
> /joke Java
(Gemini generates output...)
> /exit
```

**New Workflow (Headless):**
```bash
$ gemini "/joke Java"
```

### Scripting Example
Because this outputs to STDOUT, you can easily pipe the results or save them to files.
```bash
# Save the output to a text file
gemini "/refactor main.py" > refactored_code.txt
```

## 4. Walkthrough / Technical Deep Dive

When the Gemini CLI receives a positional argument in headless mode, it now parses the string to check for the leading forward slash (`/`).

1.  **Detection:** The CLI checks if the first positional argument starts with `/`.
2.  **Lookup:** It strips the `/` and matches the string against the `name` keys in your `custom_commands` configuration.
3.  **Argument Injection:** The text following the command name is treated as arguments and injected into the template placeholders (e.g., `{{1}}`) defined in the command prompt.
4.  **Execution:** The resolved prompt is sent to the Gemini API.
5.  **Output:** The response is streamed directly to Standard Output (stdout) and the process terminates.

**Note on Input Handling:**
Standard Input (STDIN) behavior remains unchanged. You can still pipe data *into* gemini, which creates powerful combinations when paired with slash commands:
```bash
cat error.log | gemini "/explain"
```
