# What's New: Gemini 3 Pro & Flash for Free Tier

## 1. Feature Summary
The Gemini CLI has significantly upgraded the experience for **Free Tier** users. Starting immediately, free tier users are no longer restricted to legacy models. You now have access to the cutting-edge **Gemini 3 Pro** and **Gemini 3 Flash** models.

To access these models, users must explicitly opt-in via the CLI configuration by enabling "Preview Features."

## 2. Background & Context
**The Problem:**
Previously, access to state-of-the-art reasoning (Pro) and low-latency performance (Flash) was gatekept behind paid subscription tiers. Free tier users were limited to older model iterations, which often resulted in slower response times and less nuance in complex code generation tasks.

**The Solution:**
By opening Gemini 3 access to the Free Tier, we are aiming to democratize access to the latest model capabilities. However, because this is a significant leap in capability and backend resource usage, the team has decided to gate this behind a **"Preview Features"** toggle.

This approach achieves two goals:
1.  **Controlled Rollout:** It prevents immediate overload on the API by ensuring only active, interested users enable the feature first.
2.  **User Agency:** It allows users to opt-in to the bleeding edge while keeping the default experience stable for those who prefer the legacy behavior.

## 3. How-To Guide

Here is how to enable Gemini 3 Pro and Flash on your local machine.

**Prerequisites:** Ensure your Gemini CLI is updated to the latest version.

**Step 1: Open Settings**
Launch the CLI settings menu by typing:
```bash
/settings
```

**Step 2: Enable Preview Features**
Navigate to the general configuration menu. Look for the key labeled `Preview Features`.
*   **Current Value:** `false` (Default)
*   **Action:** Toggle this to `true`.

**Step 3: Select Your Model**
Once Preview Features are enabled, the model selection list will update. You can now set your default model via the command line or the settings UI:

```bash
# To switch to Flash for speed
gemini config set model gemini-3-flash

# To switch to Pro for complex reasoning
gemini config set model gemini-3-pro
```

**Step 4: Verify**
Run a simple prompt to check the footer response metadata:
```bash
gemini "Hello, world!"
> ...
> [Model: Gemini 3 Pro | Latency: 400ms]
```

## 4. Walkthrough / Technical Deep Dive
How does this change work under the hood?

**Client-Side Gating:**
The CLI implements a logic check within the `ConfigManager`. When the application initializes, it loads the user's `config.json`. The availability of the `gemini-3-*` model strings in the selection dropdown is conditional.

Pseudocode representation of the logic:
```python
def get_available_models(user_tier, preview_enabled):
    models = ["gemini-1.5-flash"] # Base model
    
    if user_tier == "paid" OR (user_tier == "free" AND preview_enabled):
        models.append("gemini-3-pro")
        models.append("gemini-3-flash")
        
    return models
```

**API Routing:**
When you enable "Preview Features," the CLI updates the payload headers sent to the backend. It essentially signals the API gateway that this user is authorized to route requests to the `v3` endpoints. Without the local toggle set to `true`, the CLI will default to standard routing, even if the user manually tries to force the model name in the config file, ensuring graceful fallbacks.
