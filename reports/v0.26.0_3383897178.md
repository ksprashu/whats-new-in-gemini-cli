# What’s New in Gemini CLI: The "Skill Creator" & The Generalist Agent

**Date:** October 26, 2023
**Version Impacted:** Main Branch / Latest Release

## 1. Feature Summary
This update significantly matures the extensibility and autonomy of the Gemini CLI. We have introduced two major components:
1.  **The Skill Creator:** A meta-skill designed to help developers build *other* skills. It standardizes the workflow for scaffolding, validating, and packaging custom agent capabilities.
2.  **The Expert Agent (Generalist):** A new, non-interactive system agent equipped with access to all available tools. This agent serves as a powerful "router" and executor, capable of handling complex, multi-step tasks without constant user intervention.

## 2. Background & Context
### The Extensibility Challenge
Previously, creating custom skills for the Gemini CLI was a manual, error-prone process. Developers had to manually configure YAML frontmatter, ensure correct directory structures, and manage dependencies. There was no standardized way to ensure a skill would work before loading it.
*   **The Fix (PR #16394):** The team introduced a "Skill Creator" skill. By treating the *creation* of skills as a skill itself, we provide a guided, robust framework using CommonJS scripts to handle the heavy lifting (scaffolding, validation, packaging).

### The Routing Problem
As the number of tools and skills grew, the CLI needed a more robust way to decide *who* should do the work. Existing agents were often too interactive or restricted in scope.
*   **The Fix (PR #16638):** The `ExpertAgent` was introduced. This is a general-purpose AI designed to operate in a **non-interactive** mode. It has a global view of all tools and is engineered to perform tasks autonomously, improving the system's overall ability to route complex requests to the right execution path immediately.

## 3. How-To Guide

### Using the Skill Creator
The Skill Creator is now a built-in skill. You can interact with it via natural language to generate the boilerplate for new extensions.

**Step 1: Scaffolding a New Skill**
Ask Gemini to help you start a new skill.
```bash
gemini "I want to create a new skill called 'currency-converter' that fetches exchange rates."
```
*The Agent will utilize the new `init_skill.cjs` script to create the directory structure, ensuring the `node:` prefix is used for imports and the proper YAML configuration is set.*

**Step 2: Validating Your Skill**
Before sharing your skill, you need to ensure it meets the CLI's standards.
```bash
# You can ask the agent to validate, or run the script if exposed:
node tools/validate_skill.cjs ./my-skills/currency-converter
```
*This checks for missing frontmatter and residual TODOs.*

**Step 3: Packaging**
When ready to distribute:
```bash
node tools/package_skill.cjs ./my-skills/currency-converter
```
*This creates a flat `.skill` archive ready for distribution.*

---

### Leveraging the Expert Agent
The Expert Agent is integrated into the core routing system. You do not need to invoke it by a specific name; simply issue complex, multi-step commands.

**Example Scenario:**
```bash
gemini "Analyze the src/ folder, identify any files using deprecated Node APIs, and suggest a refactor plan in a markdown file."
```
*Because this requires file system access, code analysis, and file writing, the `ExpertAgent` (with access to all tools) will likely handle this request non-interactively, executing the necessary tool calls in sequence.*

## 4. Walkthrough / Technical Deep Dive

### Under the Hood: Skill Creator (PR #16394)
The architecture for the Skill Creator relies on a suite of new CommonJS management scripts located in the codebase:

*   **`init_skill.cjs`**: Handles the scaffolding. It generates the folder structure and configuration files. It enforces modern Best Practices, such as requiring the `node:` prefix for built-in modules (e.g., `import fs from 'node:fs'`) to prevent namespace conflicts.
*   **`validate_skill.cjs`**: A linter for skills. It parses the skill's code and metadata, ensuring the YAML frontmatter matches the schema and that no placeholder text (TODOs) remains.
*   **`package_skill.cjs`**: Compresses the skill into a valid archive format. Crucially, it ensures there are no nested directories inside the archive, which was a common point of failure in manual zipping.

The agent prompt has been refined to be "proactive," meaning it can offer to run `npm install` on behalf of the user and explicitly warns when a manual reload of the CLI is required to load the new skill.

### Under the Hood: Expert Agent (PR #16638)
The `ExpertAgent` represents a shift in the agent registration architecture:

*   **Configuration**: A new `ExpertAgentSettings` object has been added to the core config. The `AgentRegistry` checks this setting to conditionally register the agent.
*   **Non-Interactive Mode**: The `getCoreSystemPrompt` function was updated to accept an `interactiveOverride` parameter. The Expert Agent uses this to define itself as **non-interactive**. This drastically reduces latency and friction, as the model is instructed not to chat with the user but to prioritize tool execution to achieve the goal.
*   **Tool Access**: Unlike specialized agents that might only see a subset of skills, the Expert Agent is initialized with access to **all available tools**, making it the "Generalist" capable of solving unforeseen problems.
