# What's New in Gemini CLI: The Nanobanana Integration

**Date:** October 26, 2023
**Topic:** CLI Extensibility, Modular Architecture
**Extension:** `nanobanana`

## 1. Feature Summary
The Gemini CLI has officially moved from a monolithic tool to a modular platform with the integration of **Nanobanana**. Nanobanana is a lightweight extension framework that allows the Gemini CLI to dynamically load, manage, and execute third-party plugins.

This update enables developers to install community-driven functionalities or write their own custom commands without waiting for core CLI updates.

## 2. Background & Context
**The Problem:**
As the Gemini CLI grew, so did the request for niche features (e.g., specific output formatters, custom API integrations, or niche developer tools). Adding these to the core codebase was causing "feature bloat," increasing the binary size and maintenance burden.

**The Solution:**
Based on discussions in the community (and the need for a decoupled architecture), the team decided to integrate **Nanobanana**. This library creates a standardized interface for extensions.
*   **Decoupling:** Core maintainers can focus on stability and API interactions.
*   **Community Speed:** Developers can ship features (like a specific linter or prompt optimizer) immediately as extensions.
*   **Performance:** Extensions are lazy-loaded, ensuring the core CLI startup time remains fast.

## 4. Walkthrough / Technical Deep Dive

Under the hood, the integration changes how the CLI initializes command execution.

1.  **The Hook System:**
    When you run `gemini`, the CLI now initializes a `NanobananaLoader`. This loader scans a dedicated configuration directory (usually `~/.gemini/extensions`) for registered manifests.

2.  **Sandboxing:**
    To ensure security, Nanobanana executes extensions in a restricted scope. It exposes the `GeminiContext` object to the extension, which allows access to:
    *   The Authentication Token (read-only)
    *   The HTTP Client (for making requests)
    *   Standard Output/Error streams

3.  **Lifecycle Events:**
    The integration supports three main lifecycle hooks that extensions can tap into:
    *   `onInit`: Runs before the command is parsed (useful for adding new flags).
    *   `onRequest`: Allows middleware-like manipulation of the payload before it goes to Gemini API.
    *   `onResponse`: Allows post-processing of the data (e.g., transforming Markdown to HTML locally).
