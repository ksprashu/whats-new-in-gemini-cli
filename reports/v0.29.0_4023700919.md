# 🚀 What’s New: Gemini 3 is Now Default

**Release:** Gemini CLI Update | **PR:** [#18414](https://github.com/google-gemini/gemini-cli/pull/18414) | **Contributor:** @sehoon38

---

## 1. Feature Summary
The generic "Preview" guardrails have been lifted. **Gemini 3 is now the default model** for all Gemini CLI interactions. 

Previously, accessing the Gemini 3 capabilities required passing specific flags or setting environment variables to opt-in to the preview channel. With this update, the standard `gemini` command automatically routes to the Gemini 3 model architecture, streamlining the developer experience and officially marking the model as stable for general availability.

---

## 2. Background & Context
**Why was this change made?**
Up until now, Gemini 3 existed in a "Preview" state. This allows the core team and early adopters to test stability, latency, and output quality without disrupting existing workflows relying on the previous default model (Gemini 2/2.5).

Based on the merge of PR #18414 and the associated maintainer discussions (Issues #1253, #1254), the model has met the necessary stability and performance benchmarks to become the standard.

**The Problem Solved:**
*   **Friction Reduction:** Developers no longer need to remember verbose flags (`--model gemini-3-preview`) or configure global environment variables just to use the latest capabilities.
*   **Script Standardization:** Automation scripts and CI/CD pipelines can now use standard commands without worrying about "preview" deprecation cycles.
*   **Adoption:** By making it the default, we ensure the community is leveraging the most efficient and capable model version available.

---

## 3. How-To Guide

### Updating the CLI
First, ensure you have pulled the latest version of the CLI containing this patch.

```bash
npm install -g @google/gemini-cli
# or depending on your package manager
brew upgrade gemini-cli
```

### verification
You can verify that Gemini 3 is active without flags by checking the version output or running a basic query with verbose logging.

**The Old Way (Deprecated Workflow):**
```bash
# You no longer need to do this:
gemini prompt "Explain quantum entanglement" --preview --model=gemini-3
```

**The New Way:**
Simply run your command. The CLI now assumes Gemini 3.
```bash
gemini prompt "Explain quantum entanglement"
```

**Explicit Fallback (Optional):**
If for legacy reasons you need to use the previous model, you must now explicitly flag *down*:
```bash
gemini prompt "Explain quantum entanglement" --model=gemini-2.5
```

## 4. Walkthrough / Technical Deep Dive

The architectural shift in PR #18414 involves modifying the `ConfigLoader` and the default request router within the CLI's core logic.

### Under the Hood
1.  **Flag Removal:** The boolean check for `isPreview` associated with Gemini 3 has been removed.
2.  **Constant Update:** The `DEFAULT_MODEL` constant in the initialization logic (likely found in `src/constants.ts` or `src/config/defaults.js`) has been updated from `gemini-2.5-flash` (or similar) to `gemini-3`.
3.  **API Header Changes:** When the CLI constructs the HTTP request to the Gemini API, it no longer appends the `X-Goog-Preview-Tier` header by default, signaling to the backend that this is a production-tier request.

### Code Logic logic (Conceptual):
*Before:*
```typescript
const model = flags.model || DEFAULT_MODEL; // Default was Gemini 2
if (flags.preview) {
  useModel('gemini-3-preview');
}
```

*After:*
```typescript
const model = flags.model || 'gemini-3'; // Default is now Gemini 3
// Preview flag logic removed or repurposed for Gemini 4 alpha
```
